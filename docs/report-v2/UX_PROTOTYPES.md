# Report 2.0 — UX 프로토타입 · 레이아웃 비교

## 1. 전체 구조 대안 세 가지
### A. 다섯 화면 + 위 내비게이션 (✅ 시제품이 구현)
```
┌─ 척척발표 리포트 2.0 ─ [01 결과][02 청중석][03 리플레이][04 코칭][05 연습] ─ [선택: 「가설 A」… ×] ─┐
│                                                                                              │
│   화면마다 다른 레이아웃 · 분위기 (밝은 종이 / 극장 / 편집 도구 / 작업대 / 연습)                       │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```
- 장점: 명세의 「각각 독립 화면」 그대로. 화면마다 목적에 맞는 배치. 딥링크가 단순(`#/replay?i=…`).
- 단점: 화면을 오갈 때 맥락을 잃기 쉬움 → **위 「선택」 알약**으로 지금 진단을 늘 보인다.

### B. 한 쪽 긴 문서 + 고정 장 목차
```
┌ 목차(고정) ┐ ┌──────────── 01 진단 ────────────┐
│ 01 진단     │ │ … 스크롤 …                        │
│ 02 청중     │ ├──────────── 02 청중 ────────────┤
│ 03 근거     │ │ …                                │
└────────────┘
```
- 장점: 인쇄 · 공유에 강함, 훑기 쉬움. 단점: 리플레이(시간축 · 재생)와 극장 연출이 긴 문서 안에서 약해짐, 명세의 「섹션이 아니라 화면」과 어긋남. → 기각.

### C. 진단 레일 고정 + 오른쪽 무대 (분할)
```
┌ 진단 레일 ──────┐ ┌──────── 무대(청중석 · 리플레이 · 코칭) ────────┐
│ 1 3개 장 짧음  ▶ │ │                                              │
│ 2 「가설 A」 흔들 │ │                                              │
│ 3 시각자료 68점  │ │                                              │
└─────────────────┘ └──────────────────────────────────────────────┘
```
- 장점: 진단을 바꾸며 근거 · 코칭을 연달아 보기 좋음. 단점: 화면이 늘 반으로 갈려 01 결과 공개의 「한 문장 진단」 힘이 약해지고, 폰에서 레일이 접혀야 함.
- **부분 채택**: 03 리플레이 오른쪽의 「이 발표의 진단」 목록 · 04 아래 진단 칩이 C 의 레일 역할을 화면 안에서 한다.

## 3. 선택 · 전환 흐름 (60초 데모 경로)
1. 01 「가설 A」 줄의 `근거 보기` → 03 `#/replay?i=I:concept:gaseol-a&t=46.1-51.0` (근거 발화 강조 · 그 구간 재생)
2. 위 「02 청중석」 → 엑씨 → 「평점 인플레이션」 대사의 엔진 비교 → `근거로 가기` → 03
3. 03 `이 구간 개선하기` → 04 같은 `i`
4. 04 `해당 부분 다시 연습` → 05 → 「이 개념 질문 다시 받기」(앱 `#/rehearsal/qa`)
- 뒤로 가기 = 브라우저 기록(pushState), 새로고침 = 같은 주소로 같은 화면(시험: QA.md Q-03).
