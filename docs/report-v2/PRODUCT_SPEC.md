# Report 2.0 — 제품 명세 (5개 화면)

> 시제품: `/report-v2` (팀 전용, `main/web/report_v2.html` · `js/report_v2.js` · `css/report_v2.css`). 기존 `#/report` 는 그대로다.

## 1. 사용자 여정
**진단을 이해한다 → 근거(발언 · 장 · 구간)를 확인한다 → 어떻게 고칠지 본다 → 그 부분을 다시 연습한다.**
순서를 강제하지 않는다. 위 내비게이션 다섯 칸으로 어디든 가고, 고른 진단(`i`)과 구간(`t`)은 주소에 남아 화면을 바꿔도 따라온다.

## 2. 화면
### 01 결과 공개 (밝은 편집 보고서)
- 첫 문장 = F-19 총평(`report.one_liner`). 점수 · 등급은 오른쪽에 작게(기존 `scoreGrade` 규칙).
- **먼저 고칠 것 ≤3** — Evidence Graph 인사이트를 등급(영향 → 근거 → 고칠 수 있음)으로 정렬. 근거가 있는 문제가 3개보다 적으면 **채우지 않고** 「근거가 있는 문제는 N개예요」.
- 불확실성을 숨기지 않는다: 근거 위치 칩(발언 · 시각까지 / 장까지 / 글만 / 없음), 「판정이 흔들려요」(conflicting), **판정하지 못한 것** 상자(대체값).
- 가장 잘한 점(원문 인용 + 「들어 보기」) · 다음 행동(첫 이슈의 첫 제안 + 연습 갈 곳) · 기준별 점수(접기).
- `근거 보기` → 03(같은 `i`, 그 근거 구간 `t`) · `개선하기` → 04(같은 `i`).

### 02 삐약이 청중석 (어두운 극장)
- 코드상 청중 넷(믿:음 · 쏠라 · 엑사원 · 엑씨)의 **실제 이름 · 모델 · 맡은 것(lane)** 그대로. 점수 · 칭찬/우려 구분은 데이터에 없어서 만들지 않는다.
- 결석한 삐약이는 빈 자리로(「응답을 받지 못했어요」) — 대체 대사는 근거로 쓰지 않는다.
- 대사마다 근거 상태 칩: 근거 있음 · 근거끼리 어긋남 · 근거 없음 · 추정으로 이음. 근거 없는 대사는 까닭(「그래프 · 받아쓰기에 없는 말: …」)을 같이 보인다.
- 대사가 가리키는 개념마다 **분석 엔진 판정과 근거 발언**을 나란히 — 의견 차이를 억지로 합의시키지 않는다.
- 「○○ 근거로 가기」 → 03 (그 개념의 인사이트 또는 말한 구절 구간).
- 들어올 때 좌석이 0.5초 안에 차례로 뜬다(reduced-motion 이면 없음, 두 번째부터 없음).

### 03 발표 리플레이 (차콜 편집 도구)
- 장 그림 · 시간축(장 띠 · 발화 막대 · 인사이트 표시) · 받아쓰기 발화 줄 · 오른쪽 진단 카드.
- 진단을 고르면 근거 발화가 강조되고 그 줄로 스크롤, 「여기 듣기」는 그 구간만 재생(시작~끝+0.3초).
- **실제 녹음이 있을 때만 재생**(부스 덱 녹음). 없으면 「녹음이 저장되지 않아 들을 수 없어요 — 글로만 봐요」.
- 장 경계가 추정(`marks_estimated`)이면 「장 띠는 대략 위치예요」.
- 거르기: 전체 · 개념 전달 · 시간 · 흐름 · 말하기. 키보드: 시간축에서 ←/→ 5초.
- `이 구간 개선하기` → 04.

### 04 코칭 스튜디오 (밝은 작업대)
- 한 진단만: **원래 발표**(원문 구절 + 시각) → **진단한 까닭**(note · 상충 문구) → **이렇게 바꿔 말해요**(제안 + 근거 출처).
- 제안은 새로 짓지 않는다: 질문 생성(F-08)의 기대 답 → 없으면 자료 원문(deck_quote) → 없으면 「제안 문장이 아직 없어요」.
- 자료 해당 장 그림 · 원문을 아래에. 다른 진단은 아래 칩으로 바꾼다.
- `해당 부분 다시 연습` → 05 · `근거 구간 다시 듣기` → 03.

### 05 다시 연습
- 고른 진단의 연습 갈 곳(이 개념 질문 다시 받기 · 그 장 다시 연습 · 처음부터) — 실제 앱 주소(`index.html#/rehearsal…`)로 간다.
- **Q&A 전환점**: 질문 → 내 답(AI 가 주목한 구절 강조) → 꼬리질문 → 다음 답. 메신저처럼 다 늘어놓지 않고 질문마다 전환점만.
- 재연습 결과를 진단에 잇는 기록이 없어서 **나아졌다고 말하지 않는다** — 「다음 단계에서 만들어요」.

## 3. 성공 기준 (명세 §8 대응)
| 질문 | 시제품에서 확인하는 법 |
|---|---|
| 첫 10초에 무엇을 고칠지 보이나 | 01 첫 화면: 총평 한 문장 + 고칠 것 순위 + 다음 행동 |
| 모든 주요 진단을 근거로 따라갈 수 있나 | 이슈마다 근거 1개 이상(스모크 `실측: 이슈 인사이트마다 근거`), 근거 길 비율 지표 |
| 청중석이 캐릭터 쇼가 아니라 이해 도구인가 | 대사마다 근거 상태 · 엔진 판정 비교 · 근거로 가기 |
| 화면을 바꿔도 맥락이 이어지나 | 주소 `i · t` + 뒤로 가기 · 새로고침 시험(QA.md) |
| 제안이 연습으로 이어지나 | 제안마다 PracticeTarget(실제 앱 주소) |
| 구버전 값이 보존되나 | 점수 · 판정은 원래 산출물 그대로 표시, 기존 리포트 무변경 |

## 4. UX 원칙
- 한 화면의 주인공은 하나. 대시보드식 카드 겹치기 · 장식 그래프 금지.
- 해요체 · 「닫기」 · 다크패턴 금지(CLAUDE.md §3). 판정 5색 불변.
- 데이터가 없으면 없다고 말한다(`unavailable · not_supported` 를 사람 말로).
