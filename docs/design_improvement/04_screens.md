# 04 — 화면별 적용 지도

> 아래 행 번호는 2026-08-06 기준이다. 데모 스프린트 중이라 파일이 자주 움직인다 —
> **행 번호가 어긋나면 함수 이름·클래스 이름으로 grep 해서 다시 찾는다.**

## 1. 전 화면 공통 (토큰만으로 바뀌는 것)

`02_tokens.md` 적용 순간: 배경 회색→크림, 카드 4px→20px, 버튼 초록 갱신, 본문 잉크 갱신.
코드 수정 없이 토큰 값으로만. 이후 화면별 확인:

| 화면 | 확인 포인트 |
|---|---|
| `#/` 홈 | 크림 배경 위 흰 카드 · 다크 verdict 헤드 그라디언트(새 navy) · 764px 세로 예산 안 스크롤 0 유지 |
| `#/new` | 드롭존 dashed 보더가 새 `--border` 와 어울리는지 |
| `#/qa` | 판정 칩 5색 그대로인지 (변하면 안 된다) |
| `#/report` | 탭 바(민트 유리)·판정 헤드·카드 radius |

**대상:** `js/app.js` `reportVerdict()`(~2280-2300) · `renderReport()`(~2340-2373 마크업) ·
`design-system.css` `.verdict-*`(37-119)

| 변경 | 상세 |
|---|---|
| 점수 옆 발표새 | `.verdict-score` 안, 숫자 오른쪽에 52px 엑씨 1마리. `Chatter.chickSvg('ax')` 를 그대로 쓴다 (`window.Chatter` 로 이미 노출돼 있다 — `chatter.js:638-644`). mood 는 점수 티어: ≥90 `excited` / ≥75 `happy` / 그 외 `neutral`. 좌석 래퍼 없이 svg 만 넣으면 mood CSS 가 안 걸리므로 **`<span class="ch-seat" data-mood="…">` 축소 래퍼**로 감싼다 |
| 안내 문구 말풍선 톤 | `realSummary()`(~2641) 의 notes 조립부. "이 상황에서는 평가하지 않는 항목 N개" → "이번 발표 상황에서는 평가하지 않는 항목이 N개 있어요" / "이번엔 측정할 수 없었던 항목 N개" → "이번엔 측정하지 못한 항목이 N개 있어요. 다음 발표에서는 더 많은 피드백을 받아봐요!" — **개수 N 은 반드시 그대로** (정직 원칙). 두 안내는 계속 분리 (합치면 안 된다) |
| 막대 끝 점 | `.verdict-dims .bar i` 에 `::after` 흰 점 (r3). 7개 막대라 별·잎은 소음 |
| 응원 문맥 | 점수가 낮아도 grumpy·슬픔 없음. 헤드 카피는 기존 `headline` 로직 유지 |

가리지 않게 `.verdict-inner` 안(z-index 2)에 둔다.

## 홈 첫 화면 — 점수 카드를 캐릭터 카드로 (2026-08-07 결정)

### 왜 바꾸나

지금 홈 첫 화면에 **「최근 발표 완성도 86점 · 최근 5회 61 → 86」** 이 떠 있다.
처음 온 사람은 발표를 한 번도 안 했는데 샘플 점수가 자기 기록인 척한다.
부스에서는 방문자의 99% 가 첫 방문이라, 이게 사실상 늘 보이는 화면이다.

성장선 자체도 문제다. 서로 **다른 발표** 의 점수를 한 선으로 이어 "25 올랐다"
고 말한다. 상황별로 채점 가중치가 다르니 애초에 비교 가능한 숫자가 아니다.
비교가 성립하는 건 **같은 발표를 다시 연습했을 때** 뿐이다(리포트의 「N번째 연습」).

### 무엇을 넣나

사용자 데이터가 아니라 **제품 구성** 을 보여준다. 그래야 첫날에도 꽉 찬다.

```
네 모델이 각자 맡은 일로 발표를 봐요

  🐤형광펜      🐤슬라이드     🐤배지        🐤헤드폰
  믿:음         쏠라          엑사원        엑씨
  대조          자료          인정          듣기
  KT            Upstage       LG            SKT
```

역할은 지어낸 말이 아니라 파이프라인의 실제 담당과 1:1 이다.

| 캐릭터 | 화면 문구 | 실제 담당 |
|---|---|---|
| 믿:음 | 자료와 어긋난 곳을 찾아요 | F-11 정합 판정 |
| 쏠라 | 자료를 처음부터 끝까지 읽어요 | F-01 파싱 · F-06/07 개념 |
| 엑씨 | 발표를 귀로 들어요 | F-05 STT |
| 엑사원 | 잘 설명한 개념을 짚어줘요 | aligned 판정 |

소품(형광펜·슬라이드·로제트·헤드폰)은 `js/chatter.js` 의 `chickSvg()` 에 이미
있다. 새로 그리지 않는다 — [01_character.md](01_character.md) 의 매핑 그대로다.

### 확정된 결정

1. **후원사는 텍스트로만.** 로고 이미지를 넣지 않는다. 청중 카드가 이미
   `KT 믿:음` · `Upstage Solar` 처럼 텍스트로 쓰고 있어 그 문법을 따른다.
   («정말 필요한 순간에 작게» 원칙 — README 의 로고 판단과 같은 선)
2. **점수는 발표 목록의 각 줄로 내린다.** 홈 상단에서 큰 숫자로 주장하지 않고,
   그 발표의 속성으로 작게 붙인다. 성장선은 그리지 않는다 —
   같은 발표의 회차 간 비교가 아니면 이어 그리지 않는다.

### 구현할 때 지킬 것

- 캐릭터가 콘텐츠를 가리지 않는다. 이 카드는 **설명** 이지 연출이 아니다.
- 카드 하나로 끝낸다. 히어로·마케팅 카피를 붙이지 않는다 (MVP_SPEC §3).
- `.ch-seat` 은 객석 연출용이라 `opacity:0` 으로 시작한다.
  앱 화면에서 쓰면 보이게 하는 규칙을 같이 걸어야 한다
  (design-system.css 의 `.verdict-bird` · `.empty-bird` 와 같은 처리).
