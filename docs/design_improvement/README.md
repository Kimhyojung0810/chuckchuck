## 0. 왜 고치는가

지금 병아리 4마리가 안 귀여운 이유는 캐릭터가 아니라 **캐릭터 시스템이 없어서**다.

- 몸 색이 4가지로 갈라진다 (`--chick-midm:#f6c945` / `solar:#ffd76e` / `exaone:#f7b96b` / `ax:#ffe3a3`)
- 외곽선이 없다 — 레퍼런스(Certi·피니·코리)의 귀여움은 **굵은 브랜드색 외곽선 + 3~4색 제한**에서 온다
- UI 와 그림체가 따로 논다 — 4px 각진 카드, 회색 `#F5F5F5` 배경, 진지한 교육기관 대시보드 위에
  이모지 크기의 병아리가 얹혀 있다

레퍼런스가 잘하는 것: **캐릭터만 귀여운 게 아니라 UI 전체가 같은 그림체**다. 폴더에도 눈이 있고,
카드·배지·인증서가 전부 같은 세계관의 물건처럼 보인다.

## 1. 방향 — 절대 원칙

**"병아리 여러 마리"가 아니라 "하나의 발표새와 그 친구들".**

1. **몸은 하나, 소품만 4종.** 기본 캐릭터 하나를 만들고 역할 소품만 바꿔 붙인다.
   체형·그림체·색이 제각각이면 팀이 아니라 랜덤 스티커 모음으로 보인다.
2. **귀여움의 문법만 가져온다.** 레퍼런스를 베끼지 않는다 — 머리 60%+, 극단적으로 짧은 팔다리,
   굵은 브랜드 초록 외곽선, 색 3~4개 제한, 모든 컴포넌트가 같은 곡률과 색을 공유.
3. **70 / 20 / 10.** 콘텐츠 영역은 차분하게, 피드백 순간만 귀엽게.
   - 70% — 깔끔한 교육 서비스 (표·숫자·리스트는 그대로)
   - 20% — 부드러운 색(크림 배경·민트 틴트)과 둥근 컴포넌트(카드 20px)
   - 10% — 캐릭터와 작은 애니메이션 (빈 상태·완료·로딩·점수 옆·청중 카드 **만**)
4. **낮은 점수는 응원, 높은 점수는 축하.** 캐릭터가 우는 표정은 어떤 경우에도 없다 —
   교육 서비스에서 실패감을 주면 안 된다.
5. **모든 버튼에 캐릭터를 넣지 않는다.** 그러면 유치해진다.

## 3. 다른 디자인 문서와의 우선순위

이 저장소에는 디자인 문서가 셋이다. 충돌이 아니라 담당이 다르다:

- **이 폴더 (`docs/design_improvement/`)** — 캐릭터 시각 스펙과 컴포넌트 그림체의 **새 원본**.
  `docs/UI_REDESIGN.md` §9(실루엣)·§10(캐릭터 시트)의 시각 수치를 **대체**한다.
- **`docs/UI_REDESIGN.md`** — 연출·카피 규율은 **그대로 유효**: §11 모션 스펙(Anticipation·
  Squash&Stretch·동시에 움직이는 건 1마리), §12 카피 원칙(병아리는 판정하지 않는다, 원한다),
  §13 기억하는 객석, §14 토스의 규율.
- **`demo/YEHS_demo/MVP_SPEC.md` §3 절제 규율** — 앱 화면(`#/`, `#/new`, `#/qa`, `#/report`)의
  기율은 그대로: 히어로·마케팅 카피·장식 이모지 금지, 한 화면의 주인공은 하나,
  홈·새발표·QA 페이지 스크롤 0 (764px 세로 예산).
- 토큰의 단일 원본은 여전히 **`demo/YEHS_demo/css/app.css` 의 `:root`** 다 (CLAUDE.md §3-3).
  `02_tokens.md` 는 변경 지시서고, 적용 후에는 코드가 원본이다.

## 4. 불가침 — 바꾸면 안 되는 것

- **판정 색 5종 `--ok / --mid / --no / --ct / --om` (+ `-bg`) 불변.** 의미가 붙어 있어서
  바꾸면 리포트가 거짓말이 된다 (CLAUDE.md §3-3).
- **숫자·표·판정 칩은 캐릭터가 대체하지 않는다.** 박수는 숫자의 앞에 오지, 숫자를 대체하지 않는다.
- **모든 연출은 스킵 가능.** 두 번째부터는 빨리 가고 싶은 게 정상이다.
- **정직한 상태 유지.** 진행률·오류 원인·샘플 표시·"측정 못 함" 개수 — 문구 톤은 부드럽게 바꿔도
  사실은 그대로 보여 준다.
- **reduced-motion 레지스트리 동기화.** 새 keyframe 을 추가하면
  `css/chatter.css:934-969` 와 `css/theater.css:583-607` 의 수동 목록에도 넣어야 한다 —
  안 넣으면 모션 최소화를 켠 사용자에게 애니메이션이 그대로 재생된다.
- **이름·명패 유지.** 믿:음/쏠라/엑사원/엑씨 + KT/Upstage/LG/SKT 배지는 4개 국산 LLM 후원사
  정체성이라 대회 셀링 포인트다. 피니/코리 같은 새 이름을 붙이지 않는다.
- **`js/app.js`(199KB)·`css/app.css`(94KB) 분할 리팩터 금지** (CLAUDE.md §4, 마감 전).

## 6. 검증 — "구현하고 테스트하고 돌린다"

구현 에이전트는 각 단계 후 아래를 돌린다 (자세한 순서는 `05_implementation.md`):

```bash
cd /home/ubuntu/workspace/00_chuckchuck

# 1) 파이썬 회귀 — 이 개편은 JS/CSS 만 만지므로 결과가 그대로여야 한다
python -m pytest tests/ -q                       # 기준선: 544 passed · 7 skipped

# 2) JS 문법
node --check demo/YEHS_demo/js/chatter.js
node --check demo/YEHS_demo/js/app.js
node --check demo/YEHS_demo/js/playbill.js

# 3) 데모 기동 스모크
MOCK_EXTERNAL_APIS=true DEMO_PORT=8840 python -m demo.bridge   # http://127.0.0.1:8840/
curl -s localhost:8840/api/health                              # {"ok":true,"mock":true}
```

- 코드 반영 **전**: `components/preview.html` 을 브라우저로 열어 캐릭터·토큰 확정

- **`index.html` 의 `?v=` 를 반드시 한 단계 올린다.** 현재 값을 외우지 말고
  `grep -o '?v=[a-zA-Z0-9]*' demo/YEHS_demo/index.html | sort -u` 로 확인 후 전부 +1
  (안 올리면 브라우저가 옛 CSS/JS 를 서빙해서 "고쳤는데 안 바뀐다"가 된다 — CLAUDE.md §2)
