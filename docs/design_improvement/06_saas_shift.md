## 0. 채택하지 않은 것 — 먼저 못 박는다

원안에 있었지만 **일부러 안 가져온 것 세 가지** 다. 나중에 "왜 시안과 다르지"
가 나오면 여기를 본다.

| 원안 | 왜 안 하나 |
|---|---|
| 영문 라벨 (`Evidence` `Slides` `Delivery` `Clarity`) | CLAUDE.md §3-1 해요체·Pretendard 하나. 이번 스프린트에 랜딩에서 `SLIDE 04`·`SCROLL`·`S01~S08` 을 걷어낸 것과 정면으로 어긋난다. 한국 심사위원·국산 LLM 후원사 앞에서 영문 라벨은 세련됨보다 겉멋으로 읽힌다 |
| 역할 재배정 (엑씨=Delivery, 엑사원=Clarity) | **사실이 아니다.** 말투·속도는 F-17/F-18 이 하고 병아리 담당이 아니다. 이 카드의 유일한 강점이 "역할이 코드와 1:1" 인데 그게 깨진다 |
| Hero 의 `지난 연습 대비 평균 +8점 ↑` | 서로 다른 발표의 점수를 평균한 값이다. 상황별 채점 가중치가 달라 비교가 성립하지 않는다 — 방금 홈에서 지운 그 숫자다. 쓰려면 **같은 발표의 회차 간 비교**(「2번째 연습 · 지난번보다 +10」)여야 한다 |

### 불변

- **판정 5색 `--ok/--mid/--no/--ct/--om` 은 손대지 않는다.** 의미가 붙어 있다.
- **확인할 것:** `--om`(생략)·`--ct`(못 잼)이 회색 계열이라 새 `--border #E4E4E7`
  ·`--text-3 #71717A` 와 헷갈릴 수 있다. 채점표 탭·개념별 판정에서 대비를 눈으로 본다.

### 초록을 쓰는 자리

**CTA 와 판정 상태에만.** 테두리·칩 배경·연한 면에서는 전부 뺀다.
지금은 초록이 브랜드색이 아니라 배경색처럼 쓰이고 있다.

## 2. 카드 구조 — 중첩을 없앤다

> 큰 rounded rectangle 안에 작은 rounded rectangle 을 계속 넣는 패턴이
> 화면을 올드하게 만드는 주된 원인이다.

- 카드 안에 카드를 넣지 않는다. 행 사이는 **얇은 border-bottom** 으로만 나눈다.
- `--r-print` 20px 은 바깥 카드에만. 안쪽 요소는 radius 를 주지 않거나 8px 이하.
- border 는 거의 없애고 **아주 옅은 회색 border + 옅은 shadow** 로.
- 「지난 발표」는 테두리 상자 안의 `<ul>` 이 아니라 **테두리 없는 리스트**.
  행 hover 시 `#FAFAFA`.

## 3. 타이포 위계

지금은 전부 13~15px 이라 힘이 똑같다.

| 자리 | 크기 / 굵기 |
|---|---|
| Hero 제목 | 40–48px / 700 |
| 섹션 제목 | 16–18px / 600 |
| 카드 제목 | 14–15px / 600 |
| 메타데이터 | 12–13px / 400 |
| 점수 | 22–28px / 650 |

점수는 `86점 ›` 이 아니라 **숫자를 크게, 라벨을 작게** — 지표 자체가 제품 UI 로
보이게 한다.

```

  발표, 혼자 연습하지 마세요.
  AI 청중 앞에서 연습하고 바로 피드백을 받아보세요.

  [ + 새 발표 연습 ]

              🐥  "오늘도 한번 해볼까요?"
──────────────────────────────────────────────────────────
지난 발표                                        전체 보기 →

IMU2CLIP 논문 리뷰            학회·수업 발표          86
Hierarchical VLA 논문 리뷰     학회·수업 발표          79
척척발표 서비스 피치           대회·IR 피칭            91
──────────────────────────────────────────────────────────
내 발표를 보는 네 모델

🐥 믿:음        🐥 쏠라         🐥 엑씨         🐥 엑사원
대조            자료            듣기            인정
자료와 어긋난    자료를 처음부터   발표를 귀로      잘 설명한 개념을
```

- **AI 청중을 제품 기능으로 격상.** 지금은 작은 박스 안 설명서처럼 보인다.
  hover 시 캐릭터가 살짝 움직이거나 말풍선이 뜨게 한다.
- 역할 문구·후원사 텍스트는 [04_screens.md](04_screens.md) 결정 그대로.
  **파이프라인 실제 담당과 1:1 을 유지한다** (§0).

### MVP_SPEC §3 과의 관계

MVP_SPEC 은 앱 화면(`#/`)에 히어로·마케팅 카피를 금지한다. 이 문서는 **홈에
한해** 그 조항을 푼다 — 부스 방문자의 99% 가 첫 방문이라 홈이 사실상 첫인상
화면이기 때문이다. 다른 앱 화면(`#/new`·`#/qa`·`#/report`)에는 그대로 적용된다.

## 6. 순서와 위험

1. 카드 중첩 제거 + 「지난 발표」 리스트화
2. 초록 빼기 (테두리·칩·면 → 중립 회색)
3. 타이포 위계
4. 토큰 값 교체 (`--canvas` · `--border` · `--brand` …)
5. 홈 Hero 구조
6. micro-animation

**위험:** 1차 마감이 08-09 다. 4번은 랜딩·리포트·극장까지 전부 재검증 대상이
된다. 1~3 은 토큰을 안 건드리고 *쓰는 자리* 만 줄이므로 되돌리기 쉽다.
시간이 모자라면 **1~3 까지만 하고 4~6 을 미룬다.**

검증은 스크린샷으로 한다 — 1366×1024 에서 홈·`#/new` 1~3단계·`#/qa`·리포트
6개 탭·객석까지 눈으로 본다. 이번 스프린트에 그렇게 잡은 버그가 여럿이다.
