# 분석 대기 구간 재설계 — 발표 종료에서 질문 코칭까지

> 대상 화면: `#/new` 스텝 4 + `f11_reveal.html` 오버레이
> 작성: 2026-08-07 · 관련 규율: [`CLAUDE.md`](../CLAUDE.md) §3·§4 · [`UI_REDESIGN.md`](UI_REDESIGN.md) §14

## 0. 한 줄 요약

지금 이 구간은 **7분 30초를 기다리는 동안 5분이 완전히 정지한 화면**이고,
자랑거리인 개념그래프·산점도 연출은 **실 API 에서 한 번도 재생되지 않는다.**

원인은 버그 여러 개가 아니라 하나의 구조적 선택이다 —
**"발표가 끝난 뒤에 분석을 시작한다."**

이 문서는 그 전제를 뒤집는다.
**발표가 끝나는 순간, 분석의 절반은 이미 끝나 있어야 한다.**

## 1. 진단

### R1. 필요 없는 의존성까지 직렬로 기다린다 ← 손실이 가장 크다

[`f07_graph.py:8-9`](../chuckchuck/f07_graph.py) 가 명시한다:

> F-07 은 Transcript 를 받지 않습니다. 그건 node.id 로 조인하는 뒤 단계 몫입니다.

[`f06_concepts.py:98-101`](../chuckchuck/f06_concepts.py) 의 transcript 도 `speech_hint` 용 **선택** 인자다.
그런데 `chuckchuck_bridge.js` 의 `runPreparePipeline()` 은 STT → concepts → graph → align 을 한 줄로 `await` 한다.

실측(2026-07-30, 12장 PPTX + 3분 녹음, 실 Solar) 기준:

| 단계 | 시간 | 녹음이 필요한가 |
|---|---|---|
| F-05 STT | 0:30 | 필요 |
| F-06 개념 추출 | 1:43 | **불필요** |
| F-07 개념 그래프 | 2:40 | **불필요** |
| F-11 정합 판정 | 2:27 | 필요 |
| 흐름 비교 | <0:01 | 필요 |
| **합계** | **7:30** | |

**4분 23초가 녹음과 무관한데 녹음이 끝나기를 기다린다.**
사용자가 3~20분 발표하는 동안 서버는 놀고 있다.

### R2. 킬러 연출이 실 API 에서는 재생되지 않는다

`f11_reveal.html` 의 대기 루프:

```js
} while (!dataArrived && !skipped && pass < 90);   // × 900ms ≈ 87~92초
```

`dataArrived` 는 `f11Data`(graph **와** alignment 둘 다 도착)에서만 `true` 가 되는데,
그 시점은 `align_done` ≈ **450초**다.

즉 오버레이는 **매번 90초에 포기**하고 「분석이 아직 끝나지 않았어요」 안내로 떨어진다.
개념그래프 · 스윕 · 판정 · 산점도 — 전부 실 API 에서는 **한 번도 안 나온다.**
mock 으로 미리보기할 때만 보인다.

### R3. 가장 긴 5분 동안 진행 표시가 0개다 ← "빈 화면"의 정체

`graph` + `align` 구간(합계 5:07)에서 무슨 일이 벌어지나:

- `pipelineLoadingHtml('concepts')` 는 phase 가 `stt_done|concepts` 일 때만 반환 → `''`
- `pipelineLoadingHtml('stt')` 는 transcript 가 이미 도착해서 분기 자체를 안 탄다
- 결과: `.progress` 막대도 `.pipe-elapsed` 노드도 **DOM 에서 사라진다**
- `startPipelineElapsedTimer()` 는 1초마다 돌지만 **갱신할 대상이 없다**

**5분 동안 화면이 완전히 정지한다.**
커튼 뒤 병아리 한 줄만 남는데 그것도 `graph_done` 에서 한 번 찍히고 끝이다.

### R4. 체크리스트가 거짓말한다

`pipelineChecklistDone()` 은 `concepts_done` 에서 **4** 를 반환한다. 그 순간 4개가 전부 ✓ 로 바뀐다:

- ✓ 「발표자료의 개념과 실제 발화를 대조했어요」 → **F-11 은 아직 시작도 안 했다**
- ✓ 「먼저 확인할 질문을 만들었어요」 → **F-08 은 이 파이프라인에서 아예 안 돈다** (`#/qa` 진입 후에 돈다)

그런데 CTA 는 `nf.conceptsOk` 를 요구하고, 그 플래그는 파이프라인 **완전 종료 후**에만 세팅된다.

> **다 됐다고 표시해 놓고 5분 동안 버튼이 안 생긴다.**

CLAUDE.md §4 「분석이 실패하면 실패로 보여준다」 · UI_REDESIGN §14 「진행률은 정직하게 남긴다」 에 정면으로 어긋난다.

### R5. 진행률이 계산되어 있는데 아무 데도 안 그려진다

`pipelinePercent()` 와 `PIPELINE_MARKS` 는 실측 기반으로 잘 캘리브레이션돼 있다.
`percent` 는 postMessage 로 iframe 까지 **이미 건너간다.**

받는 쪽 핸들러는 `label` · `detail` · `transcriptPreview` 만 읽고 **`percent` 를 버린다.**
화면의 유일한 막대는 `.progress.indeterminate` — 정보량 0인 CSS 애니메이션이다.

### R6. 완료 선언 시점이 실제와 어긋난다

```js
if ((nf.pipelinePhase || '') === 'done') location.hash = '#/qa';
```

F-08 질문 생성에 필요한 건 **graph + alignment + flow** 뿐이다.
rubric(F-14) · pace(F-17) · habits(F-18) · report(F-19) 는 **리포트 화면 몫**인데
질문 코칭 진입이 그것까지 다 기다린다.

### R7. 7분의 결론이 헤드라인 숫자 하나다

요약 화면의 초대형 `covNum %` + 「자료의 핵심을 이만큼 설명했어요」.

[`f11_align.py:52`](../chuckchuck/f11_align.py) 주석이 이미 인정한다:

> coverage 분모에서 빠지는 판정이라, LLM 이 후하게 주면 헤드라인 점수가 부푼다.

`coverage = aligned_weight / (전체 − justified_skip)` 이라 판정이 후하면 **100%** 가 나온다.
그러면 CTA 힌트가 「자료의 핵심을 빠짐없이 다뤘어요」로 끝난다.

> **7분 기다린 대가가 "잘했어요" 한 줄.** 개선점이 하나도 안 남는다.

문제는 *100% 라는 숫자*가 아니라 **100% 면 남는 말이 없다**는 것이다.

### R8. 같은 자료를 열 번 시연하면 4분 23초를 열 번 태운다

디스크 캐시는 F-01 SlideDoc 뿐이다. ConceptDoc · ConceptGraph 는 어디에도 저장되지 않는다.
부스에서 같은 발표자료로 반복 시연하는 상황에 정확히 안 맞는다.

## 2. 재설계 — 세 개의 시계를 분리한다

지금은 세 층(파이프라인 · 대기 화면 · 리빌 연출)이 **전부 "발표 종료" 한 시점에 시작**한다.
서로 다른 시계로 떼어낸다.

| 시계 | 언제 도나 | 무엇이 도나 | 걸리는 시간 |
|---|---|---|---|
| **A · 자료 축** | 발표 정보 입력 직후 ~ **발표(녹음) 중** | F-06 개념 추출 → F-07 개념 그래프 | 4:23 (사용자는 발표 중이라 안 기다림) |
| **B · 발표 축** | 발표 종료 직후 | F-05 STT → F-11 정합 → 흐름 | **2:57** ← 유일한 실제 대기 |
| **C · 리포트 축** | 질문 코칭 중 | F-14 채점 · F-17 속도 · F-18 습관 · F-19 리포트 | 사용자가 질문에 답하는 동안 |

### Before / After

```
현재 (직렬 7:30)
발표종료 ├─STT─┤─────concepts─────┤────────graph────────┤────────align────────┤flow│rubric·pace·habits·report│→ Q&A
        0:00  0:30              2:13                 4:53                  7:20 7:21                    7:30
        └─ 90초 뒤 리빌 포기 ─┘└──────────── 진행 표시 0개, 화면 완전 정지 ────────────┘

개선 (선분석 + 조기 진입)
녹음중  ├──────── concepts ────────┤──────── graph ────────┤     ← 사용자는 발표하는 중
발표종료 ├─STT─┤────────align────────┤flow│→ Q&A 진입    rubric·pace·habits·report 는 Q&A 중 백그라운드
        0:00  0:30               2:57 2:58
        └ 그래프는 이미 있음 ┘└─ 결정론적 진행률 + 살아있는 그래프 ─┘
```

**체감 대기 7:30 → 약 3:00.**
3분 이상 발표하면 concepts · graph 는 발표 중에 끝난다.
3분 미만이면 남은 분량만 기다리고, 진행률 표가 그만큼 자동으로 늘어난다.

### 리빌 오버레이의 역할 변경

**"기다리는 화면" → "이미 아는 것부터 보여주는 화면".**

발표가 끝난 시점에 개념 그래프가 이미 손에 있다. 연출 순서가 통째로 바뀐다.

| 씬 | 시점 | 무엇을 보여주나 | 데이터 |
|---|---|---|---|
| 0 그래프 | **즉시 (0초)** | 「발표하는 동안 자료를 먼저 읽어 뒀어요」 — 개념 노드가 피어난다 | 선분석 graph |
| 1 전사 | ~0:30 | 실제 말한 문장이 흐르고 키워드가 노드에 붙는다 | STT transcript |
| 2 **듣는 중** | 0:30~2:57 | **유일한 진짜 대기 구간.** 노드 게이지가 차오르고 하단에 결정론적 막대 + 남은 예상 시간 | transcript + percent |
| 3 판정 | 2:57 | 초록 / 흐림 / 빨강 판정이 노드에 찍힌다 | alignment |
| 4 산점도 | | 「자료와 발표를 나란히 놓으면」 | alignment |
| 5 요약 | | **행동 가능한 결론** (§3-⑥) | alignment + graph |

지금은 씬 0~5 전체가 90초 안에 못 들어와 통째로 스킵된다.
재설계 후에는 **대기가 씬 2 하나에 몰리고, 그 씬은 화면이 살아 있다.**

## 3. 작업 항목

### P0 — 퀀텀 점프 본체

#### ① 선분석 — 녹음 중에 F-06 · F-07 을 돌린다

- **발화 지점**: 스텝 2 「녹음하러 가기」 / 「건너뛰기」 핸들러.
  업로드 직후가 아니라 **여기**여야 한다 — `situation` · `audience` 는 F-06 프롬프트에 그대로 들어가
  개념 중요도를 바꾼다. 업로드 시점에는 아직 안 정해져 있다.
- **저장 형태**: 캐시가 아니라 **promise**.
  > 캐시 조회 방식이면 짧은 녹음에서 "아직 없음" → 두 번 결제한다.
  > promise 를 await 하면 진행 중인 호출에 그대로 붙는다.
- **키**: `fileName | occ | ctx | min`. 키가 바뀌면(뒤로 가서 수정) 버리고 다시 건다.
- **폴백**: promise 가 reject 되면 기존 경로(파이프라인 안에서 호출)로 되돌아간다.
- **부수 비용 — 공짜가 아니다**: transcript 없이 F-06 을 부르므로
  `text_sparse` 슬라이드의 `speech_hint` 를 잃는다. 글자 없는 슬라이드의 topic 추정이 약해진다.
- **백엔드 변경 없음.** `demo/bridge.py` 는 `ReusableThreadingHTTPServer` 라 동시 요청을 받는다.

#### ② 리빌 재설계 — 그래프 우선 + 타임아웃 제거

- 선분석 graph 가 준비되면 **alignment 를 기다리지 않고** `f11Graph` 메시지를 먼저 보낸다.
- `applyGraphOnly(graph)` — 기존 `applyRealData()` 에서 alignment 의존부를 뺀 형태.
  verdict 없이 doc weight 로만 스테이지를 만든다.
- `pass < 90` 종료 조건을 **`graphArrived` 대기**로 교체.
- 새 씬 `sceneListening()` — 그래프가 뜬 상태로 alignment 를 기다린다.
  하드 상한은 **20분**으로 넉넉히 두고, 넘으면 기존 정직한 실패 문구로 떨어진다.
- 대기 중 「건너뛰기」는 모의 요약으로 점프하지 않고 **오버레이를 닫는다.**
  데이터 없이 요약 화면을 띄우면 CLAUDE.md §4 위반이다.
- `#/qa` 진입 조건을 `done` → **`flow_done` 이후**로 완화.

#### ③ 결정론적 진행률을 실제로 그린다

- 리빌이 `percent` 를 **읽는다**(이미 전선에 흐르고 있다).
- 대기 화면 하단에 determinate 막대 + 「n% · 남은 예상 약 m분」.
- 스텝 4 에 **항상 떠 있는 상태 줄**을 추가한다. 단계 라벨 · 경과 초 · 진행률은
  phase 와 무관하게 상시 표시한다.

#### ④ 선분석 경로용 진행률 표 재계산

`PIPELINE_MARKS` 는 F-06 · F-07 이 임계경로에 있다고 가정한다.
선분석이 끝난 상태로 시작하면 막대가 6%→74% 로 튄 뒤 2분 27초를 기어간다.

`buildPipelineMarks({ conceptsReady, graphReady })` — 파이프라인 시작 시점에 promise 가 settled 인지 보고,
끝난 단계의 구간 폭을 접고 남은 폭을 **실측 소요 시간 비율대로** 재분배한다. 한 번만 만들고 중간에 안 바꾼다.

> ⚠️ **phase 키는 하나도 바꾸지 않는다.** `chuckchuck_bridge.js` 의 `report()` 계약이고
> `PIPELINE_MARKS` · `pipelinePhaseLabel` · `pipelineChecklistDone` · `backstageLine` 이 동시에 물려 있다.

### P1 — 정직성 · 결론

#### ⑤ 체크리스트 · 완료 선언 정직화

- 항목을 실제 단계에 1:1 로 다시 매핑한다. 「먼저 확인할 질문을 만들었어요」는
  이 파이프라인이 하는 일이 아니므로 뺀다.
- `concepts_done` 에서 4 를 반환하는 조기 완료를 제거한다.
- CTA 노출 조건을 `flow_done` 이후로 맞춘다.
- 「분석을 마쳤어요」는 alignment · flow 까지를 뜻한다. 리포트 축이 아직 도는 중이면
  「상세 리포트는 뒤에서 마저 만들고 있어요」를 한 줄 남긴다.

#### ⑥ 요약 히어로 재설계 — 100% 여도 피드백이 남게

히어로를 **숫자에서 한 문장의 발견**으로 바꾼다.
coverage 가 100% 여도 데이터에 항상 남아 있는 것들이 있다:

- `rank_correlation` — 중요한 순서대로 말했는지 (커버리지 100% 여도 순서는 틀릴 수 있다)
- `edge_coverage` — 개념 **사이 연결**을 말로 이었는지 (보통 여기가 낮다)
- `doc_weight` 는 높은데 `speech_weight` 가 가장 낮은 노드 — **항상 존재한다**

우선순위대로 하나 고른다:

1. `contradiction` 있으면 → 그것
2. `missing` 있으면 → `doc_weight` 최대인 것
3. **둘 다 없으면(=100%)** → `doc_weight − speech_weight` 최대 노드로
   「자료가 2번째로 힘준 **X** 를, 발표에서는 가장 얇게 짚고 넘어갔어요」
4. 그것도 평평하면 → `edge_coverage` 로 「개념 10개 중 연결을 말로 이어준 건 3쌍이에요」

초대형 `covNum %` 는 보조 지표 줄로 내린다 — 7분 기다린 직후의 거대한 100% 는 진행률로도 오독된다.

#### ⑦ 녹음 중 선분석 상태 표시

녹음 화면 구석에 작게 한 줄: 「발표하는 동안 자료를 먼저 읽고 있어요」 → 「자료 개념 정리를 마쳤어요」.
연출이 아니라 **기대치 설정**이다. 끝나고 왜 빠른지 사용자가 납득한다.
녹음 화면의 주인공은 슬라이드다 — 작게.

#### ⑧ ConceptDoc · ConceptGraph 디스크 캐시

`fixtures/raw/stage_cache/{stage}-{sha1}.json`. **파일 이름이 아니라 내용 해시로 건다.**
SlideDoc 캐시는 파일명 stem 을 쓰는데 이름이 같은 다른 자료가 조용히 붙을 수 있어서
그쪽은 근사 매치 폴백을 금지해 뒀다. 여기서는 아예 내용이 1비트라도 다르면 다른 키가 되게 한다 —
근사 매치가 존재할 수 없다.

키에 넣는 것: 단계 이름 · 입력 문서 · `context` · `llm`(mock 여부 포함) · (F-06 은) transcript.
출력에 영향을 주는 걸 하나라도 빼면 캐시가 거짓말을 한다.

**부스에서 같은 자료 2회차부터 4분 23초 → 0초.** 끄려면 `DEMO_STAGE_CACHE=0`.

#### ⑨ 배치 세분화 + 배치별 서브 진행률

`CHUCKCHUCK_CONCEPT_BATCH_SIZE`(기본 8) 를 4 로 낮추면 12장이 2배치 → 3배치가 되어 fan-out 이 늘고,
**배치별 실제 완료 개수**를 진행률로 쓸 수 있다. 코드 변경 없는 환경변수 노브 + 서브 진행률 배선.

#### ⑩ 검증용 지연 노브

`MOCK_EXTERNAL_APIS=true` 에서는 모든 단계가 즉시 끝나 **대기 UI 를 검증할 수 없다.**
`DEMO_FAKE_STAGE_DELAY_SEC` 로 단계별 인위 지연을 준다 — 실 API 를 태우지 않고 대기 화면을 반복 확인한다.

UI 타이밍만 볼 때 쓰고, 그 화면으로 분석 품질을 판단하지 않는다.

캐시를 비우고 처음부터 보려면 `rm -rf fixtures/raw/stage_cache` (재생성되는 산출물이다).
