# 척척발표 재설계 — 리포트를 버리고 객석을 남긴다

## 한 줄

**병아리는 기능이 아니라 제품이어야 한다.**

지금은 분석 리포트에 마스코트를 하나 붙여 놓은 모양이다. 그래서 병아리가 있는 화면만 귀엽고 나머지는 대시보드다. 뒤집어야 한다 — **발표를 병아리 넷 앞에서 했고, 지금 걔들이 뒤에서 떠드는 걸 엿듣는 것.** 그게 제품 전체가 되어야 한다.

---

## 1. 진단 — 감정 곡선이 거꾸로다

사용자가 실제로 겪는 순서:

```
발표한다        ← 부끄럽고 힘듦. 감정 최대
   ↓
7분 기다린다     ← 막대만 돈다. 죽은 시간
   ↓
점수를 받는다    ← 86점. 판결
   ↓
못한 걸 본다     ← "8개 개념을 설명하지 않았어요". 상처
   ↓
(맨 끝에) 청중   ← 유일하게 귀여운 부분. 근데 이미 지쳤다
```

**가장 감정이 높은 순간(발표 직후)에 가장 지루한 화면(진행률 바)이 온다.** 그리고 유일하게 사랑스러운 부분이 제일 마지막, 지친 뒤에 온다.

그리고 더 큰 문제 — **두 은유가 싸우고 있다.**

| 은유 A: 분석 리포트 | 은유 B: 객석 |
|---|---|
| 점수·탭·차트 | 병아리·말풍선 |
| 도구적 | 감정적 |
| "당신은 86점입니다" | "그거 더 듣고 싶었어요" |

**둘 중 하나를 고르지 않아서 둘 다 약하다.** B를 고르면 A가 하던 일을 전부 흡수할 수 있다. 반대는 안 된다.

## 2. 이미 코드가 답을 알고 있다

`f12_chatter.py` 를 보면 **네 모델에게 각자 다른 분석 역할이 이미 배정돼 있다.** 그것도 "그 모델이 파이프라인에서 실제로 한 일" 기준으로.

| 병아리 | 코드상 담당 | 근거 |
|---|---|---|
| **믿:음** | 누락·모순 (`_midm_points`) | 자료와 발화가 어긋난 곳 |
| **쏠라** | 흐름·순서 (`_solar_points`) | 자료를 처음부터 끝까지 읽은 유일한 청중 (F-01/06/07) |
| **엑사원** | 잘한 것 (`_exaone_points`) | 'EXpert AI for everyONE' — 전문가의 인정 |
| **엑씨** | 발화·말 속도 (`_ax_points`) | 귀로 들은 유일한 청중 (F-05 STT) |

**그리고 지금 리포트 탭은 이것과 정확히 같은 축으로 나뉘어 있다.**

```
요약 · 개념별 판정 · 논리 흐름 · 말 속도 · 청중 반응
        └믿:음         └쏠라        └엑씨      └넷 다
```

**탭 이름만 무미건조하게 다시 붙여 놓은 것이다.** 이미 있는 캐릭터를 안 쓰고 있다.

### 그래서: 탭을 병아리로 바꾼다

```
[ 🐤 총평 ]  [ 🐤 믿:음 ]  [ 🐤 쏠라 ]  [ 🐤 엑사원 ]  [ 🐤 엑씨 ]
             빠뜨린 거      흐름          잘한 거        들은 대로
```

탭 하나를 누르면 **그 병아리가 자기 관점으로 브리핑한다.** 같은 데이터, 같은 정확도. 달라지는 건 **누가 말하느냐**다.

- 딱딱한 표: `개념별 판정 · 확신도 92% · 4축 체크 ✓✗✗✗`
- 병아리: 🐤 *"'공동 임베딩 정렬' 은 뭔지까지만 말하고 왜 필요한지는 안 알려줬어요. 저 그게 제일 궁금했는데!"* + 그 아래 같은 표

**표를 없애지 않는다.** 병아리 말풍선을 표 위에 얹는다. 감정으로 들어가서 정확한 데이터로 내려앉는다.

> 이게 "잘 생각했다" 지점이다. 새 기능을 만드는 게 아니라 **이미 있는 구조를 드러내는 것**이라 구현이 싸다.

## 3. 7분을 최고의 순간으로

지금 대기 화면은 막대 + 자막이다. 이걸 **병아리가 한 마리씩 극장에 도착하는 장면**으로 바꾼다.

파이프라인 단계가 그대로 서사가 된다 — 진짜로 그 순서로 일하기 때문에 지어낸 연출이 아니다.

| 파이프라인 | 화면 | 대사 |
|---|---|---|
| F-05 STT 완료 | 🐤 엑씨 자리에 앉음 | *"다 들었어요! 3분 12초였네요"* |
| F-06/F-07 완료 | 🐤 쏠라 앉음 | *"자료 12장 다 읽었어요. 개념 20개!"* |
| F-11 완료 | 🐤 믿:음 · 엑사원 앉음 | *"이제 맞춰볼게요…"* |
| 전부 완료 | 넷이 서로 쳐다봄 | *"…어? 얘기 좀 할까?"* |

**진행률 = 객석에 앉은 병아리 수.** 숫자가 아니라 상태로 읽힌다. 그리고 어디까지 됐는지가 오히려 더 정확하게 전달된다 — 지금 %는 추정치지만 병아리는 실제 완료 신호다.

기다림이 **"언제 끝나지"에서 "누가 올까"** 로 바뀐다. 같은 7분이다.

## 4. 점수를 판결이 아니라 반응으로

지금: 링이 차오르고 `86점` 이 뜬다. → **판결문.**

제안: 병아리 넷이 **박수를 친다.** 박수 세기·표정이 점수에 대응한다.

```
90+   전원 기립박수, 하트 튀어오름
75~89 넷 다 신나게 박수
60~74 박수 + 한 마리가 갸웃 (그 항목이 낮은 병아리)
~59   짝짝… 한 마리가 손 들고 "저 질문 있어요!"
```

숫자는 **박수가 끝난 뒤 조용히** 뜬다. 순서가 중요하다 — 반응을 먼저 보고 숫자를 본다.

그리고 **점수 항목 4개가 병아리 4마리와 1:1로 대응한다** (F-13 산식이 이미 4항이다):

| F-13 항목 | 담당 병아리 |
|---|---|
| 핵심 개념 설명 | 믿:음 |
| 비중 일치 | 믿:음 |
| 개념 연결 | 쏠라 |
| 흐름 순서 | 쏠라 |

막대 옆에 그 병아리 얼굴을 붙이면 **"누가 왜 이 점수를 줬는지"** 가 한눈에 보인다.

## 5. 상처 주지 않고 정확하기

이게 UX에서 제일 중요한 판단이다. **판정은 그대로 두고 화자만 바꾼다.**

| 지금 (진단서) | 제안 (호기심) |
|---|---|
| "아직 설명하지 않았어요" | 🐤 *"그거 더 듣고 싶었는데!"* |
| "자료와 다르게 말했어요" | 🐤 *"어? 자료엔 이렇게 적혀 있던데… 제가 잘못 봤나요?"* |
| "설명이 부족해요" | 🐤 *"왜 필요한지도 알려주세요!"* |
| "판정 확신도 92%" | 🐤 *"이건 확실해요"* / *"음… 좀 애매한데"* |

**핵심 원리: 부족을 지적하는 대신 더 듣고 싶다고 말한다.** 같은 정보인데 사용자는 혼나는 게 아니라 관심받는다. 그리고 실제로 그게 맞는 말이다 — 청중은 원래 더 듣고 싶어 하는 존재다.

`missing` 은 여전히 `missing` 이고 빨간색도 그대로다. **데이터를 무르게 하는 게 아니라 전달자를 바꾸는 것.**

## 6. 리허설을 외롭지 않게

지금 리허설 화면은 슬라이드 + 녹음 버튼뿐이다. **빈 방에 혼자 말한다.**

제안: 화면 하단에 **병아리 넷이 앉아 있다.** 작게, 조용히. 발표하는 동안:

- 슬라이드를 넘기면 고개를 든다
- 오래 말하면 한 마리가 꾸벅 존다 (지금 폴백 대사가 이미 *"쿨쿨…"* 이다)
- 목소리가 크면 귀가 쫑긋

**연습이 리허설이 된다.** 청중이 있어야 리허설이다. 그리고 이건 나중에 청중석에서 만날 그 병아리들이라 서사가 이어진다.

## 7. 그래서 앱 전체가 이렇게 된다

```
자료 올리기    🐤 병아리가 자료를 받아 든다
    ↓
발표 정보      🐤 "어떤 자리예요?" 라고 묻는다
    ↓
리허설         🐤🐤🐤🐤 넷이 객석에 앉아 듣는다
    ↓
분석 (7분)     🐤 → 🐤🐤 → 🐤🐤🐤🐤  한 마리씩 도착
    ↓
반응           🐤🐤🐤🐤 박수 → 그 다음 점수
    ↓
브리핑         [총평][믿:음][쏠라][엑사원][엑씨] 탭
    ↓
수다           객석 조명이 꺼지고 자기들끼리 떠든다
```

**하나의 은유가 처음부터 끝까지 관통한다.** 지금처럼 "대시보드 보다가 마지막에 병아리" 가 아니다.

## 우선순위 — 효과 대비 비용

| 순위 | 항목 | 비용 | 왜 |
|---|---|---|---|
| **1** | 병아리 얼굴 다시 그리기 | **낮음** | SVG 함수 하나. 모든 화면에 파급. 여기서 톤이 결정된다 |
| **2** | 대기 화면 = 병아리 도착 | 중간 | 죽은 7분이 최고 순간이 된다. 파급 최대 |
| **3** | 탭 = 병아리 브리핑 | 중간 | 이미 있는 구조를 드러내는 것. 새 데이터 0 |
| **4** | 카피 톤 (지적→호기심) | **낮음** | 문자열 교체. 감정 효과 큼 |
| **5** | 점수 = 박수 | 중간 | "와" 순간이 여기서 나온다 |
| **6** | 리허설에 관객 앉히기 | 중간 | 서사 완성. 없어도 나머지가 성립 |

**1 → 4 → 2 순서를 권한다.** 1·4는 반나절이면 되고 그것만으로 인상이 바뀐다. 그 다음 2번으로 가장 큰 구간을 잡는다.

## 캐릭터 시트 (1번 상세)

```
지금                          제안
──────────────────           ──────────────────
반쯤 감긴 눈 (.ch-lid)        또렷한 눈 + 하이라이트 점 2개
처진 눈썹                     눈썹 제거
2등신                         2.5등신
sway 3.2s (느릿)              sway 2.4s + 말할 때 통통
"몽총함"                      "다 알아듣고 살짝 짚어주는"
```

**눈썹을 빼는 게 핵심이다.** 눈썹이 있으면 인상이 생기고, 인상이 생기면 "멍청함"이나 "화남"으로 읽힌다. 눈만 남기면 순수해진다.

표정은 다섯 개면 충분하다: `기본 / 신남(∪ 눈) / 갸웃(8° 기울임) / 놀람(눈 확대) / 졸음(감은 눈)`.

## 색

판정 색 5종은 **건드리지 않는다.** 대신 분위기 층만 얹는다.

```css
--chick-yellow: #FFD76E;   /* 브랜드 보조색으로 승격 */
--warm-bg:      #FFFBF0;   /* 칭찬·성취 카드 */
--pop:          #FF8FA3;   /* 하트·박수 */
```

`aligned`(잘 설명함) 카드가 지금 파란 계열이라 "정보"로 읽힌다. `--warm-bg` 로 바꾸면 성취로 읽힌다.

## 하지 말아야 할 것

- **판정 색 5종을 귀엽게 바꾸지 마라.** 빨강이 빨강이어야 모순이 모순으로 읽힌다.
- **숫자를 장식하지 마라.** 점수·%·자/분은 또렷한 숫자로 둔다.
- **표를 없애지 마라.** 병아리는 표 **위에** 얹는다. 근거를 확인하고 싶은 사용자를 막으면 신뢰를 잃는다.
- **전체를 다크로 가지 마라.** 청중석만 어두운 게 "무대 밖으로 나간다"는 장치다.
- **병아리에게 판정을 맡기지 마라.** 코드가 사실을 고르고 LLM은 말투만 입힌다 — 이 원칙(`f12_chatter.py` 설계)을 UI에서도 깨면 안 된다.
- **애니메이션 3개 이상 동시 금지.** 새로 넣는 것도 전부 `prefers-reduced-motion` 뒤에 둔다.

## 열린 질문

- 탭을 병아리로 바꾸면 **처음 온 사용자가 뭘 눌러야 할지 알까?** → '총평' 탭을 기본으로 두고 나머지를 얼굴+한 단어로 라벨링하면 될 것 같지만, 실사용 확인이 필요하다.
- 박수 연출이 **두 번째 볼 때도 좋을까?** 스킵 가능해야 한다.
- 병아리 넷 이름(믿:음/쏠라/엑사원/엑씨)이 **모델명 그대로여도 되나?** 사용자에게는 모델명이 의미 없을 수 있다. 다만 "국내 LLM 4개가 심사한다"는 게 이 제품의 차별점이라 드러내는 게 맞다고 본다.
