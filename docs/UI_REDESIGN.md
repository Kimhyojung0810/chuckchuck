# 척척극장 — 발표 연습을 공연으로

## 0. 감정적 진실 (픽사가 제일 먼저 묻는 것)

> **혼자 하는 발표 연습은 빈 방에 대고 말하는 일이라 창피하고 외롭다.
> 사용자가 정말 원하는 건 점수가 아니라, 내 발표를 진심으로 들어준 누군가다.**

토이스토리가 "장난감이 움직인다"가 아니라 "잊히는 두려움"으로 만들어졌듯,
이 제품은 "AI가 발표를 분석한다"가 아니라 **"드디어 내 발표에 청중이 생겼다"** 로 만들어야 한다.

이 문장이 북극성이다. 아래 모든 결정은 여기서 연역된다:
- 병아리는 심사위원이 아니라 **처음 생긴 관객**이다
- 점수는 판결이 아니라 **박수**다
- 분석 대기는 로딩이 아니라 **객석의 웅성거림**이다
- 재방문은 세션이 아니라 **N회차 공연**이다

## 1. 세계관: 앱 전체가 하나의 극장이다 (디즈니의 Berm)

디즈니랜드는 파크 안에서 바깥세상이 절대 안 보이게 둔덕(berm)을 쌓는다.
지금 앱은 화면마다 세계가 다르다 — 대시보드였다가, 폼이었다가, 갑자기 극장.
**모든 화면을 한 극장 안의 장소로 다시 배치한다.**

```
홈          = 극장 앞     지난 공연 포스터가 붙은 벽 + 오늘 공연 입간판
자료 올리기   = 무대 뒤     무대감독 병아리에게 대본(PDF)을 건넨다
발표 정보    = 공연 안내판  "오늘의 공연: ○○ · 관객: 심사위원 · 15분"
리허설      = 무대 위     막이 오르고, 어두운 객석에 실루엣 넷
분석 대기    = 막간       막이 내려오고, 커튼 뒤에서 소곤소곤
결과        = 커튼콜      막이 다시 오르면 박수 → 그 다음 점수
브리핑      = 분장실 방문  병아리들이 한 마리씩 찾아와 얘기한다
질문 코치    = 무대 뒤 문   공연 끝나고 문 앞에서 기다리던 관객의 질문
```

이동이 내비게이션이 아니라 **동선**이 된다. "다음" 버튼이 아니라 "무대로", "객석으로".

> 구현 관점: 라우팅·데이터는 그대로다. 배경 톤과 전환 연출, 카피만 바뀐다.
> 지금 청중석만 어두운 게 이미 "무대 밖" 장치였다 — 그 문법을 앱 전체로 확장하는 것.

## 2. 신규 캐릭터: 무대감독 병아리 (디즈니의 Cast Member)

디즈니랜드에서 게스트를 안내하는 건 시설이 아니라 캐스트다.
지금 앱에는 안내자가 없다 — 폼과 버튼뿐이다.

**헤드셋을 끼고 클립보드를 든 조그만 병아리** 하나가 극장을 운영한다.
네 마리 평론가와 역할이 겹치지 않는다 — 걔들은 관객이고, 얘는 스태프다.

| 장면 | 무대감독이 하는 일 |
|---|---|
| 자료 올리기 | 대본을 받아 들고 팔랑팔랑 넘겨본다 (파싱 중) |
| 발표 정보 | "오늘 어떤 자리예요?" 하고 받아 적는다 |
| 리허설 직전 | "준비되셨어요? …큐!" (녹음 시작) |
| 커튼콜 | 줄을 당겨 막을 올린다 |
| **오류** | 헐레벌떡 달려와서 "죄송해요, 무대 장치가 말썽이에요!" + 그 아래 정확한 원인 |

**오류 화면이 제일 중요하다.** 지금은 빨간 글씨뿐인데, 무대 사고라는 프레임을 쓰면
귀여움과 정직함이 공존한다 — 사과는 병아리가 하고, 원인은 기술 문구 그대로 남긴다.

## 3. 막간(7분 대기) 재설계: 커튼 뒤의 소곤소곤

v1에서 "병아리가 한 마리씩 도착"으로 잡았는데, 한 단계 더 간다.
**걔들은 리허설 때 이미 객석에 있었다. 지금은 커튼 뒤에서 협의 중이다.**

화면: 내려온 커튼. 뒤에서 새어 나오는 웅성웅성 (흐릿한 말풍선이 떠올랐다 사라짐).
그리고 파이프라인 단계가 끝날 때마다 **또렷한 한 마디가 커튼 틈으로 새어 나온다:**

| 파이프라인 | 커튼 틈으로 들리는 소리 | 데이터 |
|---|---|---|
| STT 완료 | 엑씨: "3분 12초, 한마디도 안 놓쳤어" | `duration_sec` 실측 |
| F-06/07 완료 | 쏠라: "개념 20개 정리 끝!" | `nodes.length` 실측 |
| F-11 완료 | 믿:음: "어? 잠깐, 이거…" | 판정 완료 신호 |
| 점수 완료 | 넷이 동시에: "쉿—! 온다!" (커튼 들썩) | 커튼콜 직전 |

**전부 실제 완료 신호라 지어낸 연출이 아니다.** 이미 부모가 0.5초마다 보내는
`f11Progress` 메시지에 다 실려 있다 — 새 데이터 0.

기다림의 심리가 바뀐다: *"언제 끝나지"* → **"쟤들이 내 얘기를 하고 있다."**
진행률 바(정직한 %)는 하단에 얇게 유지한다. 토스의 규율: 숫자를 숨기지 않는다.

## 4. 커튼콜: 점수는 박수 뒤에 온다

막이 오른다. 병아리 넷이 **박수를 친다.** 그 다음에야 숫자가 조용히 뜬다.

```
90+    기립박수, 하트가 튀어오르고 한 마리는 눈물까지
75~89  넷 다 신나게 박수
60~74  박수 + 한 마리가 갸웃 (자기 담당 항목이 낮은 병아리)
~59    짝짝… 한 마리가 손 든다. "저, 질문 있어요!"
```

F-13 의 4개 항목이 병아리와 1:1 이라 **"누가 왜 이 점수를 줬는지"** 가 얼굴로 보인다:

| F-13 항목 | 담당 |
|---|---|
| 핵심 개념 설명 · 비중 일치 | 믿:음 |
| 개념 연결 · 흐름 순서 | 쏠라 |

두 번째 관람부터는 스킵 가능해야 한다 (지금 리빌의 「건너뛰기」 문법 재사용).

## 5. 탭 = 분장실 방문

리포트 탭이 이미 병아리 역할 분담과 정확히 같은 축이다 (`f12_chatter.py` 가 코드로 증명):

```
[ 총평 ]  [ 🐤 믿:음 ]  [ 🐤 쏠라 ]  [ 🐤 엑사원 ]  [ 🐤 엑씨 ]
           빠뜨린 거      흐름          잘한 거        들은 대로
```

각 탭은 그 병아리가 분장실로 찾아온 장면이다. **말풍선이 위, 표가 아래.**
감정으로 들어가서 정확한 데이터로 내려앉는다. 표는 절대 없애지 않는다 —
근거를 확인하려는 사용자를 막으면 신뢰를 잃는다.

## 6. 기억하는 객석 (픽사: 캐릭터는 변한다)

일회성 분석기를 **다니는 극장**으로 바꾸는 층. 리텐션이 여기서 나온다.

**공연 기록** — `localStorage` 에 회차별 요약을 남긴다:

```json
[{ "date": "2026-07-30", "run": 3, "score": 84,
   "missing": ["공동 임베딩 정렬"], "coverage": 0.78 }]
```

- **홈 = 포스터 벽.** 공연마다 포스터 한 장 (회차·점수·병아리 한 줄 평).
  첫 방문의 빈 벽에는 병아리들이 "첫 공연 준비 중!" 포스터를 붙이고 있다.
- **병아리가 기억한다.** 지난 회차의 missing 과 이번 aligned 를 diff 해서:
  믿:음 — *"지난번에 안 했던 '공동 임베딩 정렬', 오늘은 들었어요!!"*
  **데이터가 증명하는 것만 말한다** — diff 가 비면 이 대사는 안 나온다.
- **티켓.** 공연이 끝나면 티켓 반쪽이 나온다 — 날짜·회차·점수·병아리 도장 4개
  (그 회차의 mood 가 도장 표정이 된다). canvas 로 그려 이미지 저장/공유.

성장이 숫자(+10점)가 아니라 **목격**된다. "병아리가 알아챘다"가 "+10" 보다 세다.

## 7. 모션 스펙 — 디즈니 12원칙을 CSS 로

캐릭터는 생김새가 아니라 **움직임**이다. 애니메이션 원칙을 구현 스펙으로:

| 원칙 | 적용 | 스펙 |
|---|---|---|
| Anticipation | 말하기 전 살짝 움츠림 | `scale(.96)` 120ms → 발화 |
| Squash & Stretch | 폴짝 착지 | 착지 순간 `scale(1.06, .94)` 120ms |
| Follow-through | 고개 돌리면 몸이 늦게 따라옴 | 몸 transition-delay 40ms |
| Secondary action | 말할 때 꼬리깃 씰룩 | 별도 keyframe, 진폭 2px |
| Slow in/out | 모든 이동 | 기존 `--ease` 재사용 |
| **Staging** | **동시에 움직이는 병아리 최대 1마리** | 말하는 애만. 나머지는 idle |
| Exaggeration | 놀람은 20% 과장 | 단 0.4s 안에 복귀 |
| Appeal | 2.5등신 + 눈 하이라이트 | 캐릭터 시트 참조 |

전부 `prefers-reduced-motion` 뒤에 둔다. Staging 이 제일 중요하다 —
전부 움직이면 아무것도 안 보인다.

## 8. 캐릭터 시트 (v1에서 유지)

```
반쯤 감긴 눈 (.ch-lid)  →  또렷한 눈 + 흰 하이라이트 점 2개
처진 눈썹              →  제거. 눈썹이 있으면 인상이 생기고, 인상은 '멍청함'으로 읽힌다
2등신                  →  2.5등신
sway 3.2s              →  2.4s + 말할 때 통통
```

표정 5종: `기본 / 신남(∪눈) / 갸웃(8°+물음표) / 놀람(눈 확대) / 졸음(감은 눈)`.
`grumpy` 는 눈썹 대신 **∧ 눈 모양**으로 — 뾰로통이지 화남이 아니다.

## 9. 카피 원칙 (픽사의 want)

**병아리는 판정하지 않는다. 원한다.** 부족의 지적 → 더 듣고 싶다는 표현.

| 지금 (진단서) | 제안 (관객의 want) |
|---|---|
| "아직 설명하지 않았어요" | "그거 더 듣고 싶었는데!" |
| "자료와 다르게 말했어요" | "어? 자료엔 이렇게 적혀 있던데… 제가 잘못 봤나요?" |
| "판정 확신도 92%" | "이건 확실해요" / "음… 좀 애매했어요" |
| (모델 실패) | 빈 좌석에 명패 + "엑사원은 오늘 못 왔어요" |

규칙 셋:
1. `missing` 은 여전히 `missing`, 빨강은 여전히 빨강. **전달자만 바꾼다**
2. 병아리는 근거 있는 말만 한다 — 이미 코드가 강제한다 (`f12_chatter.py`: 목록 밖 node_id 대사는 버림). **UI 도 이 원칙을 깨면 안 된다**
3. 실패도 세계관 안에서 정직하게 — 빈 좌석은 숨기지 않고 귀엽게 보여준다

## 10. 토스의 규율 (귀여움이 침범하면 안 되는 것)

- **숫자는 신성하다.** 점수·%·자/분은 장식 없이 또렷하게. 박수는 숫자의 앞에 오지, 숫자를 대체하지 않는다
- **판정 색 5종 불변.** 빨강이 빨강이어야 모순이 모순으로 읽힌다
- **모든 연출은 스킵 가능.** 두 번째부터는 빨리 가고 싶은 게 정상이다
- **정직한 상태.** 진행률 %, 오류 원인, 샘플 데이터 표시 — 전부 유지. 병아리는 그 위에 얹는 층이지 가리는 층이 아니다
- **소리는 기본 무음.** 삐약·박수 소리는 옵트인

## 우선순위 — 3막 구성

| 막 | 내용 | 비용 | 비고 |
|---|---|---|---|
| **1막** | 얼굴 재설계 · 카피 톤 · 커튼 뒤 소곤소곤(대기) | **반나절~1일** | 승인된 v1 계획의 업그레이드. 대기 화면이 '도착'→'커튼 협의'로 바뀐 것 외에 동일 |
| **2막** | 극장 셸(무대감독·장면 전환·오류=무대사고) · 커튼콜 박수 · 탭=분장실 | 2~3일 | 여기까지 하면 "와" 가 나온다 |
| **3막** | 기억(포스터 벽·티켓·지난 공연 비교) · 리허설 실루엣 관객 | 2~3일 | 리텐션 층. 데모 이후 |

**1막부터.** v1 계획의 Task 1·2와 같고, Task 3(대기 화면)만 서사가 좋아졌다 — 비용은 비슷하다.

## 하지 말아야 할 것

- 판정 색·숫자·표를 건드리지 마라 (위 '토스의 규율')
- **병아리에게 판정을 맡기지 마라.** 코드가 사실을 고르고 LLM 은 말투만 — UI 도 동일
- 극장 은유를 **문구로 설명하지 마라.** "여기는 분장실입니다" 라고 쓰는 순간 죽는다. 배경과 동선으로만 말한다
- 동시에 움직이는 병아리는 1마리 (Staging)
- 기억 기능에서 **데이터가 증명 못 하는 회상 대사 금지** — "지난번보다 나아졌어요" 는 diff 가 있을 때만
