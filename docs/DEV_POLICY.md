# 척척발표 · 모델 개발 정책 (1-Pager)

> **모든 모델·기능 개발은 이 정책과 [`SCHEMA.md`](./SCHEMA.md) 규격에 맞춘다.**  
> SlideDoc / ConceptDoc 합의안: [`DOCUMENT_PARSE_POSTPROCESS.md`](./DOCUMENT_PARSE_POSTPROCESS.md).  
> cascade 파이프라인이므로 **모듈 분리**와 **입출력(API/SDK) 계약**이 전부다.  
> 새 모듈은 [`API_SDK_TEMPLATE.md`](./API_SDK_TEMPLATE.md) + [`templates/`](./templates/) 를 복사해서 시작한다.

---

## 1. 한 줄 원칙

**기능 모듈은 서로를 부르지 않는다. 정해진 입출력 양식(`ours`)으로만 주고받는다.**

서버가 순서를 정하고, 모듈은 자기 입력만 받아 자기 출력만 낸다.  
화면은 기능이 몇 개인지 몰라도 되고, 외부 AI를 바꿔도 해당 모듈 안쪽만 바뀐다.

## 4. 반드시 지킬 규칙

### 4-1. 모듈 독립

1. **모듈 간 직접 호출 금지.** A가 B를 import 하지 않는다. 서버(또는 파이프라인 오케스트레이터)만 순서를 안다.
2. **한 모듈 = 한 책임.** F-06은 개념 추출만, F-07은 트리만. 옆 단계 일을 끌어오지 않는다.
3. **담당자는 자기 모듈 + 자기 I/O 계약만 보면 된다.** 남의 구현을 열어볼 필요가 없어야 한다.

### 4-2. 입출력 계약 (API / SDK)

1. 모듈 간·프론트↔백엔드 교환은 `**ours` 타입만** 사용한다. (`to_dict()` / `from_dict()` 왕복)
2. 벤더 **raw는 어댑터 안에서만** 존재한다. (`f01_parse`, `stt_impl` 등) 밖으로 새기지 않는다.
3. 새 모듈을 만들 때 **먼저 I/O 스키마를 `SCHEMA.md` + `contracts.py`에 올린 뒤** 구현한다. 스키마 없는 코딩 금지.
4. 공통 단위: 시각 = **초(float)**, 슬라이드 번호 = **1부터**, 재방문 = 같은 `slide_no` + 다른 `visit`.
5. **모양은 템플릿을 따른다** — Python 공개 함수 1개, HTTP `POST /api/v1/{action}`, JS 키=Python `to_dict()` 동일. 자세한 규격·스켈레톤: `[API_SDK_TEMPLATE.md](./API_SDK_TEMPLATE.md)`

### 4-3. 외부 AI는 갈아끼우기


| 역할      | 현재                     | 정책                            |
| ------- | ---------------------- | ----------------------------- |
| 자료 → 글자 | Upstage Document Parse | **확정** (바꿀 때도 F-01 어댑터만)      |
| 음성 → 글자 | SKT A.X STT            | **교체 가능** — F-05 안쪽만 변경       |
| 글 읽고 판단 | Solar · A.X · 믿음 · 엑사원 | **동일 호출 방식** (`get_llm(...)`) |


벤더 교체는 어댑터·provider 레이어에서 끝내고, 상위 `ours` 스키마와 다른 모듈은 건드리지 않는다.

### 4-4. 화면·서버 경계

- 화면은 **서버 API / JS SDK**만 안다. 내부 모듈 단계 수·벤더 이름을 몰라도 동작해야 한다.
- 서버는 **저장 + 오케스트레이션 + API**만 담당한다. 기능 로직은 모듈에 둔다.

## 5. 새 모델 파트 착수 체크리스트

- F-ID와 책임이 한 문장으로 정의됐는가?
- 입력·출력 타입이 `contracts.py` / `SCHEMA.md`에 문서화됐는가?
- `[templates/](./templates/)` 기준으로 모듈·API·(필요 시) SDK를 만들었는가?
- 상위·하위 모듈을 **직접 호출하지 않는가?**
- 외부 AI raw가 어댑터 밖으로 새지 않는가?
- mock으로 파이프라인에 끼워 넣어 검증 가능한가?
- 벤더를 바꿔도 `ours` 출력이 동일한가?

## 6. 그래서 —

- STT를 바꿔도 **「받아쓰기」(F-05)** 안쪽만 바뀐다.
- 「개념 트리」(F-07) 담당자는 **남의 코드를 열어볼 필요가 없다.**
- 화면은 **기능이 몇 개인지 몰라도 된다.**

**모듈화 + 입출력 규격 = 척척발표 모델 개발의 전부.**
