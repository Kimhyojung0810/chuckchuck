# F-07 그래프 후처리 A/B (2026-09-29)

P5 최종 평가([final_report.md](final_report.md)) 문제 2를 다뤄요. 문제는 처음 보는 PPT에서 F-07 이 식·목록의 항목을 노드로 안 남기고, F-26 이 그래프 밖 말을 못 받는다는 것이었어요.

F-07 프롬프트를 고치면 위계가 흔들린 전례가 있어요(19b66ea 노드 links 칸). 그래서 **후처리만 바꾼 갈래**와 **프롬프트까지 바꾼 갈래**를 따로 쟀어요.

## 결론

**A+B+D(+주제 이름 풀기)를 넣고, C(프롬프트 예시 id 바꾸기)는 넣지 않았어요.**

- 후처리는 같은 LLM 응답에서 노드·주장·탐침을 늘렸어요. 위계 일치율은 떨어지지 않았어요.
  - 이번 표본: 0.57 → 0.61
  - P5 가 실제로 낸 성긴 그래프: 심은 주장 21 → 28, 심은 탐침 12 → 15
- C 는 주제를 루트로 두는 비율은 올렸지만 **위계 일치율을 0.61 → 0.43** 으로 떨어뜨렸어요. 그리고 새 예시 id(`detail`·`element`)를 403노드 중 46개가 그대로 따라 썼어요. 주제 쪽 이득은 코드(주제 이름 풀기)로 같은 만큼 얻었어요.

## 표 2 — P5 가 실제로 낸 그래프에 후처리만 (짝 비교, held-out+새 덱 9덱 합)

이번 표본은 운 좋게 노드가 많이 나왔어요 (건강 18~21노드). 그래서 항목 메우기가 할 일이 적었어요. **P5 최종 평가의 그래프**는 성겼어요 (건강 8노드, IR 에 「구독자 수」「유지율」 없음). 그래서 그 그래프를 그대로 base 로 두고, 같은 그래프에 새 후처리를 태운 것을 abd 로 비교했어요. 주장 LLM 은 P5 응답 저장소를 되쓰고, 그래프가 바뀐 덱만 새로 불렀어요(4콜).

| 지표 | base (P5 그대로) | **abd** |
|---|---|---|
| 노드 · 더한 노드 | 126 · 0 | 134 · 8 |
| LLM 주장 | 25 | **33** |
| 심은 주장 | 21 | **28** |
| 심은 탐침 | 12/22 | **15/22** |
| 탐침 정밀도 | 12/13 | **15/17** |

- **IR**: 「월 반복 매출 = 구독자 수 × 객단가 × 유지율」 의 좌변과 항 둘이 노드가 됐어요. 주장이 1 → 6 으로 늘었고 **긴장 T1 을 찾아요** (P5 문제 2(a)의 회귀 케이스).
- **건강**: 식 항 2개와 「세 가지 문제」 항목 3개가 「혈당 스파이크」 밑에 붙었어요. 심은 주장 2 → 5/7, **긴장 T1·미해결 U1 을 찾아요**.
- **수면(tuned)**: 원인 표 항목 4개가 「수면 연속성」 밑에 붙었어요. 미해결 탐침이 2개 새로 생겼어요.
  - 「스트레스」 미해결은 자료 그대로예요 (7장 해결 행은 카페인·음주·빛·소음만 다뤄요).
  - 「환경」 미해결은 틀렸어요 (빛·소음이 환경이에요).
  - 둘 다 심은 항목이 아니라서 정밀도에서 빠져요 (1/1 → 1/3).
- **새 덱**은 바뀌지 않았어요. 긴장 T1 은 그래프 문제가 아니에요 (아래 남은 문제 1).

## 무엇을 바꿨나

- **A. 식·목록 항목 메우기** (`chuckchuck/_graph_items.py` · `f07._add_items`)
  - 자료 줄에서 식을 읽어요: 「A = B × C」 이고, 글 상자로 쪼개진 조각을 이어요. 연산 기호 뒤에 끼어든 도식 캡션 물음 줄은 건너뛰어요.
  - 목록도 읽어요: 개수 말이나 문제 명사로 끝나는 제목 + 항목 줄이에요. 표면 첫 칸을 항목으로 보는데, 머리 행이 열 이름이면 빼요.
  - 식·목록을 믿는 조건:
    - 개수 말이 있으면 항목 수가 그와 같아야 해요.
    - 개수 말이 없으면 항목이 3개 이상이어야 해요.
    - 항목은 20자·4낱말 이하예요. 숫자·물음·문장·목적격 절은 항목이 아니에요.
  - **이미 노드인 항목은 더하지 않아요.** 같은 이름, 수식어만 다른 이름, 노드 이름+앞 수식어, 낱말 하나 더 붙은 이름은 이미 있는 것으로 봐요. 겹친 노드가 빠진 노드보다 해로워서예요.
  - 부모는 이 순서로 정해요:
    - 식이면 좌변 노드예요. 좌변 노드가 없으면 좌변도 노드로 더해 주제 밑에 둬요.
    - 목록이면 이미 노드인 항목들의 공통 부모 → 제목이 가리키는 노드 → 그 장 노드 중 제목·소개 줄에 이름이 나온 것 → 주제 순이에요.
  - id 는 이름을 로마자로 옮긴 slug 예요 (`gudokja-su`). 같은 이름이면 늘 같은 id 예요.
  - weight 는 같은 배합으로 매겨요. 정규화는 LLM 노드 기준이라 LLM 노드 서열은 안 바뀌어요.
  - 덱당 8개까지 더해요. 통째로 못 넣는 묶음은 건너뛰어요.
  - **연결 보강 호출 뒤에** 돌아요. 그래서 LLM 호출 수는 바뀌지 않아요.
- **B. 겹친 이름 합치기** (`dedupe_raw_nodes`)
  - raw 노드 단계에서 합쳐요. 조사 「의」와 띄어쓰기만 다른 이름이 대상이에요.
  - 양·방향 수식어(저하·부족)는 **떼지 않아요**. 「집중력」 밑의 「집중력 저하」 는 프롬프트 규칙 D 가 일부러 자식으로 두는 다른 개념이에요.
  - 반복 루프(같은 이름 98번)가 여기서 접혀요. 노드 상한은 80이에요.
- **주제 이름 풀기** (`f07._thesis_by_label`)
  - main 프롬프트 응답 20회 중 11회가 thesis 칸에 id 대신 **이름**을 적었어요 (「독서 경험」「실적발표」). 그래서 주제가 버려졌어요.
  - 이제 이름으로 노드를 찾아 루트 클램프가 주제를 지키게 했어요. C 가 프롬프트로 얻은 이득을 코드로 얻는 거예요.
- **D. F-26 `_resolve_id`**
  - id 칸의 이름을 규칙 추출과 같은 `resolve_label` 로 풀어요 (이름 포함 → 변별 낱말 절반 이상).
  - 4낱말이 넘는 문장은 안 받아요.
- **캐시**: 브리지 F-07 캐시 키에 `_graph_items`·`_claim_rules` 소스 해시를 더했어요 (7756058 과 같은 함정). 벤치 `STAGE_MODULES["graph"]` 도 같아요.

## 남은 문제

1. **새 덱 긴장 T1 은 F-26 줄 읽기 문제예요.**
   - `_claim_quote.slide_lines` 가 「독서 경험 = 대출 권수 × 머문 시간 ×」 뒤에 캡션 물음 줄 「얼마나 머물렀는가」 를 이어 붙여요. 그러면 식 인용이 물음 줄이 돼서 `question` 으로 버려져요.
   - 그래프 쪽 줄 읽기(`_graph_items.deck_lines`)는 이 줄을 건너뛰어요. 같은 규칙을 `_claim_quote` 에도 넣어야 해요 (이번 범위 밖).
2. **목록 항목이 해결 행의 주어로 잘못 잡혀요.** 수면 덱 「연속성 저하 | 카페인·음주·빛·소음 줄이기」 에서 `rule_solve_rows` 가 해결 칸 주어를 새 노드 「카페인」 으로 풀었어요. 그 결과 「환경」 이 미해결로 보여요. `_probes`/F-26 해결 표 쪽 일이에요.
3. **F-07 노드 수가 실행마다 크게 달라요.** 같은 개념 입력에서 건강 8(P5) vs 18~21(이번), SK 20 vs 41 이에요. 항목 메우기는 성긴 실행을 받쳐 줄 뿐이고, 흔들림 자체는 그대로예요.
4. **main 프롬프트는 예시 이름 「주제 개념」 을 노드 label 로 그대로 쓰기도 해요** (수익률격차 1회). C 로 고치면 위계가 흔들려서 이번에는 두었어요.
5. focus·SK 는 주장이 0~3개예요. 식·목록 모양이 없는 덱이라 A 가 할 일이 없어요. 그쪽은 F-26 LLM 후보가 받침 검사에서 버려지는 문제예요 (P5 문제 2(b)).
