## 1. 판정은 무엇을 근거로 하나 (`chuckchuck/f09_judge.py`)

**한 줄 요약: 판정의 채점 기준은 자료가 아니라 F-08 이 쓴 `answer_gist`(골자)예요.** 자료 본문은 프롬프트에 「대조 원본」 으로 실리지만, 골자와 자료가 어긋날 때 자료 편을 들게 하는 규칙도 코드도 없어요.

| 입력 | 어디서 | 쓰임 |
|---|---|---|
| 질문·개념·「함정 질문인가」·「이 질문을 던진 이유」 | `_build_user_prompt` (f09:353) | 프롬프트 맨 앞 |
| 개념 요약·위계 경로·이웃 요약 | `_concept_block` (f09:278) | 「옆 개념과의 관계」 대조 |
| 근거 장 **자료 본문** (anchor 장, 1200자 예산) | `_slide_block` (f09:308) | 「판정의 대조 원본 — 발표자가 말한 것이 아니다」 |
| 정합 근거·근거 장 발화 (rec 경로만) | f09:388-395 · `_speech_block` (f09:337) | 발표 때 한 말과 대조 |
| **기대하는 답의 골자** | f09:1458-1460 | 규칙 3: 「골자가 주어지면 **그것이 채점 기준이다**」 (f09:218-220) |
| 골자의 요소(`answer_gist_parts`) | `_gist_parts_block` (f09:435) | LLM 이 `covered_parts` 를 돌려주면 코드가 요소 미달 good 을 막음 (`_enforce_good` f09:520 → partial ≤79) |
| 누적 답·되묻기 단계(probe/focus/converge) | `_answer_block`·tier_brief (system 에 실음) | 되묻기 넓이 |

LLM 출력 뒤 코드가 등급을 뒤집는 가드 — 순서가 중요해요 (`_normalize` f09:657):
1. `_enforce_good` (f09:520): 요소 목록이 있는 질문에서 good 인데 요소 미달 → partial, 점수 ≤ 79.
2. `_enforce_trap` (f09:637): `question.trap` 이고 LLM 이 `premise_corrected=false` 를 주면 → **wrong, 점수 ≤ 35**, react 는 「질문의 전제부터 확인해 보세요 — 자료는 그렇게 말하지 않아요.」 `premise_corrected` 가 없거나 true 면 손대지 않아요.
3. 함정 동의가 아니면 `_enforce_on_topic` (f09:605): 답이 (질문+골자+개념 블록+자료 본문+발화)와 낱말이 하나도 안 겹치면 **무관 → wrong ≤ 35**, (질문+골자+개념)과만 안 겹치고 답이 내용 낱말 8개 이상이면 **질문벗어남 → partial ≤ 65**.
4. 통과: `qa_passed = verdict=="good" or score >= QA_PASS_SCORE(70)` (contracts:1413). 규칙 8(f09:233-239)이 「요지는 맞고 근거만 얕은 partial」 에 70~79 를 주라고 해서 **partial 도 통과**해요. 대화 종료는 `qa_mastered`(good 이거나 3라운드에서 70 이상).
5. 빈 답은 LLM 없이 unknown. 「모르겠어요」·포기 버튼·`looks_stuck` → `coach_stuck`(판정 아님, verdict unknown · score 0). 1차는 narrow(선택형 되물음), 2차 scaffold(빈칸, LLM 없음), 3차 explain.

**골자는 자료로만 쓰였나?** 프롬프트는 「자료 본문 줄에 있는 말로만 쓴다」 고 부탁하고(f08:246-257), 코드는 **숫자**(자료·발화·문헌에 없는 숫자면 버림, f08:2421-2429)와 발판 인용·목록 밖 인용만 걸러요. **낱말·주장 단위의 근거 검사는 없어요.** 그래서 숫자는 자료에 있지만 **다른 대상에 붙인 숫자**(기관 71%·개인 18% — 실제로는 상위 25%·하위 25%의 값)나 자료에 없는 서열(「연속성과 규칙성이 더 중요」)이 그대로 골자가 되고, 판정은 그 골자를 정답으로 채점해요. 아래 표에서 골자를 그대로 넣은 (a) 는 거짓 골자라도 good 80~85 를 받았어요.

## 4. 힌트는 어떻게 나가나 — 두 덱에서 c6a1fa1 이 지켜지나

사다리(`build_hint_ladder`, f08:2746, LLM 없음) = ① 위치 «자료 N장은 이렇게 말해요: «인용»» ② 방향(F-08 hint) ③ 범위(「1, 4, 8장을 같이 볼게요」) ④ 발판(골자 한 낱말 빈칸) ⑤ 접근(골자 앞 절반) ⑥ 판정 뒤 「아직 안 나온 것: …」. 「모르겠어요」 1차는 `coach_stuck` narrow — LLM 되물음이 선택형이면 그것, 아니면 `_narrow_followup`(f09:1193) 이 골자에서 낱말을 가려 「이 장이 말하는 건 'A' 쪽인가요, 'B' 쪽인가요?」 를 만들어요.

- **c6a1fa1 의 장 선택은 지켜져요.** 40문항 중 인용 장이 근거 장 밖인 경우 0건, 1장 설문 보기 같은 엉뚱한 줄도 없었어요.
- **그러나 줄 선택은 여전히 개념 이름을 따라가요.** 질문과 낱말이 하나도 안 겹치는 인용이 3건(수면 deck/10 #6, 수익률 rec/5 #1·#2), 제목만 보여 주는 인용이 여럿(수익률 5장 「격차를 만든 다섯 가지 행동 요인」). 원인: `best_quote`(`_evidence.py:247-257`)가 질문 낱말 중 **개념 이름·요약에 있는 낱말은 빼고**(`asked`) 세고, 이름이 통째로 든 줄에 +3 을 줘요. 그래서 「58%」 를 묻는데 같은 장의 «상위 2개가 전체의 58%» 가 아니라 제목 줄이, 「누운 시간과 회복 시간의 차이」 를 묻는데 «수면 시간보다 중요한 수면의 질» 이 이겨요 (점수 분해: `out/*/trace_*.json` 과 §5-4).
- **발판·접근 칸이 지어낸 골자를 그대로 흘려요.** 골자가 틀리면 ④⑤ 가 틀린 답을 힌트로 줘요(수면 #1 「특히 연속성과 ___ 회복 효과에 더 큰 영향」).
- **narrow 선택지가 뜻이 없어요.** e 탐침 6건 중 5건: '스트레스' vs '중요함', 'Chaput' vs '중요함', '발생했음' vs '타이밍', '늘릴수록' vs '차지해', '설명할' vs '투자자'. 인용문에는 둘 다 없고, 어느 쪽이 「이 장이 말하는 것」 인지 답이 안 서요. 나머지 1건(수면 #1)은 LLM 이 쓴 「…무엇인가요? **A인가요, B인가요?** (자료 1장)」 — 프롬프트의 자리 표시자를 그대로 베낀 문장이 선택형 검사를 통과했어요.
- **발화 인용(speech_quote)은 근거 장 첫 120자예요** (`_speech_quote` f08:2500). 「여러분 … 주무셨는지 떠올려 보셨으면」·「아 안녕하세요 오늘 주제는…」 처럼 인사말이 들어가고, explain 단계 해설 끝에 「발표에서는 «…» 라고 말했어요」 로 붙어요.

## 5. 문제 목록 (심각한 순)

### 치명

1. **함정 표시는 붙는데 함정 질문·함정 골자가 안 나와서, 모범답과 자료대로 한 정답이 오답 처리돼요.** 관찰: 루트(theme) 개념이 두 덱 모두 5분 트랙에서 매번(수면 3/3, 수익률 3/3 재생성) `trap=True` 였고, 질문 문장에 거짓 전제가 있는 경우는 0건. 골자를 그대로 넣은 답이 4/4 **wrong 35**, 수익률 #1 은 자료대로 쓴 정답(d)도 wrong 35. 사용자는 「질문의 전제부터 확인해 보세요 — 자료는 그렇게 말하지 않아요」 를 받는데 바로잡을 전제가 없어요.
   - 원인: 함정은 triage 가 고르고 `_pick_marks`(f08:1730)가 트랙 예산만큼 그대로 넘겨요. 질문 프롬프트는 「trap=true 면 어긋난 주장을 얹어라」(f08:261) 만 부탁하고 **골자 규칙에는 함정 이야기가 없어요**(f08:246-257) — 그래서 LLM 골자는 평범한 답이에요. 질문에 실제로 거짓 전제가 들었는지 확인하는 코드가 없고, 판정은 `trap` 만 보고 `premise_corrected=false` 면 wrong 으로 내려요(`_enforce_trap` f09:637-654).
   - 반대 방향도 있어요: 수익률 rec/10 #1 은 참인 전제(58%)에 폴백 골자 「질문의 전제가 자료와 달라요」(`_fallback_gist` f08:2038-2039)가 붙어 **모범답이 틀린 것을 가르쳐요.**
2. **골자가 자료에 없는 사실을 만들고, 판정은 그 골자를 정답으로 채점해요.** 예: 기관 71%·개인 18%(실제는 상위·하위 25%, 수익률 deck/10 #5 → good 85), 「연간 11.8회」 를 개인 평균에(#3), 「연속성과 규칙성이 더 중요」(수면 #1, rec #1 — 자료는 곱), 「카페인이 수면 후반 각성」(수면 rec/10 #3), 「외부 변수를 통제했다」(수익률 rec/10 #3), 「REM 은 빠른 안구 운동」·「실험적 관찰」·「곱해 회복 시간을 추정」. 제 대조로는 40문항 중 20건 남짓의 골자에 자료 밖 주장이나 잘못 옮긴 내용이 섞였어요(수면 쪽이 더 많음).
   - 원인: 골자 근거 검사가 **숫자만** 봐요(f08:2421-2429 `ungrounded_numbers`). 숫자가 자료 어딘가에 있으면 대상이 틀려도 통과. 판정은 규칙 3(f09:218)으로 골자를 채점 기준으로 삼고, 자료 본문과 골자가 어긋날 때의 규칙이 없어요.
3. **그럴듯한 오답이 통과해요 (c 탐침 6건 중 3건 통과).** 수면 #3(6장과 정반대) partial 75, 수익률 #2(요인 크기 뒤바꿈) partial 75, 수익률 #3(3장과 정반대) partial 70 — react 가 틀린 주장을 「정확해요/맞아요」 라고 짚어요.
   - 원인: 규칙 8(f09:233-239)이 「요지는 맞고 근거만 얕은 partial」 에 70~79 를 주고, `qa_passed` 가 70 이상 partial 을 통과로 쳐요(contracts:1413). 모순 여부를 코드가 보는 가드가 없어요 — 무관 가드(f09:605)는 낱말이 **겹치면** 통과라서 같은 주제의 오답은 못 잡아요.

### 높음

4. **질문이 자료로 답할 수 없는 것을 물어요 (거짓 전제·과녁 밖).** 「어떻게 측정/계산/정량화했나요」(수면 deck #2, deck/10 #2·#6·#7), 「가장 큰 영향은?」(자료에 서열 없음), 인용하지 않은 논문 「Chaput et al. (2020)에서 어떻게 설명했나요」(수면 규칙성 — 3/3 재생성 모두). 자료만 올린 경로의 weak 자리는 약점 근거가 없어 **항상 「맞는 개념 없음→순위」** 로 채워지고(`_slot_fits` f08:1678), 그 자리에 문헌이 붙으면 논문 질문이 돼요(`_plan_papers` f08:1915, `QA_TRACK_CITES["5"]=1`).
5. **관련 없는 논문이 질문·골자·채점 기준에 섞여요.** 수익률 덱에 F-24 가 「The Top 1 Percent in International and Historical Perspective」(소득 불평등)를 붙였고, 인용 검사가 논문 절을 떼거나 문장을 버리면서(`_verify_paper_claims` f08:1050-1121 로그 「초록에 없음 … 논문 절만 뗌 / 템플릿으로」) **틀(「구조적 요인 외에」)과 골자·요소(「노동 시장 협상 모델」)는 남았어요.** 판정은 그 요소를 빠진 점으로 요구했어요(수익률 #3 d partial 75).
6. **힌트 인용 줄이 질문이 아니라 개념 이름을 따라가요** (§4, `_evidence.py:247-257`). 장은 맞게 고르지만 줄은 제목·표지 부제가 이겨요.
7. **「모르겠어요」 되물음 선택지가 뜻이 없어요** (§4). `mask_gist`(`_evidence.py:318-341`)가 「가장 긴 낱말」 을 가리고 이웃 요약에서 「가장 긴 낱말」 을 오답으로 뽑아 '중요함'·'차지해'·'설명할' 같은 활용형이 나와요. 프롬프트 예시 「A인가요, B인가요?」(f09:1013)가 그대로 나온 것도 `_CHOICE_FORM_RE`(f09:1169)가 통과시켜요.

### 보통

8. **폴백 문장이 화면에 그대로 나가요.** `_fallback_text`(f08:1999)가 triage angle 을 「{개념}: {angle} — 설명해 주세요.」 로 붙여 「…어떻게 되는지 — 설명해 주세요」·「…근거는 무엇인가? — 설명해 주세요」(해라체) 가 됐어요(수익률 deck/10 #6, rec/10 #5, 재생성 1회 더). 폴백 골자는 개념 요약+「(1, 2, 3장 근거)」 라 **답이 아닌데**, 그 문장을 말하면 good 85(수익률 deck/10 #7). 실험대 `check` 는 폴백 1/7 을 PASS 로 봐요.
9. **함정 동의 답이 무관 가드로 떨어지기도 해요** — 수익률 rec #1 (t): LLM 이 `premise_corrected` 를 안 줘서 함정 가드를 건너뛰고 무관 문구(「질문과 다른 이야기예요」)가 나갔어요 (f09:703-708 순서).
10. **해요체·높임 누수.** rec/10 힌트가 「생각해 보라」·「참고하라」(해라체, 수익률 7건 중 6건), 골자 끝 「…근거로 한다」·「…미친다」. react 「추정하신」·「정량화하신」·「찾고 계신」, followup 「설명해 주실 수 있나요」 — `_HONORIFIC_RE`(f09:77)가 「하신·계신·주실」 을 못 잡고, `to_haeyo` 는 합쇼체만 풀어요.
11. **자료만 경로의 주제 질문이 되읊기예요.** deck 경로 루트 질문 8건(기준선 4 + 재생성 4)이 모두 「…근거는 무엇인가요? / 어떤 데이터로 뒷받침되나요?」 꼴 — 프롬프트 3-5(f08:283-287)는 조건·경계·반례를 물으라 했지만 지켜지지 않았어요. rec 경로는 조건·표본을 묻는 질문도 나왔어요. 자기모순 표식(`_self_undercut`)은 이번엔 0건(괄호 나열 꼴이 안 나옴).
12. **발화 인용이 인사말이에요** (`_speech_quote` f08:2500) — 근거 장 발화의 앞 120자.
