# #/qa 대화 내용 감사 — 코치와 발표자가 실제로 주고받은 말을 턴마다 봤어요 (2026-09-29~30)

- **목적**: 지금까지의 실험은 흐름이 `#/qa` 에 닿는지만 봤다. 이번에는 질문 코칭 **안에서 오가는 말**이 맞는지·앞뒤가 맞는지·사람이 따라갈 수 있는지를 봤다.
- **방법**: `labs/qa_convo/run.py` 가 실 API 브리지(8799, main `27e4517`~`aadf68f`, `DEMO_DEV_ROUTES=1`)에서 진짜 화면을 헤드리스 크로미움으로 띄운다 —
  `#/test/QA` → 덱 → 자료만/녹음까지 → 시간(5·10분) → `#/qa` → 질문마다 정해 둔 페르소나대로 답칸에 치고 버튼을 누른다.
  동작마다 새 말풍선 전문·판정 요청/응답 JSON·사진·지연을 남긴다.
- **답**: 덱 본문을 읽고 입말로 따로 썼다 (`labs/qa_convo/answers/`). 정답은 골자가 아니라 **자료** 기준이다.
- 코드는 고치지 않았다.

## 한 줄 결론

흐름은 끝까지 돌지만, **코치가 하는 말의 절반 가까이가 틀리거나 어긋난다.** 원인은 셋이다.
① 질문과 함께 온 골자가 자료와 다르면 판정 전체가 그 골자를 정답으로 삼는다.
② 코드 가드가 맞는 답을 틀렸다고 내려서 3라운드를 넘어도 못 닫히는 질문이 생긴다.
③ 반대로 무관한 답·한 단어가 통과선(70)을 넘는다.

### 1. [치명·근거] 자료와 반대인 골자가 판정 기준이 되고 정답으로 뜬다 — 3질문·9세션

- **focus Q7** — 골자 「폰이 **가까울수록** 인지 과제 수행이 좋아지는 경향」, 자료 6장은 「**멀어질수록** 좋아지는 경향」.
  자료대로 답한 P3 2턴(「…멀어질수록 … 좋아지는 경향… Ward 2017」)이 **wrong 0**. react 는 사용자 말을 거꾸로 읽었고, 결손 칩 「Ward 연구 언급」은 방금 말한 것이다.
  3턴 60점 「방향이 거꾸로」 아래 「이렇게 말하면 완성이에요 — 폰이 가까울수록 …」 이 뜬다 ([사진](img/focus_q7_inverted_gist.png)). 「답 보기」도 틀린 문장을 모범답으로 보인다.
- **수면 Q2** — 골자 「카페인과 음주는 수면 후반 각성을 유발」, 자료 5장은 음주만 후반 각성(카페인은 오후·저녁 섭취). 질문의 「가장 큰 영향」 도 자료에 순위가 없다.
  「순위를 매기지 않았다」 는 정답에 70/75, 이어 「카페인·음주가 빛·소음보다 더 큰 영향」 비교를 요구해 루프. 틀린 총평이 결과 화면에 「자기 말로 방어한 것」 으로 저장된다.
- **수익률 Q6** — 골자가 질문이 묻는 변수와 다르고, 결손 칩 「비용(적립식·매도규칙)」 도 틀리다.
- **원인**: F-08 이 골자를 자료와 대조하지 않는다 · `f09_judge._ground_gist` 의 `support` 가 반의어(가깝다/멀다)를 못 잡는다 · 화면(`qa_live.js` `revealHalf`·`finishLiveQuestion`·`revealLiveAnswer`)은 근거 여부와 상관없이 `q.answer_gist` 를 띄운다.
- **고칠 방향**: (a) F-08 골자에 `_deck_claims.conflicts` + 반의어 쌍 검사, 어긋나면 다시 만들거나 근거 장 인용으로. (b) F-09 가 `gist_grounded` 를 응답에 싣고, 거짓이면 프론트가 `evidence_quote` 를 보인다. (c) `why` 에 「자료에 명시되지 않아」 라 적힌 질문은 기대답을 「자료에 없다고 말하고 자료 범위 안에서 답하기」로.

### 2. [치명·일관성] 코드 가드가 맞는 답을 강등한다 — 12턴, 2질문은 못 닫힘

### 3. [치명·일관성] 무관한 답·한 단어가 통과하고, 말하지 않은 것을 칭찬한다 — 10턴

- 녹음 Q3 「주말엔 보통 친구들이랑 놀러 나가요」 → 75(passed), react 「…리듬 회복은 불완전하다는 점은 맞아요」 ([사진](img/sleep_audio_q3_offtopic_75.png)) — 「주말」 한 낱말이 무관 가드를 비켜 갔다.
- 한 단어·칩 답: 「규칙」 → good 80 닫힘, 칩 「항목」 → good 85 닫힘, 「타이밍」·「연속성」 → 75. 절반 답 「회전율이 높을수록 수익률이 낮아졌어요」 → good 85.
- 말하지 않은 것 칭찬: 「참는 걸로는 안 되니까요」에 「폰이 가까울수록 인지 자원이 사용된다는 점은 맞아요」.
- 원인: `_enforce_on_topic` 은 한 낱말만 겹쳐도 넘어가고 8토큰 미만 답은 검사를 건너뛴다 · 칩 답이 원래 질문의 답으로 채점된다(`qa_live.submitLiveAnswer`).
- 고칠 방향: 칩 답은 「되물음에 대한 답」 으로 보내고 맞아도 원래 질문은 69까지 · 내용 낱말 3개 미만 답은 65 상한 · react 의 「…은 맞아요」 대상이 누적 답과 겹치지 않으면 폴백 문구.

### 4. [높음·관련성] 자료에 없는 것을 결손으로 요구한다 — 약 25턴

「높은 온도를 낮추는 구체적인 실천 방안」, 「측정 방법(예: 실험 절차…)」 — 둘 다 자료에 없다. 수면 Q7 은 1턴 「명상」에 「질문과 다른 이야기예요」라고 해 놓고 3턴에 「(예: 명상, 호흡법…)이 빠져 있어」. focus Q4 정직한 답 「측정 방법까지는 발표에 안 넣었어요」 → wrong 0, react 는 직전 턴 답을 채점, 총평은 「(예: S4, S7, S8의 실험적 접근)」 으로 지어냄.

### 5. [높음·일관성] 이미 말한 것을 또 빠졌다고 하고, 닫으면서 결손을 단다 — 반복 6, 닫힘+결손 11

### 6. [높음·관련성] 되물음 문장이 깨진다 — 26턴

원인: `f09._followup` 이 `points[0]` 을 템플릿에 넣는데 그게 가드가 앞에 끼운 사유 문자열이다. 고칠 방향: 가드 사유는 `guard_reason` 으로 분리 · 결손 문장은 명사구로 · 틀린 답에 결손이 없으면 근거 장을 가리키는 되물음.

### 7. [높음·근거] 함정에서 정답을 흘리고, 결손·총평에 틀린 사실을 적는다 — 누설 9, 틀린 사실 11
