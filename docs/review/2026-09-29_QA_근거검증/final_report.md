## 한 줄 결론

**주장→탐침 단계는 더는 헛것을 만들지 않아요.** held-out 기준으로 탐침 정밀도가 33%→100%, 템플릿 폴백이 69%→9%, 함정 골자 오류가 100%→0%로 바뀌었어요. 그런데 이번에 **판정이 탐침 질문을 거꾸로 채점하는 새 버그**가 나왔어요. 단정에 반박하는 모범답은 60점을 받고, 단정에 동의하는 오답은 85점을 받아요. 그리고 **처음 보는 PPT에서는 그래프(F-07)가 요소 개념을 노드로 안 남겨** 긴장·미해결 탐침을 못 찾아요(새 덱에서 둘 다 놓침).

## 어떻게 작동하나 (코드 기준)

**질문 근거.** 근거는 주장 그래프에서 시작해요.

1. `f26_claims.build_claims`(:780)가 두 가지 후보를 모아요: 규칙 추출(`rule_claims` — 식·목록·비교·단정·해결 표·인과 줄)과 LLM 1콜(`_ask`)이에요.
2. 후보마다 `_check`(:611)가 거쳐요.
   - id 를 풀어요(`_resolve_id`, :504).
   - `locate_quote`로 인용이 **한 줄**(또는 줄바꿈으로 이어진 두 줄)에 있는지 찾아요.
   - 물음 줄은 버려요.
   - `_supported`(:552)가 그 줄이 주장을 받치는지 kind 별로 봐요 (2af88a6). absolute 는 부정되지 않은 단정 표지가 있어야 하고 제목 줄이면 안 돼요. compose 는 식의 좌변·우변이나 목록 머리+항목이 있어야 해요. compare 는 「보다」 같은 비교 표지, cause/solve 는 인과·해결 말투가 있어야 해요.
   - 적힌 kind 로 안 받쳐지면 `_reread`(:599)가 줄의 말투로 kind 를 다시 정해요.
3. `_probes.derive_probes`(:365)가 이 주장들로 **결정적으로** 탐침 5종을 만들어요: 긴장 `_tension`, 미해결 `_unsolved`, 근거 없는 인과 `_unsupported_cause`, 단정 `_absolute_boundary`, 형제 우선순위 `_sibling_priority`.
4. `f08_questions.triage_questions`(:1567)가 탐침을 1차 심사 후보에 올리고, `build_questions`(:3238)가 트랙 자리(theme·part·weak, `_pick_marks` :1832, `_theme_pick` :1782)를 채워요. 탐침과 자리의 source 가 같으면 그 탐침을 질문에 묶어요(:3332).
5. `_normalize_questions`(:2872)가 LLM 문장을 점검해요.
   - 탐침 개념 이름을 안 부르면 `probe_question` 템플릿으로 바꿔요(`probe_template`, :3013–3035).
   - `_grounding` 검사가 걸러요: 문헌 잔여물(`paper_residue`), 자료 밖 숫자, 자료가 안 받치는 방법 질문(`asks_method`·`method_supported`), 골자의 숫자 오배치·근거 없는 비교·표 칸 오귀속(`gist_problems`). 걸리면 그 칸을 비우거나 질문을 버리고, 골자는 자료 줄로 다시 써요(`_evidence_gist` :2806).
   - 통과·실패 이력은 모두 `basis.checks` 에 남아요.
6. 함정은 `_assign_traps`(:1872)가 트랙 허용치(`QA_TRACK_TRAPS` 5분 1개 · 10분 3개, contracts:1351) 안에서 **자료 줄로 코드가 만들어요** (`_traps.candidates` :524). 방법은 숫자·순서·방향·부정 바꾸기와 표 극값이에요. `verify`(:563)가 전제가 어느 자료 줄과도 같지 않은지 확인해요. 골자·why·힌트는 `trap_gist/why/hint` 로 고정돼요 (bc4e72f).

**힌트.** 인용 줄은 이 순서로 정해요(:3050–3057): 탐침 질문이면 탐침 근거 줄, 함정이면 사실 줄, 나머지는 `_evidence.ranked_quotes`(:247)예요. `ranked_quotes` 는 질문 틀 낱말을 뺀 **질문 낱말과 겹치는 정도**를 개념 이름 겹침보다 먼저 봐요(c6a1fa1). 그리고 최종 질문 문장이 정해진 **뒤에** 골라서 템플릿·폴백 질문에도 맞아요.

`build_hint_ladder`(:3497)는 LLM 없이 사다리를 만들어요:
1. 위치 「자료 N장은 이렇게 말해요: «인용»」
2. 방향 (F-08 hint)
3. 범위 (장 번호 3개까지)
4. 발판 (`mask_gist` 로 골자의 명사 하나를 빈칸으로 — **인용에 나오는 낱말을 먼저 가려요**, b73a18c)
5. 골자 앞 절반
6. 판정 뒤에 빠진 점

함정 질문은 사실 줄을 먼저 보여 주지 않도록 방향 → 범위 → 위치 순서로 바꿔요(:3526). 「모르겠어요」 는 `f09.coach_stuck` 으로 가요: 1차는 narrow, 2차는 scaffold, 3차는 explain 이에요. narrow 의 LLM 선택지는 `_llm_choice_ok`(:1403)를 통과해야 쓰고, 조건은 모양, 24자 이하, 높임 없음, 선택지 낱말이 **모두 자료에** 있을 것(`_in_deck` :1393)이에요. 안 되면 `mask_gist` 정답과 오답으로 「'A' 쪽인가요, 'B' 쪽인가요?」 를 만들어요.

**판정.** `f09_judge.judge_answer`(:1576)는 5d1fbf5 이후로 **자료를 채점 원본**으로 써요.
- `_ground_gist`(:1761)가 골자를 `_deck_claims.support`(:635)로 대조해요. 받쳐지면 「채점 기준」, 아니면 「참고만 — 자료와 다르면 자료가 맞다」 로 실어요.
- `_deck_line_block`(:1779)이 답의 절마다 가장 가까운 자료 줄을 붙여요.
- LLM 판정 뒤 `_normalize`(:812)가 코드 가드를 이 순서로 걸어요:
  1. `_enforce_good`: 요소 미달이면 good 을 partial 로 내려요.
  2. `_enforce_trap`(:769): `_traps.premise_stance`(:701)가 정답 단서와 반박 표지로 전제 동의를 가려요. 동의면 wrong 이에요.
  3. 동의가 아니면 `_enforce_deck`(:786): `_deck_claims.conflicts`(:557)가 숫자·표 서열·방향·부정이 **자료 줄과 어긋나면** partial ≤ 상한으로 내려요.
  4. 어긋남이 없으면 `_enforce_on_topic`: 무관하면 wrong, 질문을 벗어나면 partial 이에요.
  5. 자기 반박(`opposes`)도 잡아요.
- 높임이 새면 `_haeyo_data` → `_HONORIFIC_RE`(:117)가 react 를 고정 문구로 바꾸고 되물음을 버려요.

### 1. [치명] 판정 가드가 탐침이 **반박하라고 한 자료 줄**을 정답으로 삼는다

### 2. [치명] 처음 보는 PPT에서 주장이 대부분 버려진다 — 그래프가 요소 개념을 노드로 안 남기고, F-26 은 그래프 밖 말을 못 받는다

held-out 주장 20개에 버린 후보 98개예요 (전: 82개 남음). 버린 까닭은 `objects` 70, `support` 65, `quote` 13 이에요.

- 심은 주장 재현율이 67%에서 52%로 떨어졌어요.

원인은 둘이에요.

(a) F-07 이 식·목록의 항목을 노드로 남기지 않아요.
- IR 새 그래프에는 「월 반복 매출」「구독자 수」 가 없어요 (전 그래프에는 있었어요).
- 새 덱 그래프에는 「대출 권수」 가 없고 「대출 권수 감소」 만 있어요.

- 노드 id 도 `encoder-6`·`joint` 처럼 F-07 프롬프트 예시 id(chuckchuck/f07_graph.py:121–129)를 그대로 따라 해서, F-26 LLM 이 id 대신 라벨을 적어요.

(b) `_resolve_id` (chuckchuck/f26_claims.py:504)는 라벨이 **통째로 같을 때만** 받아요.
- 실험: 같은 LLM 응답에 `resolve_label` 퍼지 대조를 더하면 held-out 주장이 20개에서 23개로 늘어나는 데 그쳐요 (LLM 0콜 재현).

**제안**:
- `rule_compose`/`rule_list_compose` 가 식·목록 항목 중 **그래프에 없는 말**을 만나면, 그 장의 가장 가까운 노드 아래에 「구절 노드」 로 붙여 주장을 남겨요 (F-26 이 그래프를 보강). 또는 F-07 프롬프트에 「식의 항·목록 항목은 각각 노드」 규칙을 넣어요.
- F-07 예시 id 를 의미 있는 slug(「topic」「part-a」)로 바꿔요.
- `_resolve_id` 는 `resolve_label` 로 폴백해요.
- 새 덱 T1, IR T1 을 회귀 케이스로 삼아요.

### 3. [높음] 코드가 만든 함정이 자동 검사는 모두 통과하지만 3개 중 1개는 그대로 못 쓴다

자동 검사(전제 거짓, 사실=자료, 질문이 전제를 실음)는 37/37 모두 통과했어요. 사람이 보면 **23/37 (62%)** 만 그대로 쓸 만해요 (held-out 18/26 · 새 덱 1/4 · tuned 4/7). 유형별로 보면:

- **순서 바꾸기** `_order_from_line` (chuckchuck/_traps.py:398): 문장 꼴에서 `_FIRST_TOKEN_RE`·`_THAN_TOKEN_RE` 의 **낱말 하나**를 바꿔요.
  - 결과: 「권수 대출보다」「시간은 화면을 본 손실보다」
  - 제안: `grounding.label_spans` 로 **개념 이름 구간**끼리만 바꾸고, 구간이 없으면 만들지 않아요.
- **표 극값** `_extreme_from_table` (:365–384): 헤더 표시가 없으면 `col=""` 로 「값이 가장 큰 것은 2025」 가 나와요.
  - 제안: 열 이름이 없거나 행 머리가 연도·숫자면 만들지 않아요.
- **숫자 바꾸기** `NUMBER_FACTORS = (2.0, 0.5, 3.0, 1.5)` (:50): 거의 늘 ×2 예요.
  - 결과: 광주기 16→32시간(하루 넘음), 29→58세, 180→360.
  - 제안: 단위별 상한(시간/일 24, 나이 등)을 두고, 인수를 줄마다 바꿔요.
- **LLM 문장 받기** (f08 :2999–3012, `question_carries` :667): 전제만 실으면 LLM 문장을 받아요. 그래서 전제 뒤에 **딴 질문**을 붙이거나(SK 3건·정책·수익률), 「이 주장은 **자료와 어떻게 다른가요**?」 처럼 함정을 드러내도 통과해요.
  - 제안: LLM 문장에 전제 밖 숫자나 「자료와 (어떻게) 다른」 이 있으면 `trap_question` 템플릿으로 가요.

### 4. [높음] `sibling_priority` 가 자료에 없는 우선순위를 강요한다

전체 탐침 25개 중 7개가 이 종류예요. 예: 「정보 비대칭과 신축 빌라 중…」, 「수면 주기와 시간 부족 가운데…」, 과학 대조군의 「잎 면적과 생체중」. 골자가 우선순위를 지어내거나(정책·수면), 「둘 다 동등」 을 말하는 모범답이 partial 65 를 받아요(과학). `_joint`(chuckchuck/_probes.py:299)의 「둘 다 필요」 검사가 식(곱)은 못 봐요.

**제안**: `_sibling_priority` (:306)는 형제가 **곱·합 식의 항**이면 만들지 않아요. 5분 트랙에서는 weak 자리에 올리지 않고, 골자는 「자료는 우선순위를 두지 않아요 — …」 로 고정해요.

### 5. [중간] 골자·힌트 글이 아직 화면에 그대로 못 나간다

- 골자 110개 중 16개가 해요체가 아니에요 (인문 덱 「…확산을 촉진했다」「…기여했다」). 포기하면 「정답 요지」 로 나가요.

- SK하이닉스 골자·힌트에 Upstage 영문 차트 설명(「A red line connects…」)이 그대로 들어가요 (`_evidence_gist` chuckchuck/f08_questions.py:2806, `_LONG_LATIN_RE` chuckchuck/_evidence.py:32 — 전 보고 9번이 그대로 남았어요).
  - 제안: 한글 비율 30% 미만인 줄은 인용·골자 후보에서 빼요.
- 「모르겠어요」 선택지 10개 중 2개가 용언 줄기(「떨어지」「보이지」)이고, SK 는 제목 줄 «SK hynix 재무실적» 을 인용하고 선택을 물어요.
  - 제안: `mask_gist` 의 `_noun_like` 에 「…지/하/되」 줄기 거절을 더하고, 인용이 제목 줄이면 같은 장의 본문 줄로 바꿔요.

### 6. [중간] 함정 질문의 「모르겠어요」 가 사실 줄을 바로 보여 준다

사다리는 함정이면 사실 줄을 3칸째로 미뤄요(f08 :3526). 그런데 `coach_stuck` narrow 는 `_with_quote` (chuckchuck/f09_judge.py:1326)와 선택형 문장(:1446)에서 `evidence_quote`(= `tp.fact`)를 **1차에** 보여 줘요. 그래서 함정이 첫 「모르겠어요」 에서 바로 풀려요.

**제안**: `question.trap_premise` 가 있으면 narrow 에서 인용을 빼고, 선택지를 「전제 값 vs 사실 값」 으로 만들어요.

### 7. [중간] 해결책 줄이 「근거 없는 인과」 로 읽힌다

새 덱 「자유열람실 확충 — … 좌석을 40석 늘립니다.」 가 cause(has_support=False)로 남아 5분 트랙 weak 질문이 됐어요. 게다가 `method_unsupported` 가 검사에 찍혔는데도 템플릿 질문으로 살아남았고, 골자는 「…40석 늘리는 것으로 산출되었어요」(지어낸 방법)예요.

**제안**:
- `_reread`(chuckchuck/f26_claims.py:599)와 `rule_cause`(:406)는 「— 」 앞에 해결책 이름이 있거나 SOLVE 말투(늘립니다·줄입니다·확충)인 줄을 cause 로 받지 않아요.
- `method_unsupported` 가 찍힌 탐침 질문은 템플릿으로 살리지 말고 버려요.

### 8. [낮음] 그럴듯한 오답이 여전히 70~85 로 통과한다 (held-out 4/15)

4건 중 2건은 문제 1(뒤집힘)이에요. 나머지는 과학 sibling_priority(문제 4)와 SK 하나인데, SK 쪽은 하네스 답안 LLM 이 함정 질문에 **맞는 답**을 「오답」 으로 써 온 것이라 판정 잘못이 아니에요. 통과선 `QA_PASS_SCORE = 70` (chuckchuck/contracts.py:1399)은 그대로 둬도 돼요. 1·4를 고치면 대부분 사라질 거예요.

### 9. [낮음] 탐침 개념 이름이 자료 낱말이 아니면 템플릿으로 떨어진다

새 덱 탐침 질문의 템플릿 폴백이 100% (67%)예요. 탐침 개념 이름이 근거 인용 속 낱말인 비율은 40% 뿐이에요 (예: 「방문 감소」 vs 자료 「방문이 줄었습니다」). held-out 은 9% 로 낮아졌지만, 템플릿은 인용 원문을 통째로 싣는 꼴이라 되읊기(16자 이상)가 10분 트랙에서 16~43% 예요.

**제안**: `_probe_mentions`(f08 :2729)가 노드 요약·자료 구절 별칭을 받게 해요.

### (그 밖에 코드를 읽다 본 것)

- `f09._HONORIFIC_RE`(:117)의 `께\s` 가 「함께 」 를 잡아서, 좋은 react 가 고정 문구로 바뀌어요.
- `_assign_traps` 가 밀어낸 질문의 slot 이름을 함정에 넘겨요(f08 :1940). 그래서 basis.slot 이 실제와 달라요.
- `premise_in_question`·`premise_drop_reason`·`strip_paper_sentences`(`_grounding`)는 이제 안 쓰는 코드예요.
