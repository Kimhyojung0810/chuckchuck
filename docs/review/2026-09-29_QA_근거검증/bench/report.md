## 문제 — 심각한 순서

### 1. [치명] 주장 인용이 주장을 받치는지 검사하지 않는다 → 가짜 `absolute`·`compose`·`compare` 가 탐침이 된다

`f26_claims._check` (chuckchuck/f26_claims.py:408-445) 는 kind·id·인용 존재만 봐요. 인용 안에 **주어·목적어 개념이 나오는지**, `absolute` 인용에 **단정 표지가 있는지**는 안 봐요.

- IR 3장의 물음 줄 「몇 명이 구독하는가」「한 번에 얼마를 내는가」「다음 달에도 남는가」, 1장 부제 「시드 라운드 투자 제안 | 2026.09」, 7장 유보 문장 「…결정하는 경향이 있습니다」 가 전부 `absolute` → 탐침 6개 → 질문 「구독자 수가 실제와 다를 수 있는 경우는 무엇인가요?」「객단가 단정이 실제 결제 구조와 맞지 않을 수 있는 경우는 무엇인가요?」 (10분 트랙 7문항 중 5문항).
- 정책 1장 「처벌 강화보다 중요한 예방 체계」 가 `compare` 가 아니라 `absolute` → 주제 질문 「사전 예방에 대해 「처벌 강화보다 중요한 예방 체계」라고 했는데, 이 말이 들어맞지 않는 경우도 있나요?」.
- 과학(대조군) 1장 제목 「LED 광원 색에 따른 상추 생장 비교」 가 `compose(적색광 효과 ⊃ 광색 비교)` 의 근거, 6장 「적색광은 청색광보다…」 가 `compare(적색광 효과 > 광색 비교)` → **거짓 긴장** → 「광색 비교도 적색광 효과의 요소인데, 적색광 효과가 광색 비교보다 더 중요하다는 건 어떤 뜻인가요?」.
- 건강 1장 「탄수화물 양보다 중요한 혈당 부하」 가 `compare(혈당 스파이크 원인 > 식사 순서)` 로 들어갔어요 — 인용에 두 개념이 하나도 안 나와요.
- 수면(tuned)도 `absolute` 근거가 「잠을 오래 잤다고 반드시 개운한 것은 아닙니다」(부정된 단정)예요.

**고칠 것** (f26_claims.py `_check`, 인용 대조 뒤):
- `absolute` 는 인용에 단정 표지 `반드시|완전히|항상|언제나|절대|결코|모든|전혀|하나도|예외 없|무조건|100%` 가 있고, 「반드시/완전히/항상 … 아니·않·어렵·수는 없」 로 부정되지 않았을 때만 남긴다 (`절대 … 않` 은 단정이라 뺀다). held-out `absolute` 12개 중 9개가 여기서 걸러져요.
- `compare`·`compose`·`cause`·`solve`·`contrast` 는 인용에 주어 라벨과 목적어 라벨 중 적어도 하나씩이 토큰 수준으로 나와야 한다 (`_match.contains_tokens`, 조사 허용). 라벨이 자료 표현과 다르면(「사전 예방」↔「예방 체계」) 노드 `summary`·F-06 개념 문자열도 별칭으로 받는다.
- `compare` 는 인용에 「보다·대비·vs·더」 중 하나가 있어야 한다 (프롬프트엔 이미 적혀 있어요 — 코드가 안 지켜요).

### 2. [치명] 인용이 여러 글 상자를 이어 붙여도 통과한다

`verify_quote` (f26_claims.py:158-175) 는 정규화에서 줄바꿈까지 지운 뒤 **장 전체 원문**과 부분 문자열로 대조해요(:170). 그래서 LLM 이 장 전체를 한 「줄」 로 옮겨도 통과해요 — held-out 인용의 16%.
예: 과학 3장 「실험 설계 | 조건 | 광원 | 광량(μmol) | 개체 수 | | A | 적색 LED | 200 | 12 …」, focus 8장 「손실은 "시간"보다 "흐름"에서 커진다 알림 확인은 짧지만, 작업 맥락 복구는…」.
이 인용이 탐침 근거·힌트로 그대로 나가요 (정책 unsolved 근거 「예방 체계 = … 계약 전에 알고, 계약할 때 지키고, 어기면 책임지게」).

**고칠 것**: `nq in norm_for_match(raw_text)` 를 **줄 단위**로 — `slide_lines(raw_text)`(식 조각은 이미 잇는다) 한 줄 안에 있을 때만 통과. 안 되면 지금의 퍼지 분기(한 줄과 0.9 이상)로 가서 **원문 쪽 한 줄**을 남긴다. 표는 `|` 행 단위로.

### 3. [치명] 「함정」 질문의 골자가 전제를 바로잡지 않아 모범답도 통과하지 못한다

triage LLM 이 `trap=true` 를 주면 질문 LLM 이 거짓 전제를 안 넣어도 `trap` 이 그대로 남아요 (f08_questions.py:2514 `trap = mark.trap`, 탐침 템플릿일 때만 :2566 에서 내림).
함정 질문 held-out 21개(5·10분) 중 **21개 모두** 골자에 전제를 바로잡는 말이 없어요 — 실제로는 거짓 전제가 없는 평범한 질문이에요.
그런데 F-09 `_enforce_trap` (f09_judge.py:637-654) 은 `question.trap` 이면 `premise_corrected=false` 인 답을 wrong 으로 내려요. 그래서:
- 수면 긴장 질문에 **골자를 그대로** 말해도 wrong 35 「질문의 전제부터 확인해 보세요 — 자료는 그렇게 말하지 않아요」 (IR·SK하이닉스·수익률·focus 도 같아요). 판정 불일치 10건 중 5건이 이거예요.
- 포기하면 「정답 요지」 로 나가는 골자도 전제를 안 바로잡아요.

**고칠 것** (f08 `_normalize_questions`, trap 을 정하는 자리): 함정이면 골자가 전제를 바로잡는지(「전제·사실은·…가 아니라·자료는 …라고」) 보고, 없으면 `trap=False` + `checks.append("trap_without_premise")`. 탐침에 묶인 질문은 함정으로 두지 않는다 — 긴장은 자료 안에 *진짜로* 있는 부딪힘이라 거짓 전제가 아니에요(수면 tension 질문이 함정이 됐어요). F-09 쪽은 `question.answer_gist` 가 전제를 바로잡는 골자일 때만 `_enforce_trap` 을 켜는 이중 안전장치.

### 4. [높음] 그래프가 거칠면 탐침이 설 자리가 없다 — 미해결 0/4, 건강 덱 긴장 놓침

탐침은 **그래프 노드 id** 로만 주장을 적을 수 있어요. 건강 덱(라이브) 그래프는 8노드라 「혈당 부하」「탄수화물 양」 노드가 없고, 문제 셋(식후 졸림·잦은 허기·야간 폭식)이 「혈당 스파이크 영향」 한 노드로 뭉쳤어요 → 긴장·미해결 둘 다 표현할 수 없어요.
IR 덱은 문제 목록 「① 높은 배송비 ② 반찬 폐기 손실 ③ 첫 달 이탈」 이 `compose` 가 아니라 `contrast` 로 들어갔고, 그래프에 「첫 달 이탈」 노드가 **두 번**, 루트가 4개(한끼곳간·객단가·건당 배송비·폐기율)예요.
정책 덱은 문제 셋이 그래프 형제 노드로 **다 있는데**(정보 비대칭·보증 가입 장벽·피해 회복 지연, 해결책이 앞의 둘에 `solve`) 4장 목록의 `compose` 가 안 나와서 미해결을 못 찾았어요. 대신 3장 식 「예방 체계 = 정보 공개 × 보증 가입 × 처벌 강화」(해결 축)를 문제 목록으로 오인해 「정보 비대칭에는 해결책을 제시했는데, **처벌 강화는 어떻게 개선하나요?**」 가 5분 트랙 3문항 중 2문항이에요.

**고칠 것**
- `_unsolved` (_probes.py:151): compose 만 보지 말고 **그래프 형제**로도 찾는다 — 같은 부모 아래 같은 장에 나온 형제가 3개 이상이고 그중 2개 이상에 `solve` 가 닿았는데 하나가 비었으면 unsolved. 그리고 compose 의 근거 장·인용에 문제 표지(문제·원인·이유·장벽·한계·위험·저하·부족)가 없으면 unsolved 를 만들지 않는다 (해결 축·구성 요소 식을 문제 목록으로 읽지 않게).
- F-26 프롬프트 「한 장에서 많아야 2개」 (f26_claims.py:90) 를 풀거나 목록 장 예외를 둔다 — 수익률 13장 체크리스트 6항목이 `solve` 몇 개만 남아, 다섯 요인 중 넷이 「해결책 없음」 이 됐어요(수익률 unsolved 4개 모두 오탐).
- F-07: 같은 라벨 노드 병합, 목록 장의 항목은 노드로 남기기(건강·IR). F-07 을 안 고친다면 F-26 이 그래프 밖 **자료 구절**도 목적어로 받게(인용에서 검증된 부분 문자열 + 가장 가까운 노드에 붙임).

### 5. [높음] 규칙 추출(`rule_compare`)이 라벨이 자료 표현과 다르면 죽는다

`resolve_label` (f26_claims.py) 의 3단계는 「변별 낱말이 **모두** 라벨에 들어야」 해요. 「처벌 강화보다 중요한 예방 체계」 의 「예방 체계」 는 노드 「사전 예방」 에 「체계」 가 없어 실패 → LLM 이 `absolute` 로 적은 것만 남았어요.
`_ADJ_FORM`(:283)도 12개 형용사(중요한·넓은·큰…)뿐이고 「넓은」 은 수면 4장에서 온 말이에요 — 「필요한·핵심적인·우선되는·앞서는」 은 못 잡아요.
**고칠 것**: 3단계를 「변별 낱말 중 가장 많이 겹치는 노드(1개 이상, 동점이면 weight)」 로 완화하고, 비교 서술어는 목록 대신 「보다 (더)? [가-힣]+(한|은|인)」 꼴로 받되 subject 는 뒤쪽 명사구로.

### 6. [높음] `unsupported_cause` 템플릿이 엉뚱한 목적어·방향으로 문장을 만든다

`_unsupported_cause` (_probes.py:176-192) 는 목적어를 `object_ids[:1]` (:183) 로 고르고 템플릿은 「A가 B에 영향을 준다고 했는데」 예요. LLM 이 문제 목록 칸을 인과로 적으면 그대로 질문이 돼요.
- 제품: 「약속 당일 취소가 **공강에** 영향을 준다고 했는데, 그렇게 볼 수 있는 근거는 무엇인가요?」 (자료: 매칭이 실패하는 이유)
- IR: 「1인 가구 증가가 **직장인에** 영향을 준다고 했는데…」 (자료: 1인 가구 증가 → 반찬 구독 수요)

그리고 `has_support` (f26_claims.py:208) 는 **장 전체**를 봐서, 제품 2장 「혼자 보내는 90분」 같은 무관한 숫자 하나로 「공강 시간이 길수록 만족도가 떨어진다」 가 근거 있는 인과가 됐어요(심은 C1 놓침). `_RESEARCH_WORD_RE`(:205)의 「실험·조사」 는 과학 덱처럼 제목에 「실험 설계」 가 있는 장을 전부 근거 있음으로 만들어요.
**고칠 것**: cause 는 인용에 원인·결과 라벨이 둘 다 나올 때만 남기고(1번과 같은 검사), 템플릿은 라벨 대신 **인용 원문**을 쓴다(「「1인 가구 증가가 반찬 구독 수요를 늘립니다」라고 했는데, 그렇게 볼 근거는 무엇인가요?」 — `absolute_boundary` 템플릿이 이미 이 꼴). `has_support` 는 인용 줄과 그 바로 옆 줄만 본다.

### 7. [중간] 주제 자리가 가장 무거운 루트가 아닐 수 있다 / 탐침이 1차 심사 순위에 밀린다

`_slot_fits("theme")` (f08_questions.py:1743) 는 depth==1 이면 다 받아요. 그래프 루트가 여럿인 IR 에서 주제 질문이 「객단가」(가짜 absolute 탐침, 가벼운 루트)로 갔어요 — 실제 주제 「한끼곳간」 이 아니에요.
탐침은 결정적인데 뽑힘은 LLM severity 가 섞인 순위를 따라가서, 건강 덱 3회 중 1회는 단정 탐침 질문이 아예 빠졌어요(탐침 질문 자카드 0.33).
**고칠 것**: theme 자리는 depth 1 중 weight 최대를 먼저(긴장 탐침이 있는 루트면 그것), weak 자리는 탐침 근거 개념을 LLM severity 보다 앞에 — `_slot_prefers` (f08_questions.py:1751) 에 두 줄.

### 8. [중간] 형제 우선순위 질문이 자료가 부정한 선택을 강요한다

수면 3장은 「둘 중 하나만 충분해서는 완전한 회복이 어렵습니다」 인데 `sibling_priority` 가 「깊은 수면과 REM 수면 중 하나만 챙길 수 있다면 어느 쪽을 우선시해야 하나요?」 를 묻고, 골자는 「깊은 수면을 우선시해야 하며…」 로 자료에 없는 답을 정답으로 둬요. held-out 에선 3/26 탐침이라 트랙을 먹지는 않지만(정책 t10 1문항, 인문 1문항), 나오면 틀린 정답을 가르쳐요.
**고칠 것**: `_sibling_priority` (_probes.py:212) 는 compose 근거 장(또는 형제 장)에 「둘 다·모두·하나만으로는·함께」 가 있으면 만들지 않는다. 골자는 「자료는 우선순위를 두지 않아요 — …」 로 고정.

### 9. [중간] 폴백 질문·힌트가 가드를 우회한다

- `_fallback_text` (f08_questions.py:2090-2093) 는 triage `angle` 을 그대로 「{label}: {angle} — 설명해 주세요.」 에 넣어요. SK하이닉스: 질문 LLM 문장이 자료밖 숫자로 버려졌는데(`ungrounded_number_dropped`) 폴백이 angle 의 「당기순이익 93.923조원 … 무엇인가 — 설명해 주세요」 를 다시 실었어요 (자료: 93,923 십억원). angle 에도 `ungrounded_numbers` 를 걸고, 걸리면 angle 없는 폴백으로.
- 힌트 인용이 Upstage 차트 설명 영문에서 나왔어요: 「A red line connects the top of the "법인세차감순이익" bar」. `_LONG_LATIN_RE` (_evidence.py:32) 가 한글 따옴표에서 끊겨 조각이 남아요. `- Chart Type:`·`- Figure Type:` 로 시작하는 설명 블록을 통째로 지우거나, 인용 후보에서 한글 비율 30% 미만인 줄을 뺀다.
- 「…재무 건전성에 미치는 영향은」 처럼 명사로 끝난 물음이 `_polite_question` (f08_questions.py:2235) 을 그대로 통과해 `반말끝!` (SK하이닉스 t5). 「은/는」 으로 끝나면 「무엇인가요?」 를 붙이는 규칙 하나.

### 10. [낮음] 판정: 그럴듯한 오답이 70~75 로 통과

자료와 반대로 말한 답이 partial 70~75 (probe_outcome 기준 pass) 로 4건 (건강 2 · 제품 1 · 수면 1). 건강 오답 「…완전히 막을 수 있다는 말은 … 효과가 있다는 뜻」 에 react 가 「막을 수 **없다는** 점을 정확히 짚었어요」 — 답에 없는 말을 칭찬했어요(판정 규칙 1-1 위반). missing_points 에 골자의 핵심 명제(부정·반대 방향)가 들었는데 70 이상이면 60 으로 깎는 가드를 `_enforce_good` 옆에 두길 제안해요. 무관한 답(10/10)·모르겠어요(10/10)는 전부 기대대로예요.

## 잘 버틴 것

- **인용 원문 대조**(주장 109/109, 질문 근거 100%, 힌트 99%), **자기모순 문장 0**, **힌트가 질문 장 안** 100%(held-out) — c6a1fa1·P1 은 덱이 바뀌어도 버텨요.
- **설문 보기·쪽 번호 힌트 0건**. 라이브 경로에선 Upstage 가 쪽 번호를 header/footer 로 걸러 주고, 칸마다 나뉜 식을 한 줄로 이어 줘요(「혈당 부하 = 혈당 지수 × 탄수화물 양 ÷ 100」). 저작한 줄 가운데 파싱에서 빠진 것은 쪽 번호와 「×」 조각뿐이에요.
- 녹음 경로: 건강 합성 녹음에서 6초에 넘긴 3장 개념이 `missing` 으로 잡혀 「혈당 부하 계산식에서 … 100으로 나누는 이유는 무엇인가요?」 가 나왔어요. 다만 `weak_flow` 두 개가 theme·part 자리를 먹어 단정 탐침 질문은 사라졌어요. 수면 실제 전사는 긴장 질문을 지킨 채 `under_spoken` 둘을 더했어요.
