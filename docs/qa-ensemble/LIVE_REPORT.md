## 0. 결론 (최종 — 근거는 §3 기준표 · §5 회차 기록)

- **「3번+ 가 발표 전체를 반영하나」 — 지금(main) 방식은 반쯤만 반영했다.**
  - 재료(신호)는 원래도 발표 전체에서 찾는다(`_ens_slots.voice_signals` 는 핵심 노드마다 그 장의 발화를 본다 — 15장 · 15분 발표에서 신호 25개가 1~14장에 퍼짐).
  - 하지만 모델에게 주는 발표 맥락이 받아쓰기 **앞 2,400자**뿐이라(15분 발표 5,913자면 1~5장까지), 신호 목록 순서(앞 장 먼저)와 겹쳐 3번+ 가 앞쪽에 쏠렸다.
    지금 방식의 3번+ 가 겨냥한 장의 **뒷 1/3 비율 0.28**(최종 비교 r7~r9, 156문항) — 자료 장 · 발화의 뒷 1/3 몫(0.37 · 0.33)보다 낮고, 8장 이상 덱은 **0.10** 이었다.
  - 새 구조(발표 중 장 단위 후보 + 장별 요지 맥락 + 장 퍼짐 고르기)는 **0.40**(158문항, 짝 차이 +0.12, 54쌍 중 23 우세 · 10 열세) · 8장 이상 **0.32** · 1~5번 전체 0.39 로
    발표 전체에 고르게 퍼진다. 반복마다 흔들림도 작다(base 0.12~0.37 ↔ live 0.37~0.44).
- **딜레이** — 발표 끝 → 1번 질문(브라우저 안 측정, 캐시 비운 새 자료): 지금 방식 **P50 35.9초**(29.2 · 35.6 · 36.1 · 42.6, n=4) → 새 구조 **P50 2.01초**
  (n=13: 1.98~2.34). 지연의 대부분은 받아쓰기 · 정합을 기다린 뒤 **지금 방식 질문(주장 · 1차 심사 · 생성 LLM)을 다 만들고 앙상블 것으로 바꿔 끼우는 데**(17~19초),
  나머지 3초가 박수 화면이었다. 묶음(1·2번 자료 질문)은 발표 중에 이미 끝나 있었다.
- **1·2번은 자료 기반 그대로** — 두 방식 모두 `pick_opening`(자료 묶음, 패턴 P1~P10)에서만(벤치 r1~r9 1·2번 302/302 가 자료 묶음, 테스트로 묶음). 발표 중 후보는 3번부터.
- **3번 준비** — 3번+ 를 묶음에서 대신 낸 비율 벤치 5/156 → **0/158**, 실험실 마지막 판(m9) 0/4.
- **품질 하락 없음(최종 구성)** — 심판 핵심성 base 4.02 · live 3.99, 미시 확인 0.07 · 0.06, Claude 가린 라벨(핵심을 묻는 비율) base 0.91(56) ↔ live 0.89(72).
  다만 중간 회차(r6)에서 장을 넓게 펴자 「정말 가장 …인지 · 구체적으로 무엇으로」 같은 확인 질문이 늘어 0.63 까지 떨어졌다 — 「확인 말고 왜」 프롬프트와 recall 거르기로 되돌렸다.
- **호출** — 판당 지금 방식 질문(F-08 · F-26 · F-08-gist ≈4회)이 빠지고 발표 중 후보(F-08-live ≈5회)가 더해져 **판당 ≈+2회**(§3).
