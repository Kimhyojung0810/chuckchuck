## 2. 매 세션 절차 (사람이 "계속" 이라고 하면)

1. §0 의 세 조건과 오늘 날짜를 확인한다. Festa 전이면 C 는 설계만.
2. 읽는다: 회의록 할 일 → 장부 → WORKLOG 맨 위 → `git status`(남의 미커밋 변경은 건드리지 않는다).
3. A·B 에서 **끝난 기준이 가장 가까운 것 하나**를 고른다. 두 개를 동시에 벌리지 않는다.
4. 테스트와 함께 구현한다. 새 파일은 800줄/50줄 상한, 기존 거대 파일(`app.js`·`app.css`)은 분할하지 않는다.
5. 검증: `pytest` 초록(기준선 이상) · JS 를 고쳤으면 `node tests/js/qa_live.smoke.mjs` + `?v=` 올림 · 키 없음.
6. 커밋·푸시(CLAUDE.md §3-5). 메시지에 **왜**.
7. WORKLOG 맨 위에 한 절, 회의록 할 일 상태 갱신. 다음 세션이 이어받을 한 줄("다음: …")을 남긴다.
8. B4 — `/improve-qa` 를 한 바퀴 돌린다 (과금 기본 4회). 사용자가 과금을 막았으면 건너뛰고 적는다.

## 3. 절대 하지 않는 것

- 동의 없는 세션을 학습·측정에 쓰기. 동의 기본값 켜기. 목록 노출.
- `.env`·키를 코드·문서·커밋에 넣기. `MOCK_EXTERNAL_APIS=true` 로 "확인".
- `contracts.py` 를 문서(`SCHEMA.md`) 없이 바꾸기. 모듈끼리 import.
- 테스트를 고쳐서 통과시키기. `fixtures/` 를 고쳐서 벤치마크를 좋게 만들기. `fixtures/holdout/` 읽기.
- Festa 전 새 화면. 판정 색·숫자 연출. 분석 실패를 샘플로 위장.
- 두 갈래를 한 세션에 반쯤씩 하기.
