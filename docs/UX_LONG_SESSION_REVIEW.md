# 긴 세션 UX 검토 — "최소 5분 + α" 흐름은 어디서 늘어지고 어디서 이탈하나 (2026-09-13)

> 사용자 지적: "발표 한 번 하면서 루즈해질 수 있다." 코드와 실측으로 시간 구조를 그리고, 이탈 지점과 극복 방안을 비용순으로 적는다.
> 근거 파일: `demo/YEHS_demo/js/app.js`(nfStep1~4, 파이프라인 시간표) · `js/qa_live.js`(문항 루프) · `docs/ANALYSIS_WAIT_REDESIGN.md` · `chuckchuck/contracts.py`(트랙별 질문 수)

## 1. 처음 쓰는 사람의 시간 구조 (12장 자료, 5분 발표를 고른 경우)

| 구간 | 사용자가 하는 일 | 걸리는 시간 | 화면이 주는 것 | 늘어지는 이유 |
|---|---|---|---|---|
| ① 자료 올리기·파싱 | 파일 끌어다 놓고 기다림 | **1~5분** (화면 문구) | "N초 지났어요 · 자료가 길면 1~5분" 한 줄 + 흐르는 막대 | 진행률이 없다. 첫 화면에서 최대 5분을 정지한 채 본다 |
| ② 발표 정보 | 상황·청중·시간 고르기 | 30초 | 이제 상황은 자료 보고 미리 채움 | (문제 적음) |
| ③ 리허설 녹음 | 슬라이드 넘기며 **혼자 5~10분 말하기** | **5~10분** | "발표 중" 시계 · 미터 · 슬라이드 전환 로그 | 실시간 피드백 없음(의도적) — 혼자 말하는 5분이 가장 길게 느껴진다. 중간에 그만둘 이유는 많고 계속할 이유는 화면에 없다 |
| ④ 분석 대기 + 리빌 | 기다림 → 개념그래프 연출 보기 | 8/7 실측 **58초**(STT 30 + LLM 28). 선분석으로 F-06/07 은 리허설 중 끝남 → 실제 대기 ≈ STT+정합 40초 | 진행 단계·경과 · 리빌은 CTA 를 눌러야 닫힘 | 짧아졌다. 다만 무거운 자료(23장)에선 다시 길어질 수 있고, 리빌은 두 번째부터 건너뛰고 싶다 |
| ⑤ 질문 코칭 입장 | **트랙(1/5/10분) 을 또 고름** → 질문 생성 대기 | 결정 10초 + **20초**(질문 생성 실측 18~24초) | "질문 코칭 시간을 골라주세요" | 발표 시간을 이미 골랐는데 또 고른다. 20초 빈 대기 |
| ⑥ 질문 코칭 | 5분 트랙 = 3문항. 문항마다: 답(타이핑/마이크) → 판정 5~10초 → partial 이면 다시 답 → 막히면 힌트 3단 → 자기 말로 다시 말하기 | 문항당 **2~3분** → 6~9분 | 판정 반응 · 힌트 사다리 · 되말하기 | 판정 대기가 문항당 2~4번 반복(각 5~10초). "이 질문이 언제 끝나는지" 상한이 안 보인다. 함정 질문이 함정 꼴이 아니라 긴장감이 없다 |
| ⑦ 리포트 | 탭 7개 훑기 | 2~5분 | 요약·말하기·개념 전달·흐름·채점 근거·연습 도구·발표 구성 | 무엇부터 볼지 화면이 정하지 않는다 |
| **합계** | | **최소 15분, 보통 20~30분** | | 5분 발표에 20분 이상 |

## 2. 이탈 지점 (심각한 순)

| # | 어디 | 왜 나가나 | 지금 있는 방어 |
|---|---|---|---|
| D1 | ③ 리허설 2~3분째 | 혼자 말하는 게 어색·지루. "이걸 끝까지 해야 결과가 나온다"는 압박만 있고 중간 보상이 없다 | 없음 (이어하기는 있음) |
| D2 | ① 파싱 대기 | 첫 인상이 정지 화면 1~5분 | 경과 초 표시뿐 |
| D3 | ⑥ 문항 2~3번째 | 판정 대기 반복 + 부분 정답 재시도로 한 문항이 3분. 시험처럼 느껴진다 | 「모르겠어요」 사다리 · 되말하기 |
| D4 | ⑤ 트랙 게이트 | 이미 발표 시간을 골랐는데 또 결정 + 20초 대기 | 없음 |
| D5 | ⑦ 리포트 | 7탭 — 성취감보다 숙제 | 요약 탭의 「우선 보완 3가지」 |

## 3. 극복 방안 — 비용 대비 효과 순 (Festa 전 허용 범위 안은 ◆, 뒤는 ◇)

| 순위 | 방안 | 무엇을 바꾸나 | 기대 | 비용 |
|---|---|---|---|---|
| 1 ◆ | **짧게 시작을 기본으로** — 첫 사용은 "슬라이드 3장 · 1분 발표 · 질문 1개" 를 권한다. 전체 리허설은 두 번째부터 | ② 화면에 "처음이면 3장으로 5분 안에 끝내 보기" 선택지 + 슬라이드 범위 선택 | 첫 완주 10분 이내. D1·D3 을 반으로 | 폼 한 줄 + 슬라이드 범위 상태 (중) |
| 2 ◆ | **트랙 게이트 제거** — 발표 시간(nf.min)으로 트랙 자동, "질문 3개 · 약 5분" 예고. 질문 생성은 분석 끝난 직후 리빌 뒤에서 선생성 | ⑤ 화면 삭제, 리빌 동안 F-08 호출 | D4 제거, 20초 대기 숨김 | 낮음 |
| 3 ◆ | **리허설 중 정직한 진행 표시** — 장당 계획 시간(이미 계산됨: perSlide) 대비 "이 장 남은 시간", 넘길 때만 한 줄("2장, 계획보다 20초 길었어요"). 말 중간엔 아무것도 안 띄움 | ③ 상단 미터를 장 단위 진행으로 | D1 완화 — "끝이 보인다" | 낮음 (숫자는 있음) |
| 4 ◆ | **문항 상한 표시** — "이 질문 남은 시도 1번" · 부분 정답 재시도는 1회, 그 뒤 사다리 → 답 공개. 문항당 90초 목표 | ⑥ askAgain 횟수 상한 + 카운터 | D3 완화, 한 문항 3분 → 1.5분 | 낮음 |
| 5 ◆ | **파싱 대기에 첫 장 먼저** — 파싱이 끝나기 전에 첫 슬라이드 썸네일·제목을 먼저 보여 주고 "12장 중 4장 읽었어요" | ① Upstage 결과를 페이지 단위로 받거나, PDF 는 브라우저에서 먼저 그린다(pdf.js 는 이미 있음) | D2 완화 | 중 (PDF 는 낮음) |
| 6 ◆ | **리빌 두 번째부터 자동 스킵** | ④ 본 적 있으면 3초 뒤 자동 닫힘 (UI_REDESIGN §14 "모든 연출 스킵 가능") | 반복 사용자 20초 절약 | 낮음 |
| 7 ◇ | **리포트 3탭 + 더보기** — 요약 · 다시 볼 질문 · 개념 전달을 앞에, 나머지는 접기 | ⑦ 탭 구조 | D5 완화 | 중 (Festa 뒤) |
| 8 ◇ | **역순 온보딩** — 처음 온 사람에게 30초짜리 샘플 리포트를 먼저 보여 주고 "내 발표로 해 보기" | 홈 | "이걸 얻으려고 5분 말한다"가 먼저 보임 | 중 (Festa 뒤) |
| 9 ◇ | **부스 모드 분리** — 준비된 발표 → 질문 1개 → 판정, 3분. 제품 흐름과 다른 진입점 | 부스 전용 홈 카드 | 부스 3분과 제품 20분을 섞지 않음 | 중 |

지금 안 하는 것: 리허설 중 실시간 코칭(말 끊김·속도 경고). 발표 흐름을 깨고, 정확도도 STT 뒤에야 나온다. 멘토 판단을 받는다(Q9).
