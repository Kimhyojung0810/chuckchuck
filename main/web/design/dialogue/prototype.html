Q&A 대화 재설계 · 1단계 — 「내 답 때문에 다음 질문이 달라졌다」

지금 질문 생성 · 판정 · 대화 상태를 분석하고, 같은 첫 질문에 일곱 가지 답을 실제 API 에 넣어 원인을 쟀어요. 그 결과로 대화 엔진(Adaptive Dialogue Engine) · 상태 전이 · 대화 화면을 설계했어요. 앱의 대화 로직은 아직 바꾸지 않았어요(정직성 수정 하나만 — 아래 5).

1지금 구조

F-08 질문 생성발표 분석 뒤 트랙마다 질문 3개를 미리 만든다→ 화면목록을 순서대로 하나씩 낸다 (qi 0 → 1 → 2)→ F-09 판정LLM 1콜: verdict · score · react · followup · claim · grounds→ 규칙 가드초점 빗나감 · 주제 밖 · 이유 누락 · 자료 어긋남이면 react · followup 을 고정 문구로 덮는다→ 화면 사다리통과면 닫고 다음 미리 만든 질문, 아니면 되묻기(넓게 → 좁게 → 거의 답) · 모르겠어요는 코칭 3단
판정기 시스템 프롬프트의 첫 줄이 「당신은 발표 심사위원이다 … 실제로 방어했는지 판정한다」 이고, followup 규칙은 「빠진 지점 하나를 콕 집어 물어라」 예요. 대화 상대가 아니라 채점자가 정답의 빈칸으로 몰아가는 구조예요.

2실측 — 같은 첫 질문, 일곱 답 (배터리 덱 · 8810 실 API)

질문: 「2C 충전은 500 사이클에서 용량의 4분의 1을 깎았다는 결과가 어떤 조건에서만 성립하는지 설명해 주세요.」 결과 표는 프로토타입 탭 아래에 있어요. 요약:

  • B 일부만 · C 모호 · D 틀린 전제가 글자 하나 다르지 않은 같은 꼬리질문을 받았어요 — 「「2C 충전은 …」에 대한 질문이에요. 자료 3장을 다시 보고, 그 장이 … 하는 말을 한 문장으로 말해 볼래요?」 (규칙 가드의 고정 문구 _FOLLOWUP_FOCUS)
  • 반응도 고정 문구예요. 맞는 조건(25도)을 말한 B 가 「조금 멀어요」, D 도 「조금 멀어요」, C 는 「질문과 다른 이야기예요」
  • 틀린 전제(D: 「45도에서만 측정」)를 짚지 못했어요 — partial 65점, 바로잡는 질문이 없어요
  • 반대 의견(G)에는 자료 수치(12%p)를 반응에 그대로 말하고, 수치를 외워 말하라는 질문을 했어요
  • 충분한 답(A)은 바로 닫히고 미리 만든 다음 질문으로 넘어가요. 더 깊이 들어가지 않아요
  • 「모르겠어요」 는 말로 하든 버튼으로 하든 같은 코칭 문구예요
  • 관점 바꾸기 「반례」 는 422(새 질문이 계약 검사를 못 넘음)로 실패했어요 — 사용자에겐 오류로 보여요

3티키타카가 약한 근본 원인

  1. 꼬리질문의 출발점이 내 말이 아니라 정답의 빈칸이에요(missing_points). 답이 달라도 빠진 칸이 같으면 다음 질문도 같아요.
  2. 규칙 가드가 말까지 바꿔요. 점수 상한을 거는 장치가 react · followup 을 고정 문구로 덮어서, 가드에 걸리는 답은 모두 같은 말을 들어요.
  3. 대화 전략이라는 개념이 없어요. 넓게 → 좁게 → 거의 답 사다리 하나뿐이라, 흐린 말 확인 · 틀린 전제 맞서기 · 반대 의견 탐색 · 잘한 답 더 깊이가 없어요.
  4. 질문 목록을 순서대로 소비해요. 잘 답하면 대화가 끝나고 다음 카드로 넘어가요. 다음 주제를 대화가 고르지 않아요.
  5. claim(내 말)과 followup 을 따로 만들어요. 화면이 둘을 이어 보여 주면 거짓 연결이 돼요 → 오늘 막았어요(5).

4Adaptive Dialogue Engine — 채점과 대화를 나눈다

① 채점지금 판정기 그대로(verdict · score · grounds) — 리포트 · 기록용. 말은 안 만든다→ ② 읽기답 원문에서 구절을 뽑는다: 핵심 생각 · 흐린 말 · 자료와 어긋난 말(+장) · 반대 의견 · 모름→ ③ 정책(코드)신호 → 전략 하나. LLM 이 고르지 않는다→ ④ 말하기그 전략의 꼴로 reaction · follow_up_question · source_slide→ ⑤ 검사(코드)구절 원문 · 질문이 구절을 가리킴 · 자료 수치 흘림 0 · 해요체 · 원래 질문 되풀이 아님 → 실패면 한 번 다시, 그래도면 전략별 고정 틀(구절을 인용)
전략언제 (정책 — 위가 먼저)꼬리질문 꼴예 (같은 첫 질문)
hint 힌트빈 답 · 「모르겠어요」 · 기억 안 남정답 없이 볼 곳 하나 + 아주 쉬운 질문자료 2장 배치도에서 이 실험이 바꾼 조건은 두 가지예요. 하나만 찾아볼래요?
explore 다른 관점자료 결론에 반대하는 의견그 관점의 이유 + 자료의 무엇과 견줄지열 때문이라면, 항온조 온도를 바꿨을 때 결과가 어떻게 달라져야 그 생각이 맞는 걸까요?
challenge 맞서기자료와 사실이 어긋난 말내 말 ↔ 자료가 부딪히는 곳을 보여 주고 직접 확인「45도에서만 측정했다」고 했는데, 자료 3장 그래프의 2C 막대는 어느 온도 조건에서 나왔나요?
deepen 더 깊이verdict good원리 · 적용 · 한계로 한 단계방전심도 100%라는 조건이 왜 실사용보다 열화를 키운다고 볼 수 있을까요?
clarify 뜻 확인흐린 말이 핵심을 대신함그 말이 정확히 무엇을 뜻하는지 · 조건 하나「상황마다 다를 것 같다」고 했는데, 이 실험에서 그 '상황'에 해당하는 조건 하나를 꼽으면 뭘까요?
connect 고리 잇기방향은 맞고 고리가 빠짐내 말에서 출발해 빠진 고리 하나25도라는 조건을 바꾸면 이 결과가 그대로일까요, 달라질까요?
switch 주제 바꾸기사용자가 고름 · 같은 고리에서 세 번 막힘기록을 남기고 다음 주제(어긋남 → 빠뜨림 → 무게 순) · 돌아오기 가능좋아요, 「가속 조건」 으로 가 볼게요

응답 구조 (판정 응답에 더한다)

reaction · referenced_user_idea(답 원문 구절, 검사) · follow_up_question · dialogue_strategy · source_slide. 채점 필드(verdict · score · grounds · claim)는 그대로라 리포트 · 기록은 안 바뀌어요.

시간 — 두 박자로 감춘다

①+② 를 한 콜로(지금 판정 콜에 읽기 필드를 더함, ~3초) → 화면에 내 말 밑줄이 먼저 뜨고 → ④ 한 콜(~1초) → 꼬리질문이 그 구절에서 이어져요. 한 턴 LLM 1콜 → 2콜.

시험 프롬프트 실측이 알려 준 것

  • 1판(LLM 이 전략도 고름): 7개 중 4개가 deepen, 자료 수치 흘림 → 전략은 코드가 정해야 해요
  • 2판(정책 + 검사): 기본 모델(solar)은 구절을 자주 못 뽑고 틀린 전제 · 반대를 못 읽어요. A.X 는 반대(G) · 흐림(C)을 바로 갈랐지만 D 는 못 잡고 반말이 섞였어요
  • → 모델 · 프롬프트는 평가 묶음(덱 3 × 답 7)과 자동 점수로 골라요

다음 주제 — 목록 소비 대신

질문 하나 = 주제 한 가닥. 한 가닥 안에서 전략이 이어지다가 통과 + deepen 한 번이면 「다음으로 갈까요, 더 깊이 갈까요」. 다음 가닥은 미리 만든 순서가 아니라 발표와 어긋난 개념 → 빠뜨린 개념 → 무게 순(지금 「다른 핵심 개념으로」 규칙)으로 고르고, 내려놓은 가닥은 기록에서 「이 주제로 돌아가기」 로 다시 열어요.

5정직성 — 오늘 막은 것

측정 중에 화면이 B · C · D 의 고정 문구 꼬리질문 위에도 「내 말에서 「…」」 를 달아, 이어지지 않은 질문을 내 말에서 나온 것처럼 보이고 있었어요. 꼬리질문이 내 말의 낱말을 실제로 쓸 때만 잇게 고쳤어요(qwClaimLinked, 커밋 c9fb477, 테스트 포함). 엔진이 바뀌면 이 연결은 검사(⑤)가 보장해요.

6대화 상태 전이

AI 말하기질문(TTS 있으면 출력 음량)→ 생각 중(사용자)마이크 열림 · 조용→ 사용자 말하기마이크 실제 음량 · 받아쓰기→ 읽는 중①② — 끝나면 내 말 밑줄→ 꼬리질문 짓는 중④⑤ — 전략 꼬리표→ 엮기이전 질문 물러남 → 내 말 → 새 질문→ AI 말하기…

곁가지: 「힌트」 → hint 전략으로 같은 흐름 · 「다른 주제로」 → 주제 바꾸기(실패로 안 셈) · 판정 실패 → 「다시 보내기」 · 끝 → 리포트. 웹캠 틀은 어느 상태에서도 그대로예요.

7대화 화면 — 세 가지

W1 띠 대화 (추천 · 지금 배치를 잇는다)

카메라 바로 아래 한 줄로 반응 → 「내 말에서」 → 꼬리질문이 쌓였다 물러나요. 눈이 카메라 근처에 머물고 웹캠 틀 위엔 아무것도 없어요.

W2 오른쪽 대화 기둥 (Split)

대화 세 가지를 세로로 넉넉히 보여 줘요. 대신 질문을 읽을 때 눈이 옆으로 가고, 웹캠이 좁아져요.

W3 아래 자막형 (Lower third)

웹캠이 가장 커요. 대신 질문이 화면 아래라 읽을 때 고개가 숙여지고, 발표 연습에선 시선 습관이 나빠져요.

추천은 W1 이에요 — 이미 띠 · 틀 · 레일로 만든 화면에서 띠 안의 세 줄(반응 · 내 말 · 꼬리질문)과 전략 꼬리표만 더하면 돼요. 실제 화면에서 W2 와 비교 캡처를 2단계 첫 일로 해요.

8시험 · 통과 기준 (2단계)

  • 평가 묶음: 덱 3개 × 첫 질문 1~2개 × 답 A~G(+2턴 B · D) — 위 실험(etc/labs/dialogue_probe)을 키운다
  • 달라짐: 같은 질문의 A~D 꼬리질문끼리 같은 문장 0개, 낱말 겹침(바이그램) 0.5 미만
  • 전략 맞춤: 사람이 붙인 기대 전략과 덱마다 6/7 이상
  • 정직: 붙잡은 구절 100% 원문 · 질문이 그 구절을 가리킴 100% · 자료 수치 흘림 0 · 틀린 말을 맞다고 한 반응 0
  • 말투: 해요체 100%(반말 · 「~시」 0) · 반응 40자 안
  • F: 주제 바꾸기 · 관점 바꾸기 성공률 · 「반례」 422 고침, 기록 · 리포트에 실패로 안 셈
  • 회귀: 리포트 점수 · 기록 · 힌트 사용 수 그대로, 카메라 · 받아쓰기 · 자동 보내기 그대로
