# BRIEF — 척척발표 디자인 개편 기획

> 2026-10-12 사용자 기획을 정리한 것. 방향이 바뀌면 여기부터 고친다.

## 1. 서비스

**한 줄 정의.** 척척발표는 발표자료와 실제 발표 내용을 함께 분석해서, 빠뜨린 내용과 논리적 빈틈을 찾아 주고 예상 질문으로 Q&A 까지 연습시켜 주는 발표 준비 서비스다.

**누구를 위한가.** 자료는 준비했지만 실제로 말하고 질문받을 준비는 아직 부족한 모든 발표자.

- 면접 — PT 면접 · 포트폴리오 발표 · 질의응답 대비
- 회사 — 제안 발표 · 보고 · 사내 피칭
- 연구실 — 랩미팅 · 학회 · 연구 발표
- 팀플 · 공모전 — 수업 발표 · 본선 피칭

가장 필요한 순간은 중요한 발표 **전날 또는 직전**이다.

**해결하는 문제.**

- AI 로 자료를 빨리 만들 수 있어도, 자료가 완성됐다고 발표 준비가 끝난 건 아니다.
- 실제로 말할 때 슬라이드의 핵심을 빠뜨리거나, 슬라이드 사이 논리를 말로 잇지 못한다.
- 면접관 · 상사 · 교수 · 심사위원이 던질 질문을 예상하지 못해 Q&A 에서 막힌다.
- 혼자 연습하면 무엇을 놓쳤는지 스스로 알기 어렵고, 피드백 줄 사람도 마땅치 않다.

**사용 흐름 — 네 정거장.**

| # | 정거장 | 하는 일 | 지금 화면 |
|---|---|---|---|
| 1 | 자료 올리기 | 발표자료를 올린다 | `#/rehearsal` (올리기) |
| 2 | 발표 | 실제로 발표하듯 녹화 · 녹음한다 → SSA 분석(슬라이드–발화 맞대기) | `#/rehearsal/new` (비전 리허설) · 분석 기다림 |
| 3 | 질의응답 | 분석에서 나온 예상 질문에 직접 답한다 → 판정 · 힌트 · 다시 답하기 · 모범 답변 | `#/rehearsal/qa` (화상판) |
| 4 | 리포트 | 빠뜨린 내용 · 논리 빈틈 · 자료와 어긋난 곳을 슬라이드별로 · 답변 결과 | `#/rehearsal/report` |

**차별점.** 자료만 보지 않고 **자료와 실제 발화를 함께** 비교한다 — 「자료에는 있는데 말로는 안 한 것」 을 잡는다. 그리고 찾아낸 빈틈을 **실전 Q&A** 로 이어 직접 대비하게 한다.

**사용자가 얻는 것.** 발표 전에 무엇을 놓쳤는지 확인하고, 받을 질문에 미리 답해 보며 「자료 완성」 에서 「발표 준비 완료」 로 넘어간다.

## 2. 디자인 방향 — 브라우저 기반 가상 발표 스튜디오

> **YUYA 의 공간적 스토리텔링 + Apple visionOS 의 절제된 인터페이스.**

- 브라우저 전체가 하나의 **가상 공간**이다. ~~단계마다 시점이 90° 씩 돈다~~ → **10-13 바뀜: 시점은 고정, 창들이 내 앞에서 옆으로 미끄러진다 (Meta Quest Horizon OS 방식)** — 시점을 돌리면 멀미가 난다.
- **3D World + 2D Productivity UI.** 공간은 3D 이고, 일은 그 공간에 떠 있는 2D 창에서 한다(Meta Quest Horizon OS · visionOS 처럼). 단계에 필요하면 그 창 주변에 3D 인터랙션을 더한다.
- **공간의 일관성.** 서로 다른 배경 네 개가 아니라, **건축 공간 하나**에서 시점과 조명만 바뀐다 — 같은 장소에 있다고 느끼게.
- **3D / 2D 경계.**
  - 3D: 공간 · 카메라(시점) · 조명 · 발표 무대 · 개념 시각화
  - 2D: PPT 내용 · 텍스트 입력 · 질문 · 점수 · 상세 리포트

### 레퍼런스에서 가져올 것과 버릴 것

YUYA Film Studio (https://www.awwwards.com/sites/yuya-film-studio) — 공간을 쓰는 발상은 좋지만 게임하는 느낌이 너무 강하다. 척척발표는 게임이 아니라 발표 연습 도구다. **몰입감은 유지하되 조작은 일반 웹사이트만큼 간단하게.**

| YUYA | 척척발표 |
|---|---|
| 복잡한 3D 공간과 소품 | 단순한 공간 하나 |
| 자유롭게 돌아다니는 탐험 | 버튼을 누르면 자동 시점 전환 |
| 게임처럼 오브젝트 탐색 | 정면의 떠 있는 창에서 작업 |
| 다양한 공간과 장면 | 네 단계에 맞춘 시점 · 조명 변화 |
| 장식적인 인터랙션 | PPT · Q&A · 리포트에 필요한 인터랙션만 |

원하는 결:

- **Apple visionOS** — 3D 공간이 있지만 사용자는 떠 있는 창에 집중한다. 이동 · 탐험이 필요 없다.
- **Minimal Virtual Architecture** — 소품 · 장식 없이 공간 자체의 깊이와 조명으로 몰입감을 만든다.

`etc/design-ref/` 의 yuyafilmstudio 추출본은 **색 · 타이포의 결**만 참고한다 (DESIGN_SYSTEM.md). 조작 방식은 가져오지 않는다 — WASD · 마우스 시점 · 오브젝트 집기 없음.

## 3. 바꾸면 안 되는 것

- **발표와 질의응답에서 카메라를 쓰는 방식은 절대 바꾸지 않는다** — 권한 요청 시점 · 녹화 · 정면 판단(OpenCV) 동작 그대로.
- **카메라를 쓰는 정거장은 카메라가 화면의 중심이다** (10-12 사용자: 「그래야 사람의 시선을 확 끈다」). 지금 앱의 리허설 화면처럼 내 모습이 화면 대부분을 차지하고, 자료 · 조작은 그 위에 떠 있는 작은 유리 창이다. 자료가 주인공이고 카메라가 구석에 있는 배치는 쓰지 않는다.
- 판정 색 5종의 값과 뜻 (CLAUDE.md §3-3).
- 토스 규율의 말투 · 다크패턴 금지 (CLAUDE.md §3-1).
- 분석 실패는 실패로 보인다 — 연출로 가리지 않는다.

## 4. 성공 기준

- 처음 온 사람이 설명 없이 「올리기 → 발표 → 답하기 → 리포트」 를 버튼만으로 끝까지 간다 — 시점 조작을 배울 필요가 없다.
- 단계가 바뀔 때 「같은 방에서 몸을 돌렸다」 고 느낀다 (화면이 갈아 끼워진 느낌이 아니다).
- 2D 창 안의 글자는 언제나 선명하다 (확대 · 흐림 없이 1:1).
- 폰에서도 같은 흐름이 돈다. 움직임 줄이기를 켜면 회전 없이 바로 바뀐다.
