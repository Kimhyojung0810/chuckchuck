# SPACE v2 — 3D 공간 설계 (React Three Fiber)

> 방 하나, 정거장 넷, 몸을 돌리듯 90°. 조작은 버튼 + 간단한 마우스. (BRIEF §2 · §5)
> v1(CSS 3D 시제품, feffc6f)에서 바뀐 것: 실제 3D 렌더러(three.js) · 실제 조명 · 스프링 카메라 · 마우스 · 카메라 중심 정거장 · 유리 창. v1 에서 배운 것은 §9.

## 1. 방

정사각형 방 하나의 한가운데에 사용자가 서 있다. 벽 네 면이 각각 한 단계의 「정거장」 이다. 단위는 미터.

```
                 ┌──────────── 벽 0 ────────────┐
                 │      ① 자료 올리기 (0°)       │
        벽 270°  │  ④ 리포트    ●     ② 발표    │  벽 90°
                 │   (270°)   사용자    (90°)    │
                 │      ③ 질의응답 (180°)        │
                 └──────────── 벽 180 ───────────┘
              다음 단계 = 오른쪽으로 90° (시계 방향)
```

| 값 | 크기 |
|---|---|
| 방 반폭 | 6 m (벽까지) |
| 천장 높이 | 4.2 m |
| 눈높이 | 1.6 m |
| 창 · 카메라 화면까지 | 3.2 m |
| 시야각(세로) | 50° (폰 62°) |

- **건축은 하나.** 네 벽은 같은 재질(따뜻한 회색 미장 `#2B2925`, 거칠기 .95) · 같은 높이 · 같은 걸레받이. 바닥은 어둡게 광택 있는 콘크리트(약하게 비친다), 천장은 어둡다.
- **이어지는 요소 둘.** 천장 바로 밑을 한 바퀴 도는 간접 조명 줄(빛나는 띠) · 벽 아래 걸레받이 그늘. 돌 때 이어져 보여서 「같은 방」 이 된다.
- **장식 없음.** 소품 · 가구 · 창밖 풍경 없음. 빛과 그늘, 옅은 안개(멀수록 어둡게)로 깊이를 만든다.

## 2. 시점 (카메라) — 스프링으로 움직인다

| 정거장 | 방향 | 들어오는 버튼 예 |
|---|---|---|
| ① 자료 올리기 | 0° | 첫 화면 · 「새 리허설」 |
| ② 발표 | 90° | 「발표하러 가기」 |
| ③ 질의응답 | 180° | 「질문 받으러 가기」 |
| ④ 리포트 | 270° | 「리포트 보기」 |

- **한 방향으로만 돈다.** 다음 단계는 언제나 오른쪽 +90°, 각도를 누적한다(리포트 → 새 리허설도 거꾸로 270° 돌지 않는다). 뒤로 가기는 −90°.
- **스프링 카메라** (10-12 피드백 「너무 확확 넘어간다」). 정해진 시간의 곡선이 아니라 목표 각도를 향해 **임계 감쇠 스프링**으로 따라간다 — 천천히 출발해 가속하고, 끝에서 길게 감속해 멈춘다. 반응 시간(smoothTime) .7s → 90° 가 2초 안팎에 자리 잡는다.
- **걸음 경로.** 돌기 시작하면 방 한가운데 쪽으로 한 걸음 물러서고(최대 .55 m, 남은 각도에 비례), 다 돌면 다음 창으로 다가간다. 돌 때 고개가 아주 살짝 내려갔다(최대 1.5°) 올라오고, 걸음에 맞춰 눈높이가 1cm 안쪽으로 오르내린다. 「고개만 돌린 것」 이 아니라 「몸을 돌려 걸어간 것」 이 되게.
- **창은 늘 그 자리에 있다.** 지금 정거장이 아닌 창도 사라지지 않고 흐리게(불투명도 .35) 자기 벽 앞에 떠 있다 — 돌 때 옆 창이 공간 속에서 지나가는 게 보여야 「같은 방」 이다.
- **조명도 같은 스프링.** 정거장별 조명 값(§3)으로 같은 반응 시간을 따라간다.
- 전환 중에도 버튼은 받는다 — 목표 각도만 바뀌고 스프링이 이어서 따라간다(끊기지 않는다).
- **움직임 줄이기**면 스프링 없이 바로 그 각도로, 시선 따라오기 · 걸음 흔들림 없음.

## 3. 조명 — 정거장마다

같은 방에 조명만 다르다. 정거장마다 그 벽 위에 스포트라이트 하나, 천장 띠 하나, 방 전체 은은한 빛.

| 정거장 | 느낌 | 스포트(지금 벽) 세기 · 색 | 천장 띠 | 방 전체 빛 | 안개 |
|---|---|---|---|---|---|
| ① 자료 올리기 | 아침 작업실 — 고르고 맑음 | 중간 · 중립 미색 `#E8E4DC` | 켬 | .55 | 옅게 |
| ② 발표 | 무대 — 주변이 가라앉고 정면만 | 강하게 · 금빛 `#C9A96E`, 좁게 | 거의 끔 | .2 | 짙게 |
| ③ 질의응답 | 마주 앉은 대화 — 따뜻하고 낮게 | 중간 · 따뜻한 `#D9B98A` | 은은 | .35 | 중간 |
| ④ 리포트 | 읽는 방 — 가장 밝고 고르게 | 넓게 · 맑은 미색 `#F2EDE4` | 켬 | .7 | 옅게 |

빛 색은 금빛 계열 하나에서만 움직인다 — 파랑 · 초록 조명은 쓰지 않는다(판정 색과 섞인다).

## 4. 3D 와 2D 의 경계

| 3D (three.js) | 2D (React DOM, 3D 위치에 붙은 창) |
|---|---|
| 방 · 조명 · 안개 · 반사 바닥 | 자료(PPT) · 텍스트 입력 · 질문 · 판정 · 점수 · 리포트 |
| 카메라(시점) 스프링 · 걸음 · 마우스 시선 | 버튼 · 폼 · 목록 |
| **카메라 화면**(내 모습 영상) — 벽 앞의 큰 화면 | 카메라 화면 위에 뜬 작은 유리 창(자료 · 조작) |
| 유리(굴절) — 창 뒤의 방 · 영상을 굴절 | 유리 위 글자 (대비를 지키는 색 막 위) |
| 음성 구(shadergradient) | — |

## 5. 구현 — React Three Fiber

- **스택:** React 19 · `@react-three/fiber` 9 · `@react-three/drei` 10 · `three` 0.186 · `@shadergradient/react` 2.4. esbuild 로 한 파일로 묶는다 — 원본 `main/web/studio-app/src/`, 결과 `main/web/js/studio-app.js` (`npm run build`).
- **창 = drei `<Html transform>`.** DOM 을 3D 위치에 붙인다(입력 · 선택 · 화면 읽기 · 초점이 그대로). 크기 맞춤: 멈춰 있을 때 CSS 1px = 화면 1px 이 되게 스케일을 정한다(창까지 거리 · 시야각 · 화면 높이로 계산) — 글자가 흐려지지 않는다.
- **카메라 리그:** 매 프레임 목표(정거장 각도 + 마우스 시선)를 향해 `maath/easing.dampAngle` 로 따라간다. 걸음 · 고개는 남은 각도에서 계산.
- **유리:** §8.
- **음성 구:** `@shadergradient/react` 를 창 안 작은 캔버스로. 마이크를 켜면 소리 크기가 세기 · 속도를 바꾼다.
- **품질 단계:** 기본은 반사 바닥 · 유리 굴절 · 안개 켬. 느린 기기(프레임 40 아래 2초)면 반사 바닥 · 유리 해상도를 낮춘다. 화소 밀도 1 ~ 1.5.

## 6. 카메라 중심 정거장 (② 발표 · ③ 질의응답)

10-12 피드백: 카메라를 쓰는 화면은 **완전히 카메라가 중심**.

- 그 벽 앞에 **큰 카메라 화면**(16:9, 멈췄을 때 화면 높이의 약 85%)이 있고, 내 모습이 거울처럼(좌우 반전) 크게 나온다. 시선이 여기로 간다.
- 그 위에 작은 유리 창들이 떠 있다:
  - ② 발표: 왼쪽 위 **자료 창**(지금 장 · ‹ › · 장 번호), 아래 **조작 줄**(녹음 상태 · 시계 · 주 버튼), 오른쪽 **음성 구**(말하면 반응).
  - ③ 질의응답: 위 **질문 창**, 아래 **답 창**(음성 구 + 받아쓰기 · 글로 쓰기), 판정은 종이 조각으로.
- 카메라를 켜기 전에는 그 자리에 「카메라를 켜면 여기에 내 모습이 크게 보여요」 + 「카메라 켜기」. 권한은 버튼을 눌렀을 때만 묻는다 — 들어오자마자 묻지 않는다.
- 시제품의 카메라는 이 페이지 안에서만 쓰는 새 코드다. **지금 앱의 카메라 코드(`vision_rehearsal.js` · `booth_*` · `call_flow.js`)는 건드리지 않는다** — 3차에서 붙일 때도 그 코드가 연 영상을 넘겨받기만 한다.

## 7. 마우스 조작 (간단하게)

| 조작 | 동작 |
|---|---|
| 마우스 움직이기 | 시선이 아주 살짝 따라온다 (좌우 ±4°, 위아래 ±2.5°, 부드럽게) — 머리를 살짝 돌리는 느낌 |
| 빈 공간을 끌기 | 좌우로 둘러본다 (최대 ±70°). 놓으면 35° 넘게 돌렸으면 그쪽 정거장으로, 아니면 제자리로 스프링 복귀 |
| 흐린 옆 창 누르기 | 그 정거장으로 간다 |
| 터치(폰) | 끌기만 (시선 따라오기 없음) |

- 창 위에서의 끌기 · 클릭은 창 안 조작이 먼저다(글 선택 · 버튼). 끌어서 둘러보기는 창 밖 빈 공간에서만.
- 키보드 방향키는 쓰지 않는다 — 발표 중 ← → 는 슬라이드 넘김이다.
- 움직임 줄이기면 시선 따라오기 끔(끌기는 놓으면 바로 그 정거장/제자리).

## 8. 유리 — liquid-glass

10-12 피드백: 3D 공간의 2D 창은 liquid-glass-js 를 적극적으로.

- liquid-glass-js(MIT, Armagan Amcalar)는 html2canvas 로 **페이지를 한 장 찍어** 그 그림을 굴절시킨다. 그런데 html2canvas 는 3D 변환과 `<video>` 를 못 찍는다 — 3D 방 · 카메라 영상 위에서는 엉뚱한 배경이 비친다.
- 그래서 **그 라이브러리의 굴절 셰이더(가장자리 · 테두리 · 바탕 굴절, 모양 법선, 모서리 강조, 물결, 13×13 흐림, 색 막)를 three.js 재질로 옮긴다.** 배경은 페이지 사진 대신 **매 프레임 그린 방(+카메라 영상) 그림**이다:
  1. 유리를 뺀 장면(방 · 조명 · 카메라 화면)을 화면 크기 텍스처에 그린다.
  2. 창마다 둥근 판(창과 같은 크기 · 위치, DOM 바로 뒤)에 유리 재질 — 그 텍스처를 화면 좌표로 읽어 굴절 · 흐림 · 색 막.
  3. 그 위에 DOM 창(글자 · 버튼).
- 그래서 돌 때도, 영상이 움직여도 유리 속 배경이 실제로 따라 움직인다.
- **글자 대비:** 유리 위 글자 뒤에는 색 막(무대 창 `rgb(18 18 16 / .55)`, 종이 창 `rgb(244 240 232 / .78)`)을 깐다. 견본에서 대비를 자동으로 잰다(4.5 : 1 미만 0).

## 9. v1(CSS 3D)에서 배운 것

- CSS 원근은 카메라 뒤에 걸친 면을 뒤집어 그린다 → 벽 반쪽 · 시선 밖 감추기, 바닥을 카메라에 붙이기. (three.js 는 근평면에서 자르므로 이 문제가 없다.)
- 헤드리스 확인은 GPU 래스터 · WebGL 흉내 모드(`--use-gl=angle --use-angle=swiftshader --enable-gpu-rasterization --ignore-gpu-blocklist`)로. 이 VM 에는 GPU 가 없어 느리다 — 동작은 상태 값으로, 모양은 멈춘 사진으로 본다.
- 창을 원근 거리에 두면 1:1 로 선명하다 — v2 에서도 멈췄을 때 1:1 을 지킨다.
