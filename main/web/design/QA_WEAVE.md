# Q&A — 「생각 엮기(Thought Weaving)」 설계 (2026-10-13 사용자 브리프)

> 척척발표는 정답을 채점하는 서비스가 아니라, **내 답에서 이어지는 꼬리질문으로 스스로 생각을 발전시키는** 대화형 학습이다.
> 심사위원이 화면만 보고 ① 실제로 대화하고 있다 ② AI 는 이전 답을 바탕으로 꼬리질문한다 ③ 대화할수록 생각의 연결이 쌓인다
> ④ 원하면 다른 주제로 자유롭게 간다 — 를 알아야 한다.

## 0. 절대 전제 — 웹캠이 무대

- 웹캠은 Q&A 내내 화면의 75~85%(스튜디오 정면 창 = 화면 폭 90% · 높이 88%), 질문이 바뀌어도 크기가 그대로다.
- 얼굴(가운데)을 카드가 가리지 않는다 — 질문은 위 가운데 띠, 답 조작은 아래 가운데 띠, 생각의 흔적은 왼쪽 가장자리.
- 카메라 · 마이크 · 받아쓰기 · 자동 보내기 코드는 그대로다 (BRIEF §3).

## 1. 지금 무엇이 있고 무엇을 새로 만드나 (코드 조사 10-13)

| 필요한 것 | 지금 | 이번 작업 |
|---|---|---|
| 꼬리질문 | **있다** — `/qa/judge` 한 번의 LLM 호출이 누적 답을 보고 `followup` 을 쓰고, 코드가 걸러 틀로 대신하기도 한다 (`f09_judge.py`) | 그대로 쓴다. 화면이 「어느 발언에서 나왔나」 를 잇는다 |
| 내 답의 핵심 발언 | **없다** | 판정 스키마에 `claim` 추가 — LLM 이 **답 원문에서 그대로** 옮긴 짧은 구절, 코드가 원문에 있는지 확인. 자료 줄 말로 고쳐 썼으면(실측) 가장 닮은 **내 문장/마디를 원문 그대로**, 닮은 게 없으면 비운다. 나가는 글자는 언제나 사용자가 한 말이다 |
| A. 다른 핵심 개념 | 개념별 질문 요청은 없다. 트랙 10(개념이 다른 질문 7개)은 있다 | 트랙 10 질문을 받아 **아직 안 물은 개념 · 자료와 어긋남 · 빠뜨림 · 무게 순**으로 고른다. 서버 색인에 있어 판정이 그대로 된다 |
| B. 같은 개념, 다른 관점 | **없다** | 새 경로 `POST /api/v1/sessions/{id}/qa/reframe` — 같은 개념 · 같은 자료 근거로 관점(사례 · 근거 · 반례 · 원인 · 결과)만 바꾼 질문과 그 기대 답 요지를 LLM 이 쓰고, 서버 질문 색인에 올려 `/qa/judge` 가 알아본다 |
| C. 이 질문 건너뛰기 | 「답 보고 넘어가기」 · 「남은 질문 건너뛰고 리포트로」 뿐, 넘기면 리포트에서 **약한 개념**으로 셌다 | `setAside` 표시로 닫는다 — 기록(넘김)에는 남고 약함 · 실패로 세지 않는다 |

## 2. 화면 (리허설 흐름의 글라스 화상판 `#bqStage[data-flow=rehearsal][data-screen=qa]`)

```
┌─────────────────────────── 웹캠(전체) ───────────────────────────┐
│   ○ 질문 1 · 꼬리 2      ┌───────── 삐약이 질문 카드 ─────────┐       │
│   │                     │ (삐약이 · 목소리 구)  지금 질문      │       │
│   ● ← 생각의 흔적        └──────────────▲──────────────────┘       │
│   │   (지난 발언 · 질문)                  ╲  빛줄기(내 발언 → 꼬리질문)  │
│   ○                                       ╲                       │
│                          「내 발언」 칩 ●──╯                         │
│              ┌────────── 답 조작(마이크 · 파형 · 보내기) ──────────┐ [다른 주제로] │
└──────────────┴──────────────────────────────────────────────────┴──────────────┘
```

- **순간마다 필요한 것만**: 삐약이가 물을 때 = 질문 카드 + 목소리 구 / 내가 답할 때 = 파형 · 받아쓰기 한 줄 / 꼬리질문이 생길 때 = 내 발언 칩 → 빛줄기 → 새 질문.
- **생각의 흔적**: 왼쪽 가장자리 세로 실 — 질문마다 작은 마디, 꼬리질문은 같은 실에서 이어지고 주제가 바뀌면 실이 새로 시작한다. 마디를 누르면 그때의 질문 · 내 발언이 보인다.
- 대화 기록 전체 · 힌트 · 정답 보기는 「도움 · 기록」 접이 패널로(기본 닫힘). 오른쪽의 복잡한 답 패널은 없앤다.

## 3. 주제 바꾸기 — 「다른 주제로」 떠 있는 작은 메뉴

| 선택 | 하는 일 | 데이터 |
|---|---|---|
| A 다른 핵심 개념으로 | 지금 질문을 `setAside` 로 닫고, 아직 안 물은 중요 개념 질문을 다음에 넣는다 | `/api/v1/questions` track 10(서버 캐시 · 색인) + alignment(빠뜨림 · 어긋남) + 개념 무게 |
| B 같은 주제, 다른 관점 | 관점 칩(실제 사례 · 근거 · 반례 · 원인 · 결과) → 새 질문 | `/qa/reframe` (LLM 한 번) |
| C 이 질문 건너뛰기 | 지금 질문을 `setAside` 로 닫고 다음 질문 | 없음(기록만) |

- 전환 연출(0.5~1초): 흔적이 작아지며 왼쪽 실로 접히고 → 새 주제 이름이 짧게 → 삐약이가 새 질문. 웹캠은 그대로.
- `L.questions` · `L.results` 는 **같은 자리(인덱스)** 로 맞춘다 — 새 질문은 지금 자리 바로 뒤에 넣는다(`recordQaHistory` · 진행 칩이 인덱스로 읽는다).

## 4. 정직 규칙

- 「이해 완료」 같은 확인하지 않은 말을 쓰지 않는다. 판정은 서버 판정(verdict) 그대로.
- 내 발언(`claim`)이 비면 칩을 그리지 않는다(내 답 앞부분을 대신 쓰지 않는다 — 그건 핵심 발언이 아니다).
- 꼬리질문이 어느 발언에서 나왔는지는 `turns[i].claim` → `turns[i+1].question` 으로 잇는다(같은 질문 안에서만).

## 5. 코드

- 서버: `pipeline/contracts.py QaJudgement.claim` · `pipeline/f09_judge.py`(스키마 · 원문 대조) · `pipeline/f09_reframe.py`(새) · `server/bridge.py _handle_qa_reframe`.
- 앱: `js/qa_live.js`(claim 기록 · setAside · 주제 바꾸기) · `js/qa_weave.js`(새 — 흔적 · 칩 · 빛줄기 · 메뉴) · `css/qa_weave.css`(새) · `js/booth_call.js`(bcSync 에서 qwSync 부름).
- 스튜디오: ④ 정거장 = 정면 창 크게(웹캠 75~85%), 바깥 심사위원은 쉰다(앱 안 삐약이 · 목소리 구가 맡는다).
