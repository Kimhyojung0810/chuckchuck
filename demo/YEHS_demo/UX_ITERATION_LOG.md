# 척척발표 UX 이터레이션 로그

이 문서는 `MVP_SPEC.md`를 구현하면서 발견한 문제, 참고한 원칙, 변경한 화면, 검증 결과를 계속 누적하는 작업 기록이다. 제품 정의와 필수 요구사항은 `MVP_SPEC.md`가 우선한다.

## 기록 규칙

- 날짜와 버전, 관찰한 문제, 결정, 구현 범위, 검증 결과를 함께 남긴다.
- 외부 서비스를 그대로 복제하지 않고 학습 원리만 가져온다.
- 화면을 화려하게 만드는 것보다 사용자가 다음 행동을 이해하고 계속하고 싶게 만드는지를 본다.
- 새 변경은 아래 `다음 이터레이션 후보`에 먼저 적고, 구현 후 완료 항목으로 옮긴다.

## 2026-07-19 · v4 학습 루프 이터레이션

### 관찰한 문제

1. 발표 시간 스테퍼가 1분씩 움직여 10분 이상을 맞출 때 반복 클릭이 많다.
2. 리허설 화면에서 녹음 카드가 슬라이드와 같은 비중을 차지해 발표보다 녹음 행위가 주인공처럼 보인다.
3. 질문 코치는 질문과 판정은 좋지만 전체 학습 경로, 다시 만날 개념, 지금까지의 성취가 잘 보이지 않는다.
4. 리허설과 질문 코칭 중간에 안전하게 나갈 수 없어 시작 부담이 크다.
5. 질문을 순서대로 끝내는 흐름은 있지만 놓친 개념을 적절한 시점에 다시 확인하는 학습 사이클은 없다.

### 참고 원칙

말해보카의 공개 서비스 소개에서 다음 구조를 참고한다.

- 문제를 푸는 행동 자체가 게임처럼 가볍게 이어지도록 한다.
- 오답 여부와 난이도에 따라 복습 시점을 조절하고, 잊기 전에 다시 만나게 한다.
- 사용자가 챙기지 않아도 학습 기록과 성장 흐름이 쌓인다.
- 난이도는 답변에 따라 조절하고, 한 번 틀린 것을 세션 안에서 다시 기회로 만든다.

척척발표에는 단어 암기 대신 `발표 개념을 자기 말로 설명하는 능력`으로 번역한다. 점수나 목숨을 추가하지 않고 다음의 루프를 사용한다.

```text
오늘의 목표 확인
→ 발표하기
→ 설명이 빈 개념 발견
→ 질문과 간접 힌트
→ 다른 각도로 재도전
→ 자기 말로 설명
→ 다른 개념 학습
→ 앞 개념을 짧게 다시 설명
→ 최종 분석에 성장과 남은 과제 기록
```

### 결정과 구현 범위

- 발표 시간: `3 · 5 · 10 · 15 · 20 · 30분` 프리셋과 인접 프리셋 이동, 장당 예상 시간을 제공한다.
- 리허설: 16:9 슬라이드를 전체 폭의 주인공으로 두고 녹음은 하단 발표 컨트롤로 축소한다.
- 발표 조작: 이전·다음, 썸네일, 키보드 좌우 방향키를 함께 제공한다.
- 세션 안전성: 각 진행 화면에 `자동 저장됨 · 나가기`를 두고 같은 브라우저 세션에서 상태를 유지한다.
- 질문 코치: 오늘의 목표, 개념별 진행 상태, 이해한 개념 수, 다시 만날 개념 수를 한 화면에 둔다.
- 재도전: 부분 이해와 미이해에서는 다음 질문이 아니라 `다른 질문으로 다시 도전하기`로 안내한다.
- 시차 복습: Temperature를 익힌 뒤 공동 임베딩 정렬을 다시 묻고 통과시킨 다음 Aria로 진행한다.
- 말하기 우선: 녹음 전에는 `말로 답하기`가 주 행동이며, 녹음이 시작된 뒤에만 `답변 마치고 분석하기`를 보여준다.

### 검증 체크

- [x] 1280×900에서 리허설 슬라이드가 첫 화면의 가장 큰 요소다.
- [x] 768×900에서 발표 시간 프리셋과 리허설 컨트롤이 잘리지 않는다.
- [x] 리허설에서 나가기 후 홈에 같은 단계와 슬라이드로 돌아가는 이어하기 카드가 나타난다.
- [x] Q&A 상태를 브라우저 세션에 저장하고 다시 진입할 때 같은 질문 단계를 복원한다.
- [x] 공동 임베딩 정렬을 익힌 뒤 Temperature 다음에 복습 질문이 나타난다.
- [x] 녹음 전에는 분석 CTA가 보이지 않고, 녹음 중에는 분석 CTA가 주 행동이다.

### 검증 결과

- Chrome 1280×900: 발표 시간, 리허설, 시차 복습 질문, 홈 이어하기 화면 확인
- Chrome 768×900: 리허설 슬라이드와 하단 발표 컨트롤, 질문 코치 레이아웃 확인
- 리허설 하단 컨트롤이 첫 화면 밖으로 밀리는 문제를 발견해 고정형 발표 컨트롤로 한 차례 추가 수정
