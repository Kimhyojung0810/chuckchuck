## 2026-07-19 · v4 학습 루프 이터레이션

### 관찰한 문제

1. 발표 시간 스테퍼가 1분씩 움직여 10분 이상을 맞출 때 반복 클릭이 많다.
2. 리허설 화면에서 녹음 카드가 슬라이드와 같은 비중을 차지해 발표보다 녹음 행위가 주인공처럼 보인다.
3. 질문 코치는 질문과 판정은 좋지만 전체 학습 경로, 다시 만날 개념, 지금까지의 성취가 잘 보이지 않는다.
4. 리허설과 질문 코칭 중간에 안전하게 나갈 수 없어 시작 부담이 크다.
5. 질문을 순서대로 끝내는 흐름은 있지만 놓친 개념을 적절한 시점에 다시 확인하는 학습 사이클은 없다.

### 참고 원칙

말해보카의 공개 서비스 소개에서 다음 구조를 참고한다.

- 문제를 푸는 행동 자체가 게임처럼 가볍게 이어지도록 한다.
- 오답 여부와 난이도에 따라 복습 시점을 조절하고, 잊기 전에 다시 만나게 한다.
- 사용자가 챙기지 않아도 학습 기록과 성장 흐름이 쌓인다.
- 난이도는 답변에 따라 조절하고, 한 번 틀린 것을 세션 안에서 다시 기회로 만든다.

척척발표에는 단어 암기 대신 `발표 개념을 자기 말로 설명하는 능력`으로 번역한다. 점수나 목숨을 추가하지 않고 다음의 루프를 사용한다.

```text
오늘의 목표 확인
→ 발표하기
→ 설명이 빈 개념 발견
→ 질문과 간접 힌트
→ 다른 각도로 재도전
→ 자기 말로 설명
→ 다른 개념 학습
→ 앞 개념을 짧게 다시 설명
→ 최종 분석에 성장과 남은 과제 기록
```

### 결정과 구현 범위

- 발표 시간: `3 · 5 · 10 · 15 · 20 · 30분` 프리셋과 인접 프리셋 이동, 장당 예상 시간을 제공한다.
- 리허설: 16:9 슬라이드를 전체 폭의 주인공으로 두고 녹음은 하단 발표 컨트롤로 축소한다.
- 발표 조작: 이전·다음, 썸네일, 키보드 좌우 방향키를 함께 제공한다.
- 세션 안전성: 각 진행 화면에 `자동 저장됨 · 나가기`를 두고 같은 브라우저 세션에서 상태를 유지한다.
- 질문 코치: 오늘의 목표, 개념별 진행 상태, 이해한 개념 수, 다시 만날 개념 수를 한 화면에 둔다.
- 재도전: 부분 이해와 미이해에서는 다음 질문이 아니라 `다른 질문으로 다시 도전하기`로 안내한다.
- 시차 복습: Temperature를 익힌 뒤 공동 임베딩 정렬을 다시 묻고 통과시킨 다음 Aria로 진행한다.
- 말하기 우선: 녹음 전에는 `말로 답하기`가 주 행동이며, 녹음이 시작된 뒤에만 `답변 마치고 분석하기`를 보여준다.

### 검증 체크

- [x] 1280×900에서 리허설 슬라이드가 첫 화면의 가장 큰 요소다.
- [x] 768×900에서 발표 시간 프리셋과 리허설 컨트롤이 잘리지 않는다.
- [x] 리허설에서 나가기 후 홈에 같은 단계와 슬라이드로 돌아가는 이어하기 카드가 나타난다.
- [x] Q&A 상태를 브라우저 세션에 저장하고 다시 진입할 때 같은 질문 단계를 복원한다.
- [x] 공동 임베딩 정렬을 익힌 뒤 Temperature 다음에 복습 질문이 나타난다.
- [x] 녹음 전에는 분석 CTA가 보이지 않고, 녹음 중에는 분석 CTA가 주 행동이다.

### 검증 결과

- Chrome 1280×900: 발표 시간, 리허설, 시차 복습 질문, 홈 이어하기 화면 확인
- Chrome 768×900: 리허설 슬라이드와 하단 발표 컨트롤, 질문 코치 레이아웃 확인
- 리허설 하단 컨트롤이 첫 화면 밖으로 밀리는 문제를 발견해 고정형 발표 컨트롤로 한 차례 추가 수정

## 2026-08-05 · 딥그린 디자인 시스템 이식

### 배경

디자인 시안 `척척발표통합.html`(단일 파일 목업)의 시각 언어를 데모에 반영하기로 했다. 시안은 랜딩과 `#/archive` · `#/technology` 를 포함한 6개 화면짜리 제품 사이트지만, 이번에는 **색·타이포·패널 스타일만** 가져오고 정보 구조와 기능은 건드리지 않기로 정했다.

### 관찰한 문제

1. 시안의 디자인 언어가 `MVP_SPEC.md` §3의 금지 조항(히어로·glow·스크롤 애니메이션)과 정면 충돌해, 문서를 고치지 않으면 코드와 스펙이 어긋난다.
2. 토스 블루가 토큰 밖 리터럴로 CSS 13곳·JS 4곳에 흩어져 있어 `:root` 만 바꾸면 색이 새어 나온다.
3. `#8B95A1` · `#B0B8C1` · `#C6CCD3` 같은 한색 중성 그레이가 토큰과 중복 정의돼 있어, 따뜻한 종이 배경 위에서 푸르게 뜬다.

### 결정과 구현 범위

- `:root` 를 딥그린 팔레트로 교체하고 `--navy` · `--brand*` · `--cyan` · `--paper` · `--line` · `--shadow-panel` 을 추가했다.
- 기존 규칙 1,500여 줄이 참조하는 `--blue*` 는 지우지 않고 `--brand*` 를 가리키는 **레거시 별칭**으로 남겼다. 이름을 바꾸면 3개 CSS + `app.js` + iframe 페이지를 동시에 손대야 해서 회귀 위험이 커진다.
- 흩어진 리터럴을 토큰으로 회수하고, 한색 중성 그레이는 난색 등가값으로 바꿨다.
- `.card` 를 흰 배경 + 얇은 그림자에서 종이색(`--paper`) + 2단 그림자(`--shadow-panel`)로 바꿔 시안의 패널 느낌을 전 화면에 적용했다.
- `f11_reveal.html` 은 iframe 이라 `app.css` 를 상속받지 않으므로 자체 `:root` 4벌의 `--primary` 를 따로 맞췄다. 다크 테마는 어두운 면 위 가독성을 위해 `--cyan` 을 쓴다.
- **하지 않은 것:** 랜딩, `#/archive` · `#/technology`, 스크롤 고정형 쇼케이스(`#alignTrack`), Motion 라이브러리, `JJ Sans` 서브셋 폰트. 라우터 · PDF.js · SDK 녹음 · `bridge.py` 연동은 한 줄도 바꾸지 않았다.

### 유지한 판단

- **서체는 Pretendard 하나.** 시안의 `JJ Sans` 는 650자 서브셋을 base64 로 약 330KB 인라인한 것이라, IMU2CLIP 논문 용어와 발화 인용을 넣으면 글자가 깨진다.
- **`om`(정당한 생략) 은 시안의 올리브(`#8A6A15`)를 따랐다.** 중성 회색이 더 안전하지만 시안의 의미 체계를 그대로 받기로 했다.
- **`ct`(자료와 모순) 는 시안과 달리 보라 계열을 유지했다.** 시안은 `ct` 를 `no` 와 같은 빨강으로 합쳤는데, 그러면 `안 나옴` 과 `자료와 모순` 이 구분되지 않아 판정 정보가 줄어든다.
- **`mapSvgString()` 만 리터럴 hex를 유지했다.** 이 SVG 는 파일로 내려받히므로 `:root` 가 없어 `var()` 가 풀리지 않는다.

### 검증 결과

- Chrome 헤드리스 1280px: `#/` · `#/new` · `#/qa` · `#/report` · `#/about` 5개 라우트 렌더링 확인
- 리포트 6개 탭과 슬라이드 뷰어, 판정 칩 5종, 성장 차트 SVG 그라디언트 정상
- `#3182F6` · `#1B64DA` · `#EBF2FF` 계열 리터럴 잔여 0건 (`css/app.css` · `js/*.js` · `*.html`)

### 이어서 한 일 — 장면 전환 커튼 제거

라우팅마다 400ms 커튼 와이프가 화면을 가려 이동이 느리게 읽혔다. `curtainWipe()` · `WIPE_MS` · `wipeEl` 과 `route()` 의 호출, 죽은 `.tw-wipe` 규칙과 `@keyframes twLeft/twRight` 를 걷어냈다. 전환 연출 없이 즉시 교체한다.

`.bs-curtain`(무대 배경 커튼)과 `curtainCallCopy()`(커튼콜)는 전환 연출이 아니라 별개 UI라 남겼다.

### 이어서 한 일 — 랜딩 페이지 추가 (`#/landing`)

`#/` 를 랜딩으로 바꾸지 않고 `#/landing` 을 새 라우트로 얹었다. 기존 5개 라우트가 그대로라 회귀 위험이 거의 없고, 나중에 첫 화면을 랜딩으로 돌리기도 쉽다.

**스크롤 애니메이션 판단.** 시안의 정렬 쇼케이스는 `#alignTrack{height:300vh}` 안에서 `scrollY` 로 진행도를 만드는 스크롤 하이재킹이었다. 그런데 `renderAlign(p)` 이 **진행도 `p` 하나만 받는 순수 함수**라 연출과 구동원이 이미 분리돼 있었고, 시안 자체가 `reduceMotion` 일 때 `renderAlign(.99)` 로 떨어지는 경로를 갖고 있었다. 그래서 300vh 트랙과 sticky 무대만 걷어내고 완성 상태로 한 번 그리는 쪽을 택했다. 3화면을 스크롤해도 페이지가 안 넘어가는 문제가 사라지고, 슬라이드별 시간·타임라인 마커·구간 요약·판정 칩은 그대로 남는다.

`[data-reveal]` 등장 효과는 유지했다. 스크롤 위치에 연동되지 않고 뷰포트 진입 시 1회 페이드하는 IntersectionObserver라, 금지 대상인 스크롤 연동 애니메이션과 다르다.

**이식 중 걸린 것**

- 섹션별로 함수를 감싸다가 구역 간 공유 상수(`J_STATUS`)가 스코프 밖으로 나가 워크벤치 초기화가 통째로 중단됐다. 모듈 스코프로 올려 해결.
- CSS를 추릴 때 정적 마크업의 클래스만 기준으로 삼아, JS가 런타임에 만드는 클래스(`.y` · `.n` 등)의 규칙이 빠졌다. 판정 아이콘이 거대하게 렌더링돼서 발견. 랜딩 JS의 템플릿 문자열까지 포함해 재추출.
- `assets/demo_recording.m4a` 는 저장소에 없어서 `demoAudio = null` 로 두고 시뮬레이션 재생으로 떨어뜨렸다.

**검증** — 6개 구역(hero · exampleSec · alignTrack · judgeSec · demoSec · start) 전부 렌더링, 콘솔 오류 0건, 1280px·768px 오버플로 없음, 기존 5개 라우트 콘솔 오류 0건.

### 이어서 한 일 — 랜딩 입구 연결

상단 바 로고(`.brand`)를 `#/` 대신 `#/landing` 으로 걸었다. `#/about` 보다 로고 쪽이 자연스럽고, 새 링크를 늘리지 않고 이미 있는 요소를 쓴다.

로고는 원래 `wireSendoff()` 의 위임 셀렉터 `a[href="#/"]` 에 잡혀 리포트를 떠날 때 배웅 연출을 띄웠다. href 만 바꾸면 그 연출이 조용히 사라지므로 셀렉터에 `a[href="#/landing"]` 을 함께 넣었다.

### 남은 일

- `theater.css` · `chatter.css` 의 극장 모티브 팔레트(크림슨 `오늘 개관!` 배지, 한색 그레이)는 딥그린과 따로 논다. 별도 모티브로 유지할지 통일할지 결정 필요.
- 시안의 흐름 비교 패널(자료 의도 흐름 vs 실제 발화 흐름 2레인 + SVG 엣지)은 현재 `rLogic` 에 없는 새 기능이다. 도입 여부 미정.
- 수면의 질 데모 세션은 슬라이드 8장과 녹음 파일을 받은 뒤 추가한다. 랜딩은 이미 수면의 질 서사로 돼 있어 앱 화면(IMU2CLIP)과 주제가 다르다.
- 로고를 랜딩으로 돌리면서 상단 바에서 `#/`(내 발표 목록)로 가는 링크가 사라졌다. 각 화면 안의 `← 내 발표로 돌아가기` 로만 갈 수 있다. 랜딩 CTA 를 `#/` 로 잇거나 상단 바에 홈 링크를 하나 더 둘지 정해야 한다.
