## 이번에 쓸 TDS 규격 (TDS.md 에서 뽑은 것)

지어내지 않는다. 아래는 `TDS.md` 원문 기준이다.

**Button** (TDS.md:2412)
- `size`: `small` · `medium` · `large` · `xlarge`
- `variant`: `fill`(채도가 높아 주요 액션 강조) · `weak`
- 한 화면에 `fill` 은 하나. 나머지는 `weak` 이나 TextButton.

**ListRow** (TDS.md:14701)
- `left`(아이콘·이미지) / `contents`(주요 텍스트) / `right`(부가 정보·상호작용) **세 영역**
- 텍스트 레이아웃 타입: `1RowTypeA~C` · `2RowTypeA/D` · `3RowTypeA/C`
- 누를 수 있으면 터치 효과와 화살표를 준다 — "동작을 쉽게 예측할 수 있고"

**Badge** (TDS.md:933)
- "항목의 상태를 빠르게 인식할 수 있도록 강조" — 상태 표시 전용. 라벨로 쓰지 않는다.

## 2. 「질문 코칭 시간을 골라주세요」 화면이 허전하다 🟡

**증거** — `.qa-quick` 카드 253px 가 764px 예산 한가운데 떠 있다. 카드 하나 말고는 아무것도 없다.

**문제**

- 카드 세 장이 그냥 네모다. TDS ListRow 의 세 영역 구조가 아니라 정보 위계가 없다.
- 세 장 모두 같은 무게 — 무엇이 기본값인지 안 보인다.
- 「이 설정으로 시작하기 · 최대 7개 개념 · 약 10분」 CTA 에 정보가 너무 많다. 토스 다크패턴 §5: *"CTA 위에 과장되거나 중복된 보조 설명을 함께 노출하면 버튼의 역할이 흐려진다."*

**사용자 제안(검토 필요)** — *"간단 결과 보여줄 때 이거 나오면 좋을듯"*
→ 이 선택 화면을 독립 화면으로 두지 말고, **4단계 「질문 준비」가 끝나 결과를 보여주는 그 자리**에 붙이는 안.
장점: 화면 하나가 줄고, 준비된 개념 수를 보면서 시간을 고르니 선택에 근거가 생긴다.
확인할 것: `MVP_SPEC.md` §5.2 4단계가 *"완료 후 사용자가 「질문 코칭 시작하기」를 눌러 `#/qa` 로 이동한다. 자동 이동하지 않는다"* 로 정해 둔 흐름과 충돌하는지.

**할 일**

- [x] ListRow 3영역 — left=시간(1·5·10분) / contents=무엇을 하는지 / right=범위 + 선택 체크
- [x] 고른 행만 브랜드색 + 체크 표시. 나머지는 중립 — 무엇이 골라졌는지 한눈에 보인다
- [x] CTA 「이 설정으로 시작하기 · 최대 7개 개념 · 약 10분」 → 「질문 코칭 시작하기」 (토스 다크패턴 §5)

## 3. 「실전 질문 코칭 결과」가 와닿지 않는다 🔴

**증거** — `js/qa_live.js` 의 `qaLiveEnd()`

**문제 네 가지**

1. **`0 / 6` 하나로 끝난다.** 0이 왜 0인지, 이제 뭘 해야 하는지가 없다.
   비교: 소크라테스식 코칭 종료 화면은 `질문 전 3/5 → 질문 후 5/5` 로 **변화**를 보여준다 (`MVP_SPEC.md` §5.3).
   실전 코칭 결과에도 같은 축이 필요하다.
2. **여섯 줄이 전부 똑같이 생겼다.** 각 행이 LLM 이 만든 긴 질문 원문을 그대로 담고, 여섯 개 모두 "…설명해 주시겠어요?" 로 끝난다. 벽처럼 읽힌다.
3. **묶여 있지 않다.** 미방어 · 넘김 · 설득 완료가 한 줄로 섞여 있어서 "어디부터 손대야 하는지" 가 안 보인다.
4. **행이 눌리지 않는다.** 상세 리포트로 가려면 맨 아래 버튼 하나뿐. TDS ListRow 는 누를 수 있으면 화살표와 터치 효과를 준다.

## 5. 엑사원이 객석에 안 나온다 🔴 원인 확정

**증상** — 척척극장 객석에 엑사원만 늘 "오늘 객석에 못 왔어요" 로 뜬다.

**원인** — `chuckchuck/f12_chatter.py:496` 의 `_ask()` 가 `json_mode` 를 안 넘긴다.

```python
raw = engine.complete(
    system=system + nudge, user=user, temperature=0.8, max_tokens=1024
)   # ← json_mode=True 가 없다
```

다른 모듈은 전부 넘긴다 — `f07_graph.py:599` · `f08_questions.py:457` · `f09_judge.py:552` · `f11_align.py:437` · `f14_rubric.py:409`. **f12 만 빠졌다.**

엑사원은 추론 모델이라 `json_mode` 가 없으면 사고 과정을 그대로 출력한다.
`max_tokens=1024` 가 그 사고 과정 중간을 잘라서 JSON 에 닿지도 못하고,
`extract_json_object()` 가 ValueError → 재시도 1회도 같은 이유로 실패 → `[]` 반환 →
`absent` 로 분류 → "엑사원은 오늘 객석에 못 왔어요".

**실측 (2026-08-06)**

| 호출 | 걸린 시간 | 결과 |
|---|---|---|
| 지금 (`json_mode` 없음) | 9.3초 | `"Okay, let me try to figure out…"` → JSON 추출 실패 → 결석 |
| `json_mode=True` 추가 | 7.4초 | **JSON 추출 성공, turns=1** |

네 모델 응답 속도 비교 (같은 프롬프트, 개념 추출)

| 모델 | json_mode=True | json_mode=False |
|---|---|---|
| solar | 1.5초 | 0.5초 |
| ax | 0.6초 | 0.7초 |
| midm | 0.5초 | 0.3초 |
| **exaone** | **23.0초** | **31.3초** (18,604자 산문) |
