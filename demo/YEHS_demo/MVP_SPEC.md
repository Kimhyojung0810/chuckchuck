# 척척발표 MVP 구현 스펙 v4

> 이 문서가 유일한 구현 기준이다. 이전 스펙과 데일리핏 mock 시나리오는 폐기한다.

구현 중 내린 세부 UX 결정과 검증 결과는 `UX_ITERATION_LOG.md`에 누적한다. 두 문서가 충돌하면 이 문서를 우선한다.

## 1. 제품 정의

척척발표는 발표 점수만 계산하는 도구가 아니다. 사용자의 발표자료와 실제 발표를 함께 이해한 AI가 설명이 빈 개념을 질문하고, 사용자가 자기 말로 설명할 수 있을 때까지 소크라테스식으로 코칭한 뒤 최종 분석을 제공하는 서비스다.

핵심 여정은 반드시 다음 순서를 따른다.

```text
자료 업로드
→ 발표 정보 입력
→ 실제 슬라이드를 보며 리허설 녹음
→ 자료 + 발표 STT로 질문 준비
→ 소크라테스식 Q&A 코칭과 시차 복습
→ 발표 + Q&A 통합 최종 분석
```

- 최종 분석 전 Q&A는 선택 기능이 아니라 필수 코칭 단계다.
- AI 질문은 발표자료의 개념 트리, 발표 STT, 앞선 Q&A 답변을 모두 근거로 만든다.
- 정답을 바로 말하지 않는다. `질문 → 간접 힌트 → 개념 재구성 → 자기 말로 다시 설명`을 반복한다.
- 모든 판정과 제안에 슬라이드 번호, 실제 발화, 타임코드를 붙인다.
- 사용자는 리허설과 Q&A 도중 언제든 저장하고 나갈 수 있고, 같은 브라우저 세션에서 이어서 할 수 있다.
- 진행률은 단순 대화 횟수가 아니라 `처음 만남 → 재질문 → 자기 말로 설명 → 시차 복습 → 이해함`의 학습 상태로 보여준다.
- 점수·하트·목숨 같은 외재적 보상보다 개념 이해, 다시 만날 항목, 다음 단계가 보이는 내재적 진행감을 우선한다.
- 백엔드는 없다. STT와 AI 판정은 mock 시나리오로 동작한다.

## 2. 기준 발표자료

MVP 기본 자료는 `250729 IMU2CLIP_Pulbic.pdf`다.

- 23장, 16:9 논문 리뷰 발표자료다.
- `assets/slides/imu2clip/slide-01.webp`부터 `slide-23.webp`까지 렌더링해서 사용한다.
- 리허설 화면과 업로드 결과 썸네일은 플레이스홀더가 아니라 이 실제 슬라이드를 보여준다.
- `260113 Hierarchical VLA.pdf`는 35장이라 현재 30장 제한을 넘으므로 기본 시나리오에서 사용하지 않는다.

## 3. 디자인 원칙

분석 전 화면은 실제 출시된 데스크톱 도구처럼 절제한다.

- 따뜻한 오프화이트 배경 위 종이 질감 패널, 1px 보더, 딥그린 한 가지 액센트
- 정보 밀도 있는 리스트와 표
- 히어로, 마케팅 카피, 장식 이모지, glassmorphism, 스크롤 연동 애니메이션 금지
- 상태 색은 판정 칩과 상태 점에만 사용
- 해요체와 결과를 예측할 수 있는 CTA 사용
- 한 화면의 주인공은 하나로 제한한다. 리허설에서는 슬라이드와 발표가 주인공이며 녹음 상태는 보조 컨트롤이다.
- **기준 해상도는 아이패드 가로 1180 × 820 하나다.** 1024 × 768 ~ 1366 × 1024 는 기기별 레이아웃이 아니라 스케일로 대응한다 (토스 해상도 가이드). 세로 예산은 상단 바 56px 을 뺀 764px 이고, 각 화면의 주인공과 다음 버튼은 이 안에 들어와야 한다. 홈·새 발표·질문 코칭은 페이지 스크롤이 0 이어야 하며, 리포트·판단 방식·랜딩만 스크롤한다.
- 딥그린은 현재 행동, 완료, 이해한 개념에만 쓴다. 반복 학습은 실패가 아니라 `다시 만나요` 상태로 중립적으로 표현한다.
- 최종 분석 화면에 한해 데이터 변화를 강조하는 딥그린 배경, 숫자 강조, 450ms 이내의 완료 전환을 허용한다.
- 최종 분석의 시각 효과도 장식이 아니라 `질문 전 → 질문 후`, 개선된 개념, 남은 과제를 강조해야 한다.

### 디자인 토큰

`css/app.css` 의 `:root` 가 단일 원본이다. 이 문서의 블록은 그 사본이며, 둘이 어긋나면 코드를 기준으로 이 문서를 고친다.

```css
:root {
  --navy:#12362D; --navy-deep:#0B241E;
  --brand:#1F7A5F; --brand-strong:#0E352A; --brand-weak:#E9F4EE;
  --cyan:#58C9A2; --mint:#A8E0C8; --yellow:#F0B429;
  --canvas:#F5F5F5; --surface:#FFFFFF; --paper:#FAF9F6;
  --fill:#F0F3F0; --border:#E2E7E3; --line:rgba(31,64,52,.12);
  --text:#16211C; --text-2:#46584F; --text-3:#8AA295;
  --ok:#0A8F68; --ok-bg:#E9F7EF;
  --mid:#B45309; --mid-bg:#FDF6E3;
  --no:#DC2626; --no-bg:#FDF0EF;
  --ct:#9333EA; --ct-bg:#F6EDFD;
  --om:#8A6A15; --om-bg:#F7F1DE;
}
```

- `--blue` · `--blue-strong` · `--blue-weak` 는 `--brand*` 를 가리키는 레거시 별칭으로만 남아 있다. 새 규칙에는 `--brand*` 를 쓴다.
- 서체는 Pretendard 하나를 유지한다. 원본 시안의 `JJ Sans` 서브셋은 650자 제한이라 논문 용어와 발화 인용에서 글자가 깨지므로 쓰지 않는다.
- 다운로드되는 SVG(`mapSvgString()`)는 `:root` 컨텍스트가 없어 CSS 변수가 풀리지 않는다. 그 안에서만 리터럴 hex를 쓰고 위 판정 색과 같은 값을 유지한다.

## 4. 정보 구조

```text
#/         내 발표 목록
#/landing  서비스 소개 랜딩
#/new      자료 업로드 → 발표 정보 → 리허설 → 질문 준비
#/qa       발표 직후 필수 소크라테스식 Q&A
#/report   발표와 Q&A를 합친 최종 분석
#/about    서비스 판단 방식과 기술 후보
```

- 고정 상단 바에는 로고, `새 발표 연습`, 사용자 아바타만 둔다.
- 사이드바는 만들지 않는다.
- 좁은 화면 기본 최대 폭은 980px, 리포트는 1080px, 폼·Q&A는 640px다. 랜딩만 전면폭을 쓴다.
- **가로형(900px 이상)에서는 `css/tablet.css` 가 이 폭을 대신한다.** 본문은 `--shell`(최대 1320px, 좌우 여백 제외), 폼과 Q&A 시작 화면은 880px 다. 1180px 화면에 980px 한 줄만 쓰면 좌우가 죽고 주인공이 접히기 때문이다.

랜딩은 `#/landing` 에 따로 둔다. `#/` 는 로그인한 사용자의 `내 발표` 목록을 유지하며, 랜딩이 첫 화면을 대신하지 않는다.

디자인 시안 `척척발표통합.html` 의 `#/archive` · `#/technology` 페이지는 채택하지 않는다. 랜딩은 시안의 6개 구역(히어로 · 자료와 발화의 차이 · 발화 시간 정렬 · 개념 판정 · 연습 도구 · 시작하기)을 그대로 가져오되, 정렬 구역의 300vh 스크롤 하이재킹은 걷어내고 완성 상태로 고정한다.

랜딩은 전부 인라인 상수로 동작하는 시연이다. `DATA` 나 `bridge.py` 를 읽지 않으므로 앱 화면의 실데이터 경로와 섞이지 않는다.

## 5. 화면 스펙

### 5.1 홈

- 제목은 `내 발표`다.
- 발표 목록은 테이블형 행으로 표시한다.
- 첫 행은 `IMU2CLIP 논문 리뷰 · 학회·수업 발표 · 23장 · Q&A로 공동 임베딩 정렬 이해`다.
- 각 행은 고유 세션 ID를 가지며 `#/report/{sessionId}`로 이동한다. 모든 행을 IMU2CLIP 리포트로 연결하면 실패다.
- IMU2CLIP은 전체 5탭 리포트를 제공한다. 나머지 과거 발표는 해당 주제에 맞는 점수·Q&A 변화·근거 발화 3개·다음 보완 3개를 보여주는 요약 리포트를 제공한다.
- 과거 발표 주제는 Hierarchical VLA 논문 리뷰, 척척발표 서비스 피치, 2분기 제품 성과 보고, 소비 트렌드 세미나다.
- 하단 작은 링크로만 `#/about`에 진입한다.

### 5.2 새 발표

상단 단계는 `자료 올리기 · 발표 정보 · 리허설 녹음 · 질문 준비`다.

#### 1단계: 자료 올리기

- `.pdf`, `.pptx`, 최대 30MB, 30장까지
- 샘플 선택 시 `250729 IMU2CLIP_Pulbic.pdf`를 파싱한다.
- 성공 시 실제 슬라이드 23장 썸네일과 제목을 보여준다.
- 9번처럼 도식 중심인 장은 경고 보더와 `발표 때 말한 내용으로 구조를 보완할게요`를 표시한다.
- 형식 오류 시 다른 파일을 올리도록 안내한다.

#### 2단계: 발표 정보

- 상황: `사내 보고 · 학회·수업 발표 · 대회·IR 피칭 · 범용`
- 자유 입력과 3~30분 발표 시간 선택
- 발표 시간은 `3 · 5 · 10 · 15 · 20 · 30분` 빠른 선택을 제공한다.
- 미세 조정 버튼은 1분씩 반복 클릭하게 하지 않고 인접 프리셋 단위로 이동한다.
- 선택한 시간과 슬라이드 수를 바탕으로 `23장 기준 장당 약 26초`처럼 속도를 미리 안내한다.
- 입력은 선택 사항이며 건너뛰면 범용으로 처리한다.

#### 3단계: 리허설 녹음

- 실제 IMU2CLIP 슬라이드를 큰 16:9 화면으로 보여준다.
- 녹음 카드를 슬라이드 옆에 동등한 크기로 두지 않는다. 슬라이드는 전체 폭에 가깝게 확장하고 녹음은 아래의 얇은 발표 컨트롤로 둔다.
- 이전·다음 버튼, 현재 번호, 제목, 23장 썸네일 필름을 제공한다.
- 키보드 좌우 방향키로도 슬라이드를 넘길 수 있다.
- 슬라이드 이동 시 `02:04 → 4번 슬라이드`를 기록한다.
- 재방문은 `02:57 ↩ 2번 슬라이드 (2번째 방문)`처럼 별도 회차로 보존한다.
- 마이크 요청 전, 권한 거부, 녹음 중 상태를 실제 UI로 구현한다.
- 녹음은 분석에만 사용한다고 안내한다.

#### 4단계: 질문 준비

최종 분석 단계가 아니다. 발표자료와 발표 STT를 결합해 Q&A를 준비한다.

1. 음성을 글로 바꿔요.
2. 슬라이드별로 발화를 나눠요.
3. 개념 트리와 실제 발화를 대조해요.
4. 먼저 확인할 질문을 만들어요.

완료 후 사용자가 `질문 코칭 시작하기`를 눌러 `#/qa`로 이동한다. 자동 이동하지 않는다.

### 5.3 Q&A 코칭

- 헤더: `발표를 들은 AI와 질문 코칭 · IMU2CLIP 논문 리뷰`
- 청중은 교수님, 심사위원, 회사 상사, 일반 청중 중 선택한다.
- 화면 상단에는 오늘 익힐 개념 수, 현재 단계, 이해한 개념, 다시 만날 개념을 보여준다.
- 개념 진행 바는 각 개념을 `예정 · 진행 중 · 이해함 · 다시 만나요` 상태로 표현한다.
- 질문마다 개념 경로와 근거 슬라이드를 표시한다.
- 사용자는 말로 답하고 `답변 분석하기`를 누른다.
- mock STT 답변을 `답변에서 들은 말`로 보여준다.
- 부분 이해면 빠진 이유나 관계만 다시 묻는다.
- 막히면 정답 대신 간접 힌트를 단계적으로 준다.
- 세 번째에는 반드시 자기 말로 처음부터 다시 설명하게 한다.
- 성공하면 `대화로 이해함`으로 기록한다. 사용자가 직접 `나중에 연습하기`를 고른 개념만 추가 연습으로 남긴다.
- 이해한 핵심 개념은 다른 개념을 학습한 뒤 한 번 더 질문한다. 이 시차 복습을 통과해야 세션의 최종 `이해함`으로 기록한다.
- 부분 이해와 미이해 뒤 CTA는 `다른 질문으로 다시 도전하기`로 표시해 같은 실패를 반복한다는 인상을 줄인다.
- 항상 `이 개념은 나중에 연습하기`로 빠져나올 수 있다.

MVP 시나리오:

1. 세 모달리티를 함께 정렬하는 이유를 부분적으로 답한다.
2. 공동 임베딩 정렬의 이유를 설명하지 못한다.
3. 자전거 예시로 각 모달리티의 역할을 찾는다.
4. 자기 말로 다시 설명해 `공동 임베딩 정렬`을 이해한다.
5. Temperature Parameter의 방향을 찾는다.
6. 힌트 뒤 수식과 학습 효과를 자기 말로 다시 설명한다.
7. 앞에서 익힌 공동 임베딩 정렬을 짧게 다시 설명해 시차 복습을 통과한다.
8. Aria 데이터셋의 의미를 설명하고 종료한다.

종료 화면은 두 블록으로 나눈다.

1. `스스로 점검한 결과`: 질문 전 3/5 → 질문 후 5/5, 대화로 이해한 개념과 다음 발표에서 연습할 개념
2. `발표에 가져갈 것`: Q&A에서 완성한 발표 문장 + `최종 분석 보기`

### 5.4 최종 분석

Q&A 뒤에만 도달하는 결과 화면이다. 헤더에 `발표 + 질문 코칭 최종 분석`을 표시한다.

요약 최상단:

- 질문 전 설명 가능 `3/5`
- 질문 후 설명 가능 `5/5`
- 대화로 이해한 개념 `공동 임베딩 정렬 · Temperature Parameter`
- 다음 발표 연습 `IMU Encoder`

탭은 다음 5개다.

1. 요약: 종합 점수, 한 줄 코멘트, 발표 타임라인, 우선 보완 3가지
2. 개념별 판정: 개념 트리, 상태, confidence, 체크 항목, 근거 발화, 슬라이드, 보완 문장
3. 논리 흐름: 연결 멘트 없음, 근거 점프, 잘된 연결
4. 말 속도: 구간별 속도와 보조 분석 시간 배분
5. 연습 도구: 개요 이미지, 펀치라인, 용어 카드

판정 결과는 발표 STT와 Q&A를 구분해서 보여준다. Q&A에서 이해한 개념도 발표 당시 판정 자체를 지우지 않고 `발표에서는 언급만 함 → 대화로 이해함`으로 변화가 보이게 한다.

### 5.5 서비스 정보

- 문서 파싱만 확정 기술로 표시한다.
- STT는 SKT A.X 계열 검증 중이다.
- 질문·판정 모델은 후보 테스트 중이다.
- 계산 가능한 말 속도와 시간 배분은 AI를 사용하지 않는다.
- 자료와 녹음은 분석에만 사용하며 보존·폐기 정책은 TBD다.

## 6. 데이터 기준

구현 데이터의 단일 원본은 `js/data.js`다.

- 세션: IMU2CLIP 논문 리뷰, 23장, 10분 18초, 2번째 연습
- 종합 86점, 내용 이해 84, 논리 흐름 82, 말 속도 91
- 개념 트리: Self-Supervised Learning, Contrastive Learning, CLIP, 공동 임베딩 정렬, 세 가지 Contrastive Pair, IMU Encoder, Temperature Parameter, Cross-Entropy Loss, Aria 데이터셋 등
- Q&A 전후: 3/5 → 5/5
- 대화로 이해함: 공동 임베딩 정렬 · Temperature Parameter
- 다음 발표 연습: IMU Encoder
- 자료와 모순: Aria에 text narration이 있다고 잘못 말한 발화

화면 문구와 질문은 이 데이터와 일치해야 한다. 데일리핏, 네트워크 효과, 이탈률 등 이전 mock 데이터가 화면에 남으면 실패다.

## 8. 완료 체크리스트

- [ ] 홈에 랜딩이나 히어로가 없다.
- [ ] 내 발표 목록의 다섯 행이 서로 다른 세션 ID와 주제별 리포트로 연결된다.
- [ ] 업로드 성공 화면에 실제 IMU2CLIP 23장 썸네일이 보인다.
- [ ] 녹음 화면에 실제 슬라이드, 이전·다음, 썸네일 필름, 재방문 로그가 동작한다.
