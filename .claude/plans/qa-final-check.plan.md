### 버그 재현 경로 (코드로 확인함)

`resetQa()` 호출 지점은 6곳인데 **자료 업로드 경로에 없다.**

- `app.js:287` `startFreshPractice()` — 탑바 「새 발표 연습」
- `app.js:346` `route()` — `#/new/reset` 이거나 `nf.completed` 일 때만
- `app.js:3469` 녹음 다시 하기
- `app.js:6154` 코칭 길이 바꾸기
- `app.js:6749`, `7131` 스크립트 데모 경로

`startParse()`(app.js:1377) → `applySlideDoc()`(app.js:1202) 어디에도 `resetQa()` 가 없다.
`nf.completed` 는 `qaLiveEnd()` 만 세운다. 따라서:

```
분석 끝 → #/qa 에서 2문제 답함 (nf.completed = false)
  → 뒤로 가서 #/new 에 새 PDF 업로드   ← route() 가드가 안 걸린다
  → 새 분석 끝 → #/qa
  → ensureLiveQuestions() 가 qaLiveActive() 만 보고 그냥 return false
  → 지난 발표의 질문·대화가 그대로 뜬다
```

**게다가 `FLAT_QA_SESSION_ID = 'flat'` 은 상수라 서버 쪽 아티팩트도 같은 키로 덮인다.**
새 자료의 그래프 위에서 **옛 자료의 `node_id`** 로 판정이 돌 수 있다 —
"내 자료로 도는 것처럼 보이는데 남의 자료가 나온다" 의 QA 판 재발이다.

### W2 — 새 발표 = 새 QA 세션 🔴

두 겹으로 막는다. 하나는 확실한 지점, 하나는 모든 경로를 덮는 그물.

**(a) 지문(fingerprint) 으로 낡음을 감지한다 — 주 방어**

`route()` 에 가드를 더 붙이지 않는다. `#/new` 로 들어오는 길이 너무 많고
(뒤로가기·주소 직타·리포트 링크), 새로고침도 넘어야 한다.
**자료의 정체성이 바뀌는 지점**에 건다.

- `newLiveState()` 에 `docKey` 를 하나 넣는다 — `file_name + total_slides`
  (또는 graph 의 `file_name`). `nf.slideDocMeta` 에 이미 둘 다 있다.
- `qaLiveActive()` 가 `docKey` 불일치를 낡음으로 본다 → `ensureLiveQuestions()`
  가 새로 만든다.
- 옛 세션엔 `docKey` 가 없다 → `undefined` 는 낡음으로 치지 않는다 (진행 중
  코칭을 새로고침 한 번에 날리지 않기 위해).

**(b) 업로드 경로에서 그냥 지운다 — 벨트**

`applySlideDoc()` 안에서 `docKey` 가 바뀌었으면 `resetQa()`.
`applySlideDoc` 은 `startParse` 와 캐시 재사용 경로가 **둘 다** 지나는 유일한 지점이다.

**(c) 서버 쪽 세션 키 — 확인 완료. 지금은 새는 데가 없다. 선택 사항이다.**

`session_id` 는 `SessionStore._sessions` (`demo/session_store.py:77`) 의 **dict 키**
하나다. `MAX_SESSIONS = 32` LRU · `TTL_SEC = 6시간`. `'flat'` → `'flat:<해시>'` 로
바꾸는 비용은 키가 몇 개 더 생기는 것뿐이고, 데모 한 번에 32개를 넘길 일이 없다.

무엇을 막아 주나: `put_artifacts` 는 **덮어쓰기가 아니라 병합**이라, 프론트가
안 보낸 `ARTIFACT_KEYS` 항목은 이전 발표 값이 그대로 남는다. 그 버그가 실제로
있었고 docstring 88~91행에 기록돼 있다 — "발표 A 의 flow 가 발표 B 의 질문·판정
근거로 섞여 들어갔다". 그때 **명시적 `None` 은 지운다**로 막았다.

그리고 `liveArtifacts()`(qa_live.js:118)는 **다섯 키를 늘 보낸다** — 없으면
명시적 `null` 로. 즉 **지금 새는 데는 없다.** 세션 키를 나누는 것은 앞으로
일부만 보내는 호출자가 생겼을 때를 위한 보험이지, 오늘 깨진 것을 고치는 게 아니다.

→ **마감 전에는 (a)+(b) 클라이언트만 한다.** (c) 는 마감 뒤.

**(d) qa-history 는 손대지 않는다.** 다만 기록 목록이 **어느 발표인지**
라벨을 안 달고 있으면 그것만 한 줄 붙인다 (`qa-history.js`, 확인 필요).

**결론 3 — 그런데 이 중복은 5분 트랙에서만 나온다.** 같은 자료를 기본 트랙(10분,

→ **마감 전에 `_normalize_questions` 에 중복 제거 게이트를 넣지 않는다.**
기본 경로에서 재현되지 않는 문제에 마지막 오후를 쓰는 것이 되고, 게이트가
멀쩡한 질문을 떨어뜨릴 위험이 이득보다 크다. 5분 트랙을 고르는 경우에만
나타난다는 것을 알고 시연하면 된다.

**마감 뒤에 고칠 곳**: `_spread_adjacent` 다음이 아니라 **질문을 받아 온 뒤**다.
`_normalize_questions` 결과에서 `answer_gist` 가 서로 많이 겹치는 질문을

### W7 — PPT 와 다른 내용의 녹음본을 올리면 아예 인식을 못 한다 🔴 (2026-08-08 사용자 제보)

**원인을 저장된 fixture 에서 그대로 재현했다.**
`fixtures/raw/척척발표_수면발표_정상슬라이드.transcript.json` 이 바로 그 경우다 —
수면 슬라이드(8장)에 집중·알림 발표 녹음이 붙어 있다.

```
marks_estimated : True          ← 추정을 채택했다
marks_confidence: 0.1931        ← MIN_CONFIDENCE 0.12 를 겨우 넘겼다
marks           : 2·3·4 장이 start == end == 77.81   ← 폭 0 인 구간
by_slide        : 2·3·4 장의 words = []              ← 발화가 통째로 비었다
```

`f04_infer_marks.py:236` 의 `a = b = cursor` — DP 경로가 안 들른 장은 **0초 구간**으로
남는다. `split_by_slide` 가 거기에 단어를 하나도 안 넣고, F-11 정합은 그 개념들에
근거가 없다고 보고, 화면은 "말한 적 없음" 으로 채워진다. 그게 "인식을 못 한다" 의 실체다.

**가드가 너무 헐겁다** (f04:212):

```python
if confidence < MIN_CONFIDENCE or len(used) < max(2, n_slides // 2):
```

- `MIN_CONFIDENCE = 0.12` — 한국어 조사·불용어 겹침만으로도 넘는다 (실측 0.19 통과)
- `len(used) >= n_slides // 2` — **8장 중 4장만 쓰여도 통과.** 33장이면 17장만 맞아도
  나머지 16장이 통째로 비어 있는 채 "추정 성공" 이 된다

**고칠 방향 세 겹**

1. **빈 장 비율을 가드에 넣는다.** 폭 0 구간이 일정 비율을 넘으면 추정을 버린다 —
   `used` 개수만으로는 "쓰인 장이 한쪽에 몰렸는지" 를 못 본다.
2. **균등 분할로 물러서는 것이 답이 아니다.** 녹음이 자료와 정말 다르면 균등 분할도
   틀린 발화를 모든 장에 뿌릴 뿐이다. **사실대로 말해야 한다** (CLAUDE.md §4
   「분석이 실패하면 실패로 보여준다」). `InferredMarks.reason` 이 이미 그 자리이고,
   브리지가 `marks_reason` 으로 실어 보내며 화면에 표시 경로도 있다(app.js:3258~3265).
   → **"이 녹음은 자료와 맞지 않아요" 를 명시적 상태로 올린다.**
3. **전체 전사문은 살린다.** 구간 추정이 실패해도 `full_text` 는 멀쩡하다.
   슬라이드별 분할만 못 할 뿐이므로 음성 습관(F-18)·속도(F-17)는 그대로 돌아야 한다.

### W4 — 힌트 🟡

**(a) 산문에서 정규식으로 장 번호를 캐는 것을 그만둔다**

`qa_live.js:431 hintSlideNos()` 가 `"27, 28장을 같이 볼게요"` 를 정규식으로 읽는다.
주석은 "서버가 장 번호를 따로 안 실어 준다" 고 하는데 — **그건 고칠 수 있는 전제다.**
서버는 `question.slide_nos` 를 구조적으로 갖고 있으면서 문장에 녹여 버리고 있다.

→ `with_hint_ladders()`(f08_questions.py:1166) 에 `hint_slides` 배열을 나란히 싣는다.
함수 하나 안에서 끝난다. 프론트는 정규식을 폴백으로만 남긴다.

**(b) 「답 보고 다시 말해보기」가 너무 일찍 열린다 — W3 와 얽힌다**

`liveStalled()`(qa_live.js:143) 의 마지막 줄:

```js
return (last.score || 0) <= (prev.score || 0);
```

**점수가 안 오르기만 해도** 2턴째에 출구가 열린다. partial 55 → partial 55 는
아주 흔하다. 여기에 `autoHint` 가 라운드마다 힌트를 자동으로 여는 것이 겹치면
(`hintLevel >= liveQuestionHints().length` 조건), 대부분의 사람이 2라운드에
답을 펼쳐 볼 수 있게 된다. **"판정이 광범위하다" 는 체감의 절반이 여기일 수 있다.**

→ 실제로 몇 라운드에 열리는지 확인 후, `<=` 를 `<` 로 좁히거나
최소 라운드 조건을 붙인다.

**(c) 사다리 길이가 질문마다 흔들린다**

`liveHints()` 가 판정본(4단)과 질문본(3단) 중 **긴 쪽**을 쓰는데,
`build_hint_ladder` 의 중복 제거(f08:1161)가 4단을 3단으로 만들 수 있다.
말풍선은 `total: list.length` 를 찍으므로 **한 질문 안에서 "힌트 2/4" → "힌트 3/3"**
처럼 분모가 변한다. 소비한 힌트를 인덱스가 아니라 단계 이름으로 키잉하면 사라진다.
